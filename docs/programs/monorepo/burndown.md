# Monorepo: burndown

Goal, invariants, owner decisions, phases and resume protocol: [README.md](README.md). This file is the tracker: one row per item (IDs from section 9 of the plan), with acceptance criteria, status and evidence, and a dated progress log. Only the Phase 1 coordinator edits this file while Phase 1 runs; other agents report state changes to the coordinator, who updates the row and the log. From Phase 2 on, whoever changes an item's state edits its row and appends one log line in the same PR.

Status values: `todo`, `in-progress` (work started or a PR is open), `done` (acceptance holds and the evidence is linked), `descoped`. Items marked **OWNER** need an npm setting, a GitHub setting, a ruleset, an App permission, an archive, a secret or a deploy: the agent prepares the exact steps in `docs/programs/monorepo/owner-steps.md` and stops (Resume protocol, step 5).

Estimates (wall-clock hours with parallel agents, from the plan): Phase 1 about 5, Phase 2 about 11, Phase 3 about 12, Phase 4 about 8 (overlapping Phase 3), Phase 5 about 5; critical path about 36 hours plus about 1 to 1.5 hours of owner actions.

Item IDs MR-15, MR-42, MR-43 and MR-54 are not used (the plan's section 9 skips them; earlier drafts used MR-42/MR-43 for per-package canaries, which MR-41 now covers).
