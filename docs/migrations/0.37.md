# Updating from 0.36 to 0.37

0.37 renames eight keys so that one idea has one name, and widens one list of values. For a deck, run `opf fix deck.opf.json -i`, then validate (`opf validate deck.opf.json --fail-on warning`). `opf fix` makes every change in the first table below, and none of them changes how a slide draws. Before 1.0 OPF keeps no aliases: a deck that still writes an old name fails validation with `opf/schema` at the key, a message that names the new key, and the fix `rename-key` (marked safe).

## Decks

| In 0.36 | In 0.37 |
| --- | --- |
| A font scheme's `languageFamily`, with the values `latin`, `ea`, `cs`, `eastAsian` and `complexScript` | `scriptGroup`, with the values `latin`, `eastAsian` and `complexScript`. `ea` and `cs` are no longer accepted: `opf/schema` at the value says `"cs" is written "complexScript" since OPF 0.37` and offers the safe fix `rename-value`. `latin` covers every script outside the other two groups (Cyrillic and Greek too), as before. Embedded font scheme records (`catalogs`) are rewritten too |
| A styled table cell's `style.verticalAlign` (`top`, `middle`, `bottom`) | `style.anchor`, the word layouts, regions and shapes already use for vertical placement. The values are unchanged |
| A speaker's `organizationId` | `organization`, like every other key that names another entry by its id (`dataset`, `layout`, `theme`, `datasource`). The value is still the `id` of an entry of the root `organization` list |
| A composition's `minFontSize` and `maxFontSize` | `minFontSizePx` and `maxFontSizePx`. The numbers are the same reference pixels (at a 720-pixel short edge); the name now says the unit, because a run's `fontSize` is in points. This includes the `composition` of a layout record (`catalogs`) |
| A reference's `url` | `link`, checked like a run's `link`: `https://`, `http://`, `mailto:` or `tel:` (a `slide:` link is not valid on a reference). A value without its scheme (`acme.com/report`) fails the pattern, and `opf validate` offers the fix `Add https://`, which is not safe: `opf fix` leaves it for you to confirm |
| A picture or gradient background's `tone` (`dark` or `light`) | `appearance`. The deck's own `tone` (its voice) is another key and is unchanged |
| A combo chart's `line` (the columns drawn as lines) | `lineSeries`. The list of column names is unchanged |
| A chart reference line's `stroke.dash`: `solid`, `dash` or `dot` | Also `longDash`, `dashDot`, `longDashDot`, `longDashDotDot`, `sysDot`, `sysDash`, `sysDashDot` and `sysDashDotDot`: the preset names a shape outline's dash takes. The preview draws them and the PowerPoint export writes the matching `a:prstDash`. A custom dash array is not available on a chart line. A table cell border keeps `solid`, `dash` and `dot`. Nothing to fix |

A deck that has both the old and the new key of a pair (`organizationId` and `organization`) gets the same finding, which says both are present, and no fix: remove the one you do not want.

## Naming rules

The renames follow four rules, which the format keeps: `type` says which sort; `anchor` places something vertically; a key that names another entry by its id is the bare word (`organization`, not `organizationId`); where one measure has two units, the unit is in the name (`widthPx`, `minFontSizePx`).

## PowerPoint files

The PowerPoint records store the 0.37 names. A file that an earlier release wrote still imports: the importer reads each record it restores through the same table `opf fix` uses, so `languageFamily` in a stored record comes back as `scriptGroup`. A 0.36.0 importer does not read the new names inside the records of a 0.37 file.

## Hosts

Exported names, options and fields that mirror a renamed key follow it, with no alias. A host updates them when it takes 0.37; the three sites list the names they used in their bump.

| In 0.36 | In 0.37 |
| --- | --- |
| `normalizeLanguageFamily`, `LanguageFamilyName` (`@openpresentation/opf`) | `normalizeScriptGroup`, `ScriptGroupName`; only the three group names are read |
| The option `tone` of `resolveColorRoles` | `appearance` |
| The field `speakers[].organizationId` of `stats` | `speakers[].organization` |
| The option `minFontSize` of the composition functions (`composeSlide`, `layoutTable`, `layoutQuote`, `layoutTimeline`, `layoutMetrics`, ...), of `paginateSlide`, of `chartTextSize` and of the annotation layout options | `minFontSizePx` |
| The composition field `maxFontSize` read by the engine | `maxFontSizePx` |
| The `url` field of `Reference`, of a laid-out note and of the editor's `addReference`, `updateReference` and reference state | `link` |
| The `line` option of `setChartOptions` and of the chart options panel (`@openpresentation/opf-editor`) | `lineSeries` |
| The `verticalAlign` field of a table cell style in the editor's `prepareTableCellStyle` and `setTableCellStyle` | `anchor` |
| New | `renameRecordKeys` (`@openpresentation/opf`): core's one table of renamed keys, for a reader of older records |
