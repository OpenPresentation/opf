# Updating from 0.34 to 0.35

0.35 changes little that a deck or a host has to act on. Run `opf validate deck.opf.json --fail-on warning` first: each deck change below is reported, and the icon and layout changes come with a fix.

## Decks

| In 0.34 | In 0.35 |
| --- | --- |
| Eight Lucide icons: `lucide:circle-arrow-out-up-right`, `-up-left`, `-down-right`, `-down-left`, and the same four as `lucide:square-arrow-out-*` | Lucide renamed them: `lucide:circle-arrow-up-right-exit`, `-up-left-exit`, `-down-right-exit`, `-down-left-exit`, and `lucide:square-arrow-*-exit`. The old names no longer draw. `opf/icon-unknown` says the icon was renamed, names the new one and offers the replace fix. |
| `"layout": "auto"` on a slide: automatic composition | Omit `layout`: a slide without one is composed automatically, as `"auto"` was. `"auto"` is now an ordinary layout reference, so it resolves nowhere: `opf/unresolved-reference` says "Layout 'auto' resolves nowhere: OPF 0.35 removed layout 'auto' (omit layout for automatic composition); the slide composes automatically." and offers the safe fix `remove-layout-auto`, which deletes the key. The slide still composes automatically meanwhile. `opf format` no longer drops the key. A catalog may now define a layout with the id `auto`. |
| `"layout": "flow"` (boxes joined by arrows in a row) or `"layout": "vertical-flow"` (the same as a column) | `"layout": "process"` or `"layout": "vertical-process"`. The gallery has no `flow` layout: `process` absorbs it, and `vertical-flow` is renamed `vertical-process` (it draws as before). The old ids resolve nowhere: `opf/unresolved-reference` says "Layout 'flow' resolves nowhere: OPF 0.35 removed layout 'flow' (use 'process'); the slide composes automatically." and offers the safe fix `rename-layout`, which writes the new id (`default:flow` becomes `default:process`). The slide composes automatically meanwhile. A catalog of your own may still define a layout named `flow`. |
| A `process` slide whose only body content is one list of 2 to 8 entries of one or two words | It drew numbered steps beside badges, or for 3 to 6 entries a row of chips joined by arrows. It now draws Basic Process, the drawing the `flow` layout had (live SmartArt in PowerPoint), at the size its steps would have or larger; a list that Basic Process cannot hold at that size keeps the steps. A longer list, an entry of three or more words or over 24 characters, a description, an icon, numbering, nested entries, or a list beside other blocks draw as before. |
| A block pinned to a region of a built-in layout by its 0.34 name (`"region": "notes"`, Markdown `region=notes`) | The built-in layouts use seven standard body-region names: `body`, `lead`, `aside`, `media`, `first`, `second` and `third` (table below). A 0.34 name is reported as `opf/region-unknown` and the pin is ignored: the block binds by kind, role and reading order, which puts it in the region it was pinned to unless the pin moved it away from plain binding. Rename the pin, or remove it where plain binding places the block. Every layout draws as before. |
| `design.contentDirection` (`horizontal` or `vertical`) on the deck or a slide | Removed. Delete it (`opf validate` reports `opf/schema` at the key, says what replaced it and offers the safe fix `remove:contentDirection`). On an automatic slide write `composition.mode`: `"row"` for `horizontal`, `"column"` for `vertical` (a deck-wide value becomes a `composition.mode` on each slide that needs it). On a slide with a layout, the layout's regions say it: the built-in `process` lays its steps in a row as before; for another layout, use a custom record whose region has `"flow": "row"` or `"column"`. Until it is deleted the key fails the schema and composition ignores it. |
| `design.chartPrimary` (`none`, `start`, `end`, `top`, `bottom`) on the deck or a slide | Removed. Delete it (`opf/schema` at the key, safe fix `remove:chartPrimary`). It drew only on automatic slides (a slide with a layout ignored it). `start`: the `chart-beside` layout (the chart first at 3:2, the supporting blocks beside it); `end`: `chart-beside` with `design.mirror: true`; `top` or `bottom`: `composition: { "mode": "column", "weights": [3, 2] }` with the chart first (or `[2, 3]` with the chart last), the other blocks in one group; `none`: delete it. Without it an automatic slide gives a short chart among other blocks its own track (LH-49) as before. |
| A number format with `;` printed everything after the first section as literal text | The sections are Excel's `positive;negative;zero`: `"+0%;-0%"` gives `+12%` and `-5%`, and `"0;(0)"` puts a loss in brackets. A format that used `;` as literal text now reads as sections; four or more sections, an empty section or one without a numeric part is `opf/number-format-invalid`. |

### Region names of the built-in layouts

`title` and `subtitle` are unchanged, as are the regions of `cover`, `section`, `image` (`media`), `image-beside` (`media`, `body`), `list` and `text` (`body`), `two-column` (`first`, `second`) and `three-column` (`first`, `second`, `third`). Roles do not change.

The icon sets follow `lucide-static` 1.72.0 and `@tabler/icons` 3.51.0. Any former Lucide name (304 of them, such as `lucide:alert-triangle`) is answered the same way as the eight above: it does not draw, and the finding names the current one. Tabler ships no rename list.

## Custom layout records

| In 0.34 | In 0.35 |
| --- | --- |
| A region with `"role": "secondary"` (bound after `primary`, before `supporting`) | Write `"role": "supporting"` (or `"primary"`, or leave `role` out for the default `primary`). `role` is `primary`, `media` or `supporting`; `secondary` fails the layout schema: `opf validate` reports `opf/catalog-record` at the region's `role`, and until it is fixed the engines read that region as `primary`. The gallery `dashboard` layout's `kpis` region is `supporting` now and draws as before. |
| A region with `"sequence": "steps"` or `"sequence": "numbered"` (step badges) | `"arrangement": "steps"` or `"arrangement": "numbered"`. A region has one `arrangement`: a sequence (`steps`, `numbered`) or a diagram, never both. |
| A region with `"arrangement": "flow"` or `"arrangement": "vertical-flow"` | `"arrangement": "process"` or `"arrangement": "vertical-process"`, PowerPoint's names (Basic Process and Vertical Process). The gallery's `flow` layout is gone (its `process` layout draws a short list as Basic Process) and `vertical-flow` is `vertical-process` (Decks, above). |
| A region with `"arrangement": "steps"`: its lone list of 3 to 6 entries of one or two words drew as a row of chips joined by arrows | Its lone list of 2 to 8 entries of one level, each of one or two words and at most 24 characters, without numbering, descriptions or icons, draws as Basic Process in the region's whole cell where Basic Process holds every entry at the size its steps would have or larger; otherwise the list draws as steps. The chips are gone. |
| A region with `"arrangement": "pyramid"` and `"pyramidDirection": "down"` | `"arrangement": "inverted-pyramid"`. With `"pyramidDirection": "up"` (the default), drop the key and keep `"arrangement": "pyramid"`. |
| How validation reports the old keys and values | `sequence` and `pyramidDirection` fail the layout schema as unknown keys and `flow` and `vertical-flow` as unknown values: `opf validate` reports `opf/catalog-record` (error) at the region's `sequence` or `pyramidDirection` key, or at its `arrangement`. The record does not resolve, so each slide that names it gets `opf/unresolved-reference` and composes automatically until it is fixed. An engine handed the record directly ignores what it does not know: the region draws its content without badges, a list instead of the process, or an upright pyramid. The gallery records changed the same way and draw as before. |
| A region with `"flow": "none"` (one block fills it) | `"max": 1`, without `flow` (or with `flow` for the blocks that join it). A region of `max: 1` is a single-block region and keeps every rule of `none`: its block fills it; on a layout with no overflow region, blocks no region had room for join it, up to 6, with no finding, and flow by its `flow` (`auto` by default, as `none` did); single-block regions of one role side by side share their joined blocks; it is never the default `overflowRegion` nor the region a slide's own `composition` arranges. `none` fails the layout schema: `opf validate` reports `opf/catalog-record` at the region's `flow` and offers the safe fix `use-max-1` (deletes `flow`, writes `max: 1`); an engine handed the record directly reads it as `auto` with room for 6. The built-in records changed the same way and draw as before. |
| A region with `"max": 1` and a flowing `flow` (`auto`, `grid`, `column`) | It is a single-block region now (above): it is no longer the default overflow region, and blocks no region had room for may join it instead of being drawn beyond its `max` with `opf/layout-unplaced`. Set `overflowRegion` to keep it as the overflow region, or `max: 2` or more. |
| `flow` values `none`, `grid`, `column`, `auto` | `auto`, `grid`, `row`, `column`, the words of `composition.mode`. `row` is new: the region's blocks side by side in one row, one cell each at equal widths, kept as written (no paragraph columns, lead block, list grid or regrouping), as `design.contentDirection: "horizontal"` made a flowing region before. |
| `design.contentDirection` in a layout record's `design` (the built-in `process` had `horizontal`) | Write the direction on the regions: `horizontal` is `"flow": "row"` and `vertical` `"flow": "column"` on each region that is not single-block (`process`'s `body` is `"flow": "row"` and draws as before). The key fails the layout schema (`opf/catalog-record`, safe fix `remove:contentDirection`). `vertical` turned a region into a strict column; `"flow": "column"` stacks the blocks too but may still set similar paragraphs as columns or two lists in a grid. |
| `design.chartPrimary` in a layout record's `design` | Delete it (it never applied on a slide with a layout); safe fix `remove:chartPrimary`. |
| `design.contentDirection` in a theme record's `design` | Delete it; the theme's other design keys are unchanged. Safe fix `remove:contentDirection`. |
| An id `auto` was refused for a layout record | Allowed: `auto` is an ordinary id. |
| Region names | Any valid name | Unchanged: a custom record names its regions as it likes. The built-ins use the seven standard names above; a record that follows them pins the same way as the built-ins. Composition reads one name besides the headings: the `aside` of a layout that also has a `first` region is its closing verdict (LH-170: a lone short text there draws as the foot band), as the comparison's `verdict` region was. A custom record that named a region `verdict` loses that rule; name it `aside` beside `first` columns to keep it. |

## Hosts and scripts

| What | In 0.34 | In 0.35 |
| --- | --- | --- |
| Pinned font peers | `@expo-google-fonts/noto-color-emoji` and `@expo-google-fonts/noto-sans-mongolian` at their 0.34 versions | Install `@expo-google-fonts/noto-color-emoji` 0.4.8 and `@expo-google-fonts/noto-sans-mongolian` 0.4.2 with this release; the font manifest's reviewed hashes follow them. Mongolian lines measure 0.1% to 4% differently. |
| `RenderDiagnostic` reason `"shaping"` (`text-as-paths-fallback`, `raster-marker-unavailable`) | A run could stay text under `text: "paths"` with this reason | The reason is gone from the types and such a run is outlined. Drop a `reason === "shaping"` branch. |
| The renderer's shaper without HarfBuzz | fontkit 2.0.4 | fontkit 3.0.0 (ESM-only, Node 22 or later; the renderer already requires both). Myanmar, Syriac, Nastaliq Urdu and Mongolian now measure the same through fontkit and HarfBuzz. |
| The MCP viewer's resource URI | `ui://opf/deck` | `ui://opf/deck/<hash>`, the first 12 hex digits of the page's SHA-256 (`DECK_APP_URI`), so a host that caches a view by its URI gets the new viewer when it changes. `ui://opf/deck` and earlier hashes still read as the current viewer. A host that compared the URI to the literal string reads `DECK_APP_URI` instead. |
| The Design menu's bottom sheet (the editor on a phone) | Three lists that each scrolled | One section at a time behind a switch (Theme, Colors, Fonts, Layout). New label `layoutTab` (default "Layout") for a host that translates the editor's labels; `--opf-design-menu-sheet-h` sets the sheet's height. |
| `AUTO_LAYOUT` from `@openpresentation/opf/composition` | The reserved layout id `'auto'` | Removed. A slide without `layout` is automatic; compare `slide.layout === undefined` instead of `=== 'auto'`. |
| `REGION_ROLES` (core) and `LAYOUT_REGION_ROLES` (editor) | `primary`, `secondary`, `media`, `supporting` | `primary`, `media`, `supporting` |
| `fromPptx` on OPF's automatic layout, or a foreign blank, title-only or unmatched custom layout | `layout: "auto"` | No `layout`. A slide moved to the automatic layout with Change Layout in PowerPoint loses its stored layout (`layout-changed`). `foreignLayoutReference` returns `undefined` for these layouts. |
| PPTX export of a built-in layout | Placeholders and the `OPF_LAYOUT_V1` tag's region map named after the 0.34 regions (`notes`, `verdict`, ...) | Named after the 0.35 regions (`aside`, ...). Import of a 0.34 file: a block restored from its provenance keeps its old pin (`opf/region-unknown`, bound by kind); a block read from a placeholder whose tag names an old region gets no pin and binds by kind. |
| Editor source hints for a built-in layout | A region named like a slide key (`items`, `chart`, `table`, `code`, `timeline`) suggested that key | The regions are `body` and `aside`, so the hint lists the keys of the kinds the region accepts (`chart` or `diagram` for `chart-beside`'s `body`). |
| `SlideComposition.arrangements[].kind` and the SVG trace `data-opf-arrangement` | `flow`, `vertical-flow`, and `pyramid` with `pyramidDirection: "down"` for an inverted pyramid | `process`, `vertical-process` and `inverted-pyramid`; a composed arrangement has no `pyramidDirection`. The drawing is unchanged. |
| `LayoutRegion` from `layoutTemplate` (core) | `sequence`, `arrangement` and `pyramidDirection` | One `arrangement` (`RegionArrangement`, values in `REGION_ARRANGEMENTS`). `regionSequence(region)` returns `steps` or `numbered`, `regionDiagram(region)` the diagram (`Arrangement`, values in `ARRANGEMENTS`). |
| `smartArtUnavailable` and `SMART_ART_LAYOUTS` (core) | A candidate `{kind: "pyramid", pyramidDirection: "down"}`; layouts keyed by `flow` and `vertical-flow` | `{kind: "inverted-pyramid"}`; keyed by `process` and `vertical-process` (`LiveArrangement`: an inverted pyramid has no live SmartArt layout). |
| PPTX `OPF_SMARTART_V1` and `OPF_ARRANGEMENT_V1` tags and the `smartart-adapted` finding's `form` | `kind` and `form` `flow`, `vertical-flow`, and `pyramid` for an inverted pyramid | `process`, `vertical-process` and `inverted-pyramid`. Import of a 0.34 file reads its `flow` and `vertical-flow` tags as the new kinds. |
| `STEP_FLOW_MIN`, `STEP_FLOW_MAX`, `STEP_FLOW_CHARACTERS` (core composition) | 3, 6 and 24: a `steps` region's short list drew as a flow of chips | Removed. `STEP_PROCESS_MIN` (2), `STEP_PROCESS_MAX` (8) and `STEP_PROCESS_CHARACTERS` (24) bound the list a `steps` region draws as Basic Process. |
| `SlideComposition.steps[].form` and the SVG trace `data-opf-steps` | `row`, `column`, `flow` or `tiles`; a flow carried `chips` and `arrows` | `row`, `column` or `tiles`. A `steps` region's short list drawn as Basic Process is in `SlideComposition.arrangements` (`kind` `process`) and has no `steps` entry. |
| PPTX import of PowerPoint's Basic Process and Vertical Process SmartArt | A list on the `flow` and `vertical-flow` layouts | A list on the `process` and `vertical-process` layouts. A 0.34 file's slide on `flow` or `vertical-flow` (its stored layout or its slide layout's `OPF_LAYOUT_V1` tag) imports on `process` or `vertical-process`; a stored layout reports `layout-renamed`. New core helper `renamedLayout(kind, reference)` (`@openpresentation/opf/composition`) returns the id that replaced a removed gallery layout. |
| `DESIGN_HINT_KEYS`, `THEME_DESIGN_KEYS`, `DesignHints` and `resolveDesignHints` (core) | Include `contentDirection` (and, but for the theme, `chartPrimary`) | Without them. `SlideComposition.design` never carries them; a host that read them reads the slide's `composition.mode` or the layout region's `flow`. New `REMOVED_DESIGN_KEYS` says what replaced each. |
| `REGION_FLOWS` (core), `LAYOUT_REGION_FLOWS` (editor) and `geometry.regions[].flow` | `none`, `grid`, `column`, `auto`; a single-block region reported `flow: "none"` | `auto`, `grid`, `row`, `column`; a single-block region reports its `flow` (`auto` unless set) and `max: 1`. A host that tested `flow === "none"` tests `max === 1`. `layoutStructure` writes `body (auto, max 1: chart, diagram)` where it wrote `body (none: chart, diagram)`. |
| The `arrangement-adapted` finding at `design.chartPrimary` and the root decision `reason: "chart-primary"` | The finding said a chartPrimary could not be drawn; the reason marked a chartPrimary split or LH-49's chart track | The finding is gone. `chart-primary` marks LH-49's chart track only. |
| The editor's design options and Design panel | `contentDirection` ("Content direction") and `chartPrimary` ("Primary chart position"), deck and slide | Removed from `DESIGN_OPTIONS`, `DesignOptionId` and the panel; `setDesignOption` refuses the ids. The layout inspector's flow choice lists `auto`, `grid`, `row` and `column`, and its "Max blocks" help says 1 is a region of one block. |
| PPTX export and import of the deck and slide composition hints (`OPF_DOCUMENT_V1`, `OPF_SLIDE_V1`) | `contentDirection` and `chartPrimary` were stored and restored | Not written. Import of a 0.34 file does not restore them (the deck validates without them). A 0.34 file's embedded custom layout or theme record is restored as stored: fix its `flow: "none"` and `contentDirection` with the safe fixes. |
| The gallery examples (`examples/gallery`, pptx.gallery's example decks) | Each deck set `design.contentDirection` and `design.chartPrimary` (a pptx.gallery dimension) | The generator writes neither; the 100 decks are regenerated, and their automatic slides and layout slides draw as the engine decides. |
| A custom icon set record | No `renamed` | May carry `renamed`, a map from a former icon name to its current one. Optional. |

## Nothing to change

The MCP viewer on a phone and in a very narrow pane, its host line, the viewer in ChatGPT, PDF text that copies in logical order for reordering scripts, doughnut labels that fit their ring, waterfall labels through a sectioned format, and metric rows with icons need no change to a deck.

## Check the result

```sh
opf validate deck.opf.json --fail-on warning
```
