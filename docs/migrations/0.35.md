# Updating from 0.34 to 0.35

0.35 changes little that a deck or a host has to act on. Run `opf validate deck.opf.json --fail-on warning` first: each deck change below is reported, and the icon and layout changes come with a fix. A self-contained deck (one that `opf embed` filled with copies of the built-in layouts) takes one command first: `opf embed deck.opf.json -i` ([below](#self-contained-decks-embedded-copies-of-built-in-layouts)). Validate again after each round of fixes: an error in the deck's own keys stops the accessibility, layout and content checks, so findings such as `opf/region-unknown` appear only once it is fixed.

## Decks

| In 0.34 | In 0.35 |
| --- | --- |
| Eight Lucide icons: `lucide:circle-arrow-out-up-right`, `-up-left`, `-down-right`, `-down-left`, and the same four as `lucide:square-arrow-out-*` | Lucide renamed them: `lucide:circle-arrow-up-right-exit`, `-up-left-exit`, `-down-right-exit`, `-down-left-exit`, and `lucide:square-arrow-*-exit`. The old names no longer draw. `opf/icon-unknown` says the icon was renamed, names the new one and offers the replace fix. |
| `"layout": "auto"` on a slide: automatic composition | Omit `layout`: a slide without one is composed automatically, as `"auto"` was. `"auto"` is now an ordinary layout reference, so it resolves nowhere: `opf/unresolved-reference` says "Layout 'auto' resolves nowhere: OPF 0.35 removed layout 'auto' (omit layout for automatic composition); the slide composes automatically." and offers the safe fix `remove-layout-auto`, which deletes the key. The slide still composes automatically meanwhile. `opf format` no longer drops the key. A catalog may now define a layout with the id `auto`. |
| `"layout": "flow"` (boxes joined by arrows in a row) or `"layout": "vertical-flow"` (the same as a column) | `"layout": "process"` or `"layout": "vertical-process"`. The gallery has no `flow` layout: `process` absorbs it, and `vertical-flow` is renamed `vertical-process` (it draws as before). The old ids resolve nowhere: `opf/unresolved-reference` says "Layout 'flow' resolves nowhere: OPF 0.35 removed layout 'flow' (use 'process'); the slide composes automatically." and offers the safe fix `rename-layout`, which writes the new id (`default:flow` becomes `default:process`). The slide composes automatically meanwhile. A catalog of your own may still define a layout named `flow`. |
| `"layout": "agenda-split"` (a short agenda beside its title) | `"layout": "agenda"` with `"design": { "titlePosition": "start" }` on the slide. The gallery has no `agenda-split` (38 layouts): any layout can now put its title beside its body with `design.titlePosition` (below). `opf/unresolved-reference` says "Layout 'agenda-split' resolves nowhere: OPF 0.35 removed layout 'agenda-split' (use 'agenda' with design.titlePosition 'start'); the slide composes automatically." and offers the safe fix `rename-layout`, which writes `agenda` and adds `design.titlePosition: "start"` to the slide (unless the slide sets a `titlePosition` of its own). The slide composes automatically meanwhile. The fixed slide draws its title in a column of two fifths of the width (agenda-split's was half) and the list beside it; the list is numbered as before. |
| The title beside the body: the gallery's `cycle`, `matrix`, `vertical-process` (and `agenda-split`) | New key `design.titlePosition`: `top` (the default) or `start`, the heading group beside the body in a column of two fifths of the content width, on the reading side (the right in a right-to-left deck; `design.mirror` swaps it). It works on the slide, the deck and the theme, on any layout and on an automatic slide (a cover, a slide with promoted regions and a portrait canvas keep their title on top). `cycle`, `matrix` and `vertical-process` set it in their record and draw exactly as before on a landscape canvas; a deck or slide that sets `titlePosition: "top"` now puts their title on top, and on a portrait canvas (taller than wide) the title is on top and the diagram draws larger under it. Nothing to change. |
| A `process` slide whose only body content is one list of 2 to 8 entries of one or two words | It drew numbered steps beside badges, or for 3 to 6 entries a row of chips joined by arrows. It now draws Basic Process, the drawing the `flow` layout had (live SmartArt in PowerPoint), at the size its steps would have or larger; a list that Basic Process cannot hold at that size keeps the steps. A longer list, an entry of three or more words or over 24 characters, a description, an icon, numbering, nested entries, or a list beside other blocks draw as before. |
| A block pinned to a region of a built-in layout by its 0.34 name (`"region": "notes"`, Markdown `region=notes`) | The built-in layouts use seven standard body-region names: `body`, `lead`, `aside`, `media`, `first`, `second` and `third` (table below). A 0.34 name is reported as `opf/region-unknown` and the pin is ignored: the block binds by kind, role and reading order, which puts it in the region it was pinned to unless the pin moved it away from plain binding. The finding names the new region ("OPF 0.35 renamed region 'charts' of the built-in layout 'chart' to 'body'") and offers the safe fix `rename-region`, which writes it; or remove the pin where plain binding places the block. A block drawn as the automatic foot band (the comparison's `verdict` text) is reported too. Every layout draws as before. |
| `design.contentDirection` (`horizontal` or `vertical`) on the deck or a slide | Removed. Delete it (`opf validate` reports `opf/schema` at the key, says what replaced it and offers the safe fix `remove:contentDirection`). On an automatic slide write `composition.mode`: `"row"` for `horizontal`, `"column"` for `vertical` (a deck-wide value becomes a `composition.mode` on each slide that needs it). On a slide with a layout, the layout's regions say it: the built-in `process` lays its steps in a row as before; for another layout, use a custom record whose region has `"flow": "row"` or `"column"`. Until it is deleted the key fails the schema and composition ignores it. |
| `design.chartPrimary` (`none`, `start`, `end`, `top`, `bottom`) on the deck or a slide | Removed. Delete it (`opf/schema` at the key, safe fix `remove:chartPrimary`). It drew only on automatic slides (a slide with a layout ignored it). `start`: the `chart-beside` layout (the chart first at 3:2, the supporting blocks beside it); `end`: `chart-beside` with `design.mirror: true`; `top` or `bottom`: `composition: { "mode": "column", "weights": [3, 2] }` with the chart first (or `[2, 3]` with the chart last), the other blocks in one group; `none`: delete it. Without it an automatic slide gives a short chart among other blocks its own track (LH-49) as before. |
| A number format with `;` printed everything after the first section as literal text | The sections are Excel's `positive;negative;zero`: `"+0%;-0%"` gives `+12%` and `-5%`, and `"0;(0)"` puts a loss in brackets. A format that used `;` as literal text now reads as sections; four or more sections, an empty section or one without a numeric part is `opf/number-format-invalid`. |
| A long list (more than 6 entries) on a layout slide | It flowed into columns only on the `agenda`, `faq` and `list` layouts (their regions set `listColumns: "auto"`). It now may on any layout, in a region without an `arrangement` (or with `numbered`, the agenda's): up to three columns when one column does not hold it at its starting size, kept only when the columns set it at least as large as one column would and do not overflow where one column fits. A region made for a list (`list` its first accepted kind: `agenda`, `faq`, `list` and a custom record's list region) keeps LH-184's rule that columns may come out up to a type-scale step under one column whose lines would run past the reading measure; there, columns that overflow now give way to one column that fits at least as large. A list in a diagram region, a `steps` region or below a layout's grid keeps one column. No gallery layout preview, example slide or layout golden draws differently. Write `"columns": 1` on the list to keep it in one column, or `2`, `3` or `"auto"` to choose. Nothing to change. |
| A list in a row of cells sized by `composition.weights` whose cell was narrower than its longest word | The word broke inside it. The row is rebalanced: the list's cell widens to the narrowest width at which every word holds at the list's size (or larger) and the other cells give that width up while none of their text is set smaller; when they cannot, the blocks are stacked in one column, kept only when no block reads smaller there. The list is never set smaller. Nothing to change. |

### Self-contained decks (embedded copies of built-in layouts)

`opf embed` (core `embed()`) copies every built-in layout a deck uses into `catalogs.default.layouts`, as the release that ran it published the record. 0.35 changed the keys of those records (`flow: "none"`, `listColumns`, `sequence`, `pyramidDirection`, the `flow` arrangement, `design.contentDirection`) and an earlier copy can also carry 0.34's `left` and `right` alignments, so such a copy fails the 0.35 layout schema: every deck made self-contained before 0.35 (pptx.gallery's how-to decks, pptx.dev's saved and starter decks, openpresentation.org's tutorials) is invalid, and `opf convert` stops with `invalid-document`.

| What | In 0.35 |
| --- | --- |
| The fix | `opf embed deck.opf.json -i`. It makes each stale copy valid without changing what it draws, writes the deck and lists the copies in the report's `embed.refreshed` (`how`): an unedited copy of the 0.34 release takes the current record (`current`), and each pin of its slides the region's 0.35 name; an unedited copy of a layout 0.35 removed moves its slides to the replacement and drops the copy (`renamed`, as `rename-layout` does); any other copy (an earlier release, or one you edited) gets the safe fix of each key (`converted`), keeping its own drawing and region names. Then validate again. It still refuses a deck with other invalid content, listing it; fix that and run it again. |
| `opf validate` | Each error in the copy says what it is: "catalogs.default.layouts.cover is an unedited copy of OPF 0.34's release of the built-in layout 'cover'; 0.35 changed the keys of the built-in records, so the copy fails the 0.35 layout schema." (or "of an earlier release", or "an edited copy"), then what replaced the key. It carries the key's own fix (`use-max-1`, `remove:listColumns`, `use-arrangement`, `use-inverted-pyramid`, `use-pyramid`, `rename-arrangement`, `remove:contentDirection`, `change-to:start`) and `use-current-record`, which replaces the copy with the current record and renames the pins of its slides. |
| What is safe | Decided by the copy's content hash against every version of the built-in record released before 0.35. `use-current-record` is safe for an unedited copy of the 0.34 release: 0.35 converted exactly that record, so the current one draws the same. For a copy of an earlier release it is offered, not safe (the current built-in draws differently, for example `cover` with its title at the bottom over a rule), and for an edited copy it drops the edits. A copy of `flow`, `vertical-flow` or `agenda-split` gets `rename-layout`, safe when unedited. |
| A slide on a stale copy | `opf/unresolved-reference` says "Layout 'cover' is embedded in catalogs.default, but the record fails the layout schema: see the opf/catalog-record findings at /catalogs/default/layouts/cover." with the same cause and fix. It said the layout was not embedded. A record of the deck's own (`catalogs.custom`) gets the same message and its keys' fixes; `opf embed` does not change it. |
| `opf convert`, `opf paginate` and the other writing commands | Still refuse the deck; their error now ends "The deck embeds copies of built-in layouts from before OPF 0.35 (cover): `opf embed <deck> -i` refreshes each one it can without changing what it draws; validate again after it." |
| `--check` | `opf embed deck.opf.json --check` exits 1 when a copy would be refreshed. |

The icon sets follow `lucide-static` 1.72.0 and `@tabler/icons` 3.51.0. Any former Lucide name (304 of them, such as `lucide:alert-triangle`) is answered the same way as the eight above: it does not draw, and the finding names the current one. Tabler ships no rename list.

## Custom layout records

| In 0.34 | In 0.35 |
| --- | --- |
| A region with `"role": "secondary"` (bound after `primary`, before `supporting`) | Write `"role": "supporting"` (or `"primary"`, or leave `role` out for the default `primary`). `role` is `primary`, `media` or `supporting`; `secondary` fails the layout schema: `opf validate` reports `opf/catalog-record` at the region's `role`, says it was removed and offers `change-to:supporting` and `change-to:primary` (neither marked safe: which one keeps the binding depends on the record), and until it is fixed the engines read that region as `primary`. The gallery `dashboard` layout's `kpis` region is `supporting` now and draws as before. |
| A region with `"sequence": "steps"` or `"sequence": "numbered"` (step badges) | `"arrangement": "steps"` or `"arrangement": "numbered"`. A region has one `arrangement`: a sequence (`steps`, `numbered`) or a diagram, never both. |
| A region with `"arrangement": "flow"` or `"arrangement": "vertical-flow"` | `"arrangement": "process"` or `"arrangement": "vertical-process"`, PowerPoint's names (Basic Process and Vertical Process). The gallery's `flow` layout is gone (its `process` layout draws a short list as Basic Process) and `vertical-flow` is `vertical-process` (Decks, above). |
| A region with `"arrangement": "steps"`: its lone list of 3 to 6 entries of one or two words drew as a row of chips joined by arrows | Its lone list of 2 to 8 entries of one level, each of one or two words and at most 24 characters, without numbering, descriptions or icons, draws as Basic Process in the region's whole cell where Basic Process holds every entry at the size its steps would have or larger; otherwise the list draws as steps. The chips are gone. |
| A region with `"arrangement": "pyramid"` and `"pyramidDirection": "down"` | `"arrangement": "inverted-pyramid"`. With `"pyramidDirection": "up"` (the default), drop the key and keep `"arrangement": "pyramid"`. |
| How validation reports the old keys and values | `sequence` and `pyramidDirection` fail the layout schema as unknown keys and `flow` and `vertical-flow` as unknown values: `opf validate` reports `opf/catalog-record` (error) at the region's `sequence` or `pyramidDirection` key, or at its `arrangement`, says what replaced it and offers the safe fix: `use-arrangement` (`sequence` becomes `arrangement`, for a region without one), `use-inverted-pyramid` (`pyramidDirection: "down"` on a pyramid), `use-pyramid` (`"up"`: the key is dropped) and `rename-arrangement` (`flow` to `process`, `vertical-flow` to `vertical-process`). Each slide that names the record gets `opf/unresolved-reference`, which says the record is embedded but fails the schema. An engine handed the record directly ignores what it does not know: the region draws its content without badges, a list instead of the process, or an upright pyramid. The gallery records changed the same way and draw as before. |
| A region with `"flow": "none"` (one block fills it) | `"max": 1`, without `flow` (or with `flow` for the blocks that join it). A region of `max: 1` is a single-block region and keeps every rule of `none`: its block fills it; on a layout with no overflow region, blocks no region had room for join it, up to 6, with no finding, and flow by its `flow` (`auto` by default, as `none` did); single-block regions of one role side by side share their joined blocks; it is never the default `overflowRegion` nor the region a slide's own `composition` arranges. `none` fails the layout schema: `opf validate` reports `opf/catalog-record` at the region's `flow` and offers the safe fix `use-max-1` (deletes `flow`, writes `max: 1`); an engine handed the record directly reads it as `auto` with room for 6. The built-in records changed the same way and draw as before. |
| A region with `"max": 1` and a flowing `flow` (`auto`, `grid`, `column`) | It is a single-block region now (above): it is no longer the default overflow region, and blocks no region had room for may join it instead of being drawn beyond its `max` with `opf/layout-unplaced`. Set `overflowRegion` to keep it as the overflow region, or `max: 2` or more. |
| `flow` values `none`, `grid`, `column`, `auto` | `auto`, `grid`, `row`, `column`, the words of `composition.mode`. `row` is new: the region's blocks side by side in one row, one cell each at equal widths, kept as written (no paragraph columns, lead block, list grid or regrouping), as `design.contentDirection: "horizontal"` made a flowing region before. |
| `design.contentDirection` in a layout record's `design` (the built-in `process` had `horizontal`) | Write the direction on the regions: `horizontal` is `"flow": "row"` and `vertical` `"flow": "column"` on each region that is not single-block (`process`'s `body` is `"flow": "row"` and draws as before). The key fails the layout schema (`opf/catalog-record`, safe fix `remove:contentDirection`). `vertical` turned a region into a strict column; `"flow": "column"` stacks the blocks too but may still set similar paragraphs as columns or two lists in a grid. |
| `design.chartPrimary` in a layout record's `design` | Delete it (it never applied on a slide with a layout); safe fix `remove:chartPrimary`. |
| A row record with the title in a column of its own beside the body (as 0.34's `cycle`, `matrix`, `vertical-process` and `agenda-split` were: `direction: "row"`, `title` at `size: 2`, the body at `size: 3`) | Draws as before. To let a deck or slide choose, write the record as a column (title over the body, no sizes) with `"design": { "titlePosition": "start" }`: it draws the same (the title column at two fifths), and a slide or deck with `titlePosition: "top"` puts the title on top. `titlePosition` is new in a layout record's `design` (and a theme's). |
| `design.contentDirection` in a theme record's `design` | Delete it; the theme's other design keys are unchanged. Safe fix `remove:contentDirection`. |
| An id `auto` was refused for a layout record | Allowed: `auto` is an ordinary id. |
| A region with `"listColumns": "auto"` or `1` | Delete it: a list of more than 6 entries flows into columns by default in a region without an `arrangement` (or with `numbered`), when the columns set it at least as large as one column (a region whose first accepted kind is `list` keeps the rule `"auto"` had); a region with a diagram or `steps` keeps one column. To keep a list in one column, write `"columns": 1` on the list. `listColumns` fails the layout schema: `opf validate` reports `opf/catalog-record` at the key, says what replaced it and offers the safe fix `remove:listColumns`; an engine handed the record directly ignores it. The gallery `agenda`, `faq` and `list` records drop the key. |
| Region names | Any valid name | Unchanged: a custom record names its regions as it likes. The built-ins use the seven standard names above; a record that follows them pins the same way as the built-ins. Composition reads one name besides the headings: the `aside` of a layout that also has a `first` region is its closing verdict (LH-170: a lone short text there draws as the foot band), as the comparison's `verdict` region was. A custom record that named a region `verdict` loses that rule; name it `aside` beside `first` columns to keep it. |
