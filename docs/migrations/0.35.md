# Updating from 0.34 to 0.35

0.35 changes little that a deck or a host has to act on. Run `opf validate deck.opf.json --fail-on warning` first: each deck change below is reported, and the icon and layout changes come with a fix.

## Decks

| In 0.34 | In 0.35 |
| --- | --- |
| Eight Lucide icons: `lucide:circle-arrow-out-up-right`, `-up-left`, `-down-right`, `-down-left`, and the same four as `lucide:square-arrow-out-*` | Lucide renamed them: `lucide:circle-arrow-up-right-exit`, `-up-left-exit`, `-down-right-exit`, `-down-left-exit`, and `lucide:square-arrow-*-exit`. The old names no longer draw. `opf/icon-unknown` says the icon was renamed, names the new one and offers the replace fix. |
| `"layout": "auto"` on a slide: automatic composition | Omit `layout`: a slide without one is composed automatically, as `"auto"` was. `"auto"` is now an ordinary layout reference, so it resolves nowhere: `opf/unresolved-reference` says "Layout 'auto' resolves nowhere: OPF 0.35 removed layout 'auto' (omit layout for automatic composition); the slide composes automatically." and offers the safe fix `remove-layout-auto`, which deletes the key. The slide still composes automatically meanwhile. `opf format` no longer drops the key. A catalog may now define a layout with the id `auto`. |
| A block pinned to a region of a built-in layout by its 0.34 name (`"region": "notes"`, Markdown `region=notes`) | The built-in layouts use seven standard body-region names: `body`, `lead`, `aside`, `media`, `first`, `second` and `third` (table below). A 0.34 name is reported as `opf/region-unknown` and the pin is ignored: the block binds by kind, role and reading order, which puts it in the region it was pinned to unless the pin moved it away from plain binding. Rename the pin, or remove it where plain binding places the block. Every layout draws as before. |
| A number format with `;` printed everything after the first section as literal text | The sections are Excel's `positive;negative;zero`: `"+0%;-0%"` gives `+12%` and `-5%`, and `"0;(0)"` puts a loss in brackets. A format that used `;` as literal text now reads as sections; four or more sections, an empty section or one without a numeric part is `opf/number-format-invalid`. |

`title` and `subtitle` are unchanged, as are the regions of `cover`, `section`, `image` (`media`), `image-beside` (`media`, `body`), `list` and `text` (`body`), `two-column` (`first`, `second`) and `three-column` (`first`, `second`, `third`). Roles do not change.

The icon sets follow `lucide-static` 1.72.0 and `@tabler/icons` 3.51.0. Any former Lucide name (304 of them, such as `lucide:alert-triangle`) is answered the same way as the eight above: it does not draw, and the finding names the current one. Tabler ships no rename list.

## Custom layout records

| In 0.34 | In 0.35 |
| --- | --- |
| A region with `"role": "secondary"` (bound after `primary`, before `supporting`) | Write `"role": "supporting"` (or `"primary"`, or leave `role` out for the default `primary`). `role` is `primary`, `media` or `supporting`; `secondary` fails the layout schema: `opf validate` reports `opf/catalog-record` at the region's `role`, and until it is fixed the engines read that region as `primary`. The gallery `dashboard` layout's `kpis` region is `supporting` now and draws as before. |
| An id `auto` was refused for a layout record | Allowed: `auto` is an ordinary id. |
| Region names | Any valid name | Unchanged: a custom record names its regions as it likes. The built-ins use the seven standard names above; a record that follows them pins the same way as the built-ins. Composition reads one name besides the headings: the `aside` of a layout that also has a `first` region is its closing verdict (LH-170: a lone short text there draws as the foot band), as the comparison's `verdict` region was. A custom record that named a region `verdict` loses that rule; name it `aside` beside `first` columns to keep it. |

## Hosts and scripts

| What | In 0.34 | In 0.35 |
| --- | --- | --- |
| Pinned font peers | `@expo-google-fonts/noto-color-emoji` and `@expo-google-fonts/noto-sans-mongolian` at their 0.34 versions | Install `@expo-google-fonts/noto-color-emoji` 0.4.8 and `@expo-google-fonts/noto-sans-mongolian` 0.4.2 with this release; the font manifest's reviewed hashes follow them. Mongolian lines measure 0.1% to 4% differently. |
| `RenderDiagnostic` reason `"shaping"` (`text-as-paths-fallback`, `raster-marker-unavailable`) | A run could stay text under `text: "paths"` with this reason | The reason is gone from the types and such a run is outlined. Drop a `reason === "shaping"` branch. |
| The renderer's shaper without HarfBuzz | fontkit 2.0.4 | fontkit 3.0.0 (ESM-only, Node 22 or later; the renderer already requires both). Myanmar, Syriac, Nastaliq Urdu and Mongolian now measure the same through fontkit and HarfBuzz. |
| The MCP viewer's resource URI | `ui://opf/deck` | `ui://opf/deck/<hash>`, the first 12 hex digits of the page's SHA-256 (`DECK_APP_URI`), so a host that caches a view by its URI gets the new viewer when it changes. `ui://opf/deck` and earlier hashes still read as the current viewer. A host that compared the URI to the literal string reads `DECK_APP_URI` instead. |
| The Design menu's bottom sheet (the editor on a phone) | Three lists that each scrolled | One section at a time behind a switch (Theme, Colors, Fonts, Layout). New label `layoutTab` (default "Layout") for a host that translates the editor's labels; `--opf-design-menu-sheet-h` sets the sheet's height. |
| `AUTO_LAYOUT` from `@openpresentation/opf/composition` | The reserved layout id `'auto'` | Removed. A slide without `layout` is automatic; compare `slide.layout === undefined` instead of `=== 'auto'`. |
| `REGION_ROLES` (core) and `LAYOUT_REGION_ROLES` (editor) | `primary`, `secondary`, `media`, `supporting` | `primary`, `media`, `supporting` |
| `fromPptx` on OPF's automatic layout, or a foreign blank, title-only or unmatched custom layout | `layout: "auto"` | No `layout`. A slide moved to the automatic layout with Change Layout in PowerPoint loses its stored layout (`layout-changed`). `foreignLayoutReference` returns `undefined` for these layouts. |
| PPTX export of a built-in layout | Placeholders and the `OPF_LAYOUT_V1` tag's region map named after the 0.34 regions (`notes`, `verdict`, ...) | Named after the 0.35 regions (`aside`, ...). Import of a 0.34 file: a block restored from its provenance keeps its old pin (`opf/region-unknown`, bound by kind); a block read from a placeholder whose tag names an old region gets no pin and binds by kind. |
| Editor source hints for a built-in layout | A region named like a slide key (`items`, `chart`, `table`, `code`, `timeline`) suggested that key | The regions are `body` and `aside`, so the hint lists the keys of the kinds the region accepts (`chart` or `diagram` for `chart-beside`'s `body`). |
| A custom icon set record | No `renamed` | May carry `renamed`, a map from a former icon name to its current one. Optional. |

## Nothing to change

The MCP viewer on a phone and in a very narrow pane, its host line, the viewer in ChatGPT, PDF text that copies in logical order for reordering scripts, doughnut labels that fit their ring, waterfall labels through a sectioned format, and metric rows with icons need no change to a deck.

## Check the result

```sh
opf validate deck.opf.json --fail-on warning
```
