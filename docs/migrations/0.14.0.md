# OPF 0.14.0 migration notes

0.14.0 is a deliberate break with no deprecation period: names are renamed or removed outright, with no aliases and no
stubs. This page maps what changed. It is written in sections as the parts of the release land.

## Validation: one checker

Releases before 0.14 had a schema validator, a lint and an audit, each with its own entry points, report shape and rule
ids, in the library and in the CLI. 0.14 has one: `validate(input, options?)` and `opf validate`. Its report is a list of
`findings` in the shared [finding format](../finding-schema-reference.md) (`spec/schemas/finding.schema.json`). The
full guide is [validate](../validate.md).

### Names

| Before | 0.14 |
| --- | --- |
| `validatePresentation(value, options?)` | `validate(value, options?)`; the hot-path equivalent is `validate(value, { only: ['format'] })` |
| `assertValidPresentation(value)` | `assertValid(value)` (it throws `OPFValidationError`, which carries the `report`) |
| `validate(value, schemaOrKind, options?)` and `assertValid(value, schemaOrKind, options?)` (the generic validator) | internal; there is no replacement for validating against an arbitrary JSON Schema (use Ajv). A catalog record uses `validateCatalogRecord(kind, record)` and `assertValidCatalogRecord(kind, record)`, which stay |
| `lintSource(text, options)` | `validate(text, { only: ['format', 'references', 'policy'], ...options })` |
| `lintPresentation(document, options)` | `validate(document, { only: ['format', 'references', 'policy'], ...options })` |
| `auditSource(text, options)` / `auditPresentation(document, options)` | `validate(text, options)` / `validate(document, options)`: the default run includes the accessibility, layout and content rules |
| `auditRules`, `findAuditRule`, `DEFAULT_AUDIT_THRESHOLDS` | `validationRules`, `findValidationRule`, `DEFAULT_VALIDATION_THRESHOLDS` (rule metadata gains `category` and `cost`) |
| `ValidationResult` (`errors`, `warnings`) | `ValidationReport` (`findings`, `counts`, `checks`) |
| `LintDiagnostic`, `AuditDiagnostic`, `MarkdownDiagnostic` | `Finding` (Markdown findings are `Finding & { location }`) |
| `LintReport`, `AuditReport` | `FindingReport`, `ValidationReport` |
| `LintOptions`, `AuditOptions`, `ValidateOptions` (`template`, `values`) | `ValidateOptions` (all of them) |
| `LintContract` | `Contract` |
| `LintSeverity`, `AuditSeverity`, `AuditCategory`, `AuditFix`, `AuditPatchOperation`, `LintLocation`, `LintSuggestion`, `AuditRuleInfo`, `AuditThresholds` | `FindingSeverity`, `FindingCategory`, `FindingFix`, `JsonPatchOperation`, `FindingLocation`, `FindingSuggestion`, `ValidationRuleInfo`, `ValidationThresholds` |
| `ValidationIssue` | the same type, now the raw `validation` detail of a finding |
| subpaths `@openpresentation/opf/lint` and `@openpresentation/opf/audit` | removed; `@openpresentation/opf/validator` and the root export the checker |
| `opf validate <file> [--strict]` (schema and semantic checks) | `opf validate <file> [--only] [--ignore] [--fail-on] [--format json\|text] [--config]`: the one checker |
| `opf lint`, `opf audit` | removed (there is no stub: an unknown command exits 2) |
| `--strict` on every command | `--fail-on <error\|warning\|info>` (`--fail-on warning` is the old `--strict`) |

### The report

```js
// before
const { valid, errors, warnings } = validatePresentation(deck);   // ValidationIssue[]
const { diagnostics, counts } = lintSource(text);                 // LintDiagnostic[]
const { diagnostics: design, documentValid } = auditPresentation(deck);

// after: one list, filtered by severity or category
const { valid, findings, counts, schemaValid, checks } = validate(deck);
const errors = findings.filter((finding) => finding.severity === 'error');
```

Every finding has `ruleId`, `severity`, `category` (`format`, `references`, `policy`, `accessibility`, `layout`,
`content`), `path` and `message`, and may have `help`, `slide`, `slideId`, `location`, `measured`, `suggestions`,
`lookup`, `validation` (the raw `ValidationIssue` with `path`, `message`, `keyword`, `schemaPath` and `params`, where
`params.code` was the semantic code) and `fixes`. `report.errors` and `report.warnings` are gone: filter `findings`.
`AuditReport.documentValid` is `schemaValid`; `rulesRun`, `slideCount` and `thresholds` are gone; `checks` now says what
ran (`layout` is `not-run`, `estimated` or `measured`).

A fix has a `title` where it had a `label`, and its `patch` is a full RFC 6902 JSON Patch (any of `add`, `remove`,
`replace`, `move`, `copy`, `test`). `OPFValidationError` has `report` and `findings` (the error findings) where it had
`issues` and `result`.

### What `valid` means now

`valid` is true when no finding has severity `error`. By default only `format`, `references` and `policy` findings (and
`opf/variable-unfilled` in a deck that is not a template) can be errors, so `valid` keeps meaning "correct OPF" and an
accessibility, layout or content finding never makes a deck invalid unless you promote the rule with `severity`. Two
changes follow from folding lint into the same list:

- **A missing `asset:` reference makes a deck invalid** (`opf/asset-reference`, error), and so does an `asset:` cycle, an
  invalid or repeated inline or loaded catalog record (`opf/catalog-record`) and a host contract that fails. These were
  lint errors, never `validatePresentation` errors: `{ "slides": [{ "title": "x", "image": "asset:nope" }] }` was valid
  and is invalid. All 126 bundled examples give the same answer under both. The renderer, the PPTX importer and the
  editor's `rejectInvalid`, which call the checker on every document, see it when they move to `validate`; pass
  `{ only: ['format'] }` to keep the old check exactly.
- **The default runs everything.** `validate(deck)` builds slide layouts (about 80 percent of its cost). A hot path asks
  for what it needs: `validate(deck, { only: ['format'] })` costs what `validatePresentation` cost, and
  `{ only: ['format', 'references'] }` what lint cost. Pagination, conversion, Markdown, `applyPatch(..., { validate: true })`
  and the CLI's write commands call it that way.

Two smaller changes: an unfilled required variable is `opf/variable-unfilled` in the `content` category, so
`only: ['format']` no longer reports it (an error in a deck that is not a template, a warning in a template), and the
catalog ids of a kind with an external `catalogs.<kind>.source` are not judged unless the host passes that source's records
(the lint report warned; `validatePresentation` did not).

### Rules

The 21 objective accessibility, layout and content rules stay. `font-family-count`, `slide-word-count`, `title-position`
and `small-cell` are deleted (taste, not standards: a hosted review is the place for them), with their thresholds
`maxFontFamilies`, `maxWordsPerSlide` and `titlePositionTolerance`. `audit/invalid-document` is gone: a document that
fails the schema reports its `format` findings and `schemaValid: false`. An authored `overflow: "error"` is reported as a
warning by `opf/text-overflow` so that `valid` never depends on font metrics; rendering and export still refuse such a
slide. Rule ids:

| Before | 0.14 |
| --- | --- |
| `audit/<rule>` (every audit rule) | `opf/<rule>` |
| `json/syntax`, `json/duplicate-key` | `opf/json-syntax`, `opf/duplicate-key` |
| `opf/schema`, `opf/asset-reference`, `opf/catalog-reference` and the other lint ids | unchanged |
| `audit/unfilled-variable`; the validator's `variable-unfilled` | `opf/variable-unfilled` |
| `audit/font-family-count`, `audit/slide-word-count`, `audit/title-position`, `audit/small-cell` | deleted |
| `audit/invalid-document` | `opf/schema` and the other `format` findings |
| the Markdown ids `markdown/<rule>` | unchanged, with category `format` |

The old ids are not accepted in `only`, `ignore` or a config file.

### Options

| Before | 0.14 |
| --- | --- |
| `AuditOptions.rules` (`{ id: severity \| 'off' }`) | `severity` (rule or category keys, `error`, `warning`, `info` or `off`) |
| `AuditOptions.textMeasurement` | `fonts: { textMeasurement }` |
| `AuditOptions.only` / `ignore` (rule ids) | `only` / `ignore` (rule ids or category names) |
| `AuditOptions.ignorePaths`, `thresholds`, `catalogs`, `chartPalette` | the same names |
| `LintOptions.catalogs`, `contracts` | the same names |
| `opf audit --rule`, `--ignore`, `--severity`, `--threshold`, `--explain`, `--json`, `--fail-on never` | `--only`, `--ignore`, `--config` (severity, thresholds), `--list-rules` and `--format json`; there is no `--explain` and no `never` |
| `opf lint --config`, `opf audit --config` | `opf validate --config` (one file with the keys of both) |

### CLI reports

The report array is `findings` everywhere: `opf validate`, `opf render`, `opf export`, `opf import` and `opf from-md`
(`diagnostics` before), and the write commands (`create`, `edit`, `fill`, `import-data`, `paginate`, `bundle`) print
`findings` where they printed `warnings`. These commands check only `format` and `references`. Text that is not valid
JSON is now an invalid document to `opf validate` (exit 1, an `opf/json-syntax` finding) instead of a usage error (exit
2). `opf validate` also takes strict JSON text only: Markdown and YAML go through `from-md` (and `fromYaml`).

### Skills and docs

The installed skills (`opf skills install`) say `validate` and `--fail-on`; `opf-inspect`'s helper needs core 0.14 for
`validate`. `docs/lint.md` and `docs/audit.md` are replaced by [validate](../validate.md).
