# Updating a deck from 0.33 to 0.34

0.34 renames a few keys and closes several objects. There are no aliases: an old name is rejected (or, for a small anchored overlay size, reported) and the finding names the new one. Run `opf validate deck.opf.json` after the edits below; it lists every spot with its path, and most findings carry a patch.

| In 0.33 | In 0.34 |
| --- | --- |
| A text run's `"lang": "fr-FR"` | `"language": "fr-FR"` (as on the deck, a slide and a code block). The Markdown span attribute `lang=fr` is unchanged. |
| `design.titleAlignment` and `design.contentAlignment` of `left` or `right` (deck, slide, theme and layout records) | `start` or `end` (`center` is unchanged) |
| `design.chartPrimary` of `left` or `right` | `start` or `end` (`none`, `top` and `bottom` are unchanged) |
| `design.header` and `design.footer` zones `left` and `right` | `start` and `end` (`center` is unchanged) |
| A promoted slide region key with `left` or `right`: `left`, `right`, `left+center`, `center+right`, `left+center+right`, and each of those after `top:`, `middle:`, `bottom:`, `top+middle:`, `middle+bottom:` and `top+middle+bottom:` (for example `top:left`) | The same key with `start` for `left` and `end` for `right` (`start`, `end`, `start+center`, `center+end`, `top:start`, ...). Markdown `region=left` is `region=start`. |
| `caption.align` and a table cell's `style.align` of `left` or `right` | `start` or `end` |
| An image's `placement.edge` and the `edge` of an image `overlay` band of `left` or `right` | `start` or `end` (`top` and `bottom` are unchanged) |
| An anchored overlay shape's size in pixels, `"at": { "block": "note", "edge": "end", "width": 160, "height": 64 }` | `"widthPx": 160, "heightPx": 64`. In `at`, `width` and `height` are now fractions of the target block (1 is the block's own size, at most 8). A pixel size above 8 is a schema error whose finding asks `Did you mean "widthPx"?` (or `"heightPx"`) and whose patch renames the key and keeps the value (up to 1280, the pixel maximum); a value above 4 and up to 8 still validates, as a fraction, and the warning `opf/shape-anchor-size-unit` offers the same rename. |
| An overlay shape or anchored size above 8 (`width` or `height` of a shape in `shapes`, or of its `at`) | At most 8: 8 slide widths or heights for a free shape, 8 times its target for an anchored one. A larger shape is a schema error; a PowerPoint shape larger than 8 slides imports at 8, reported. |
| An object with a misspelled or unknown key that used to be ignored | An error naming the nearest known key. These objects are now closed: `design`, `design.dimensions`, the theme, solid, gradient and pattern backgrounds (and a gradient's stops and a pattern), `design.header` and `design.footer`, an inline `colorScheme` (which declares `name`, the palette name the PPTX export writes) and `fontScheme`, `organization`, `speaker`, an inline `audience`, `purpose`, `tone` and `language`, and the object form of a text run (`"href"` is `link`). Put custom data under `extensions`. |
| A gradient background without `stops` | `stops` is required: `{ "type": "gradient", "gradient": { "stops": [...] } }` |
| A chart whose title or subtitle named a threshold or a period (`"stayed above 92%"`) and got a reference line or band drawn from it | The line is no longer inferred. Write it as `chart.referenceLines`: an ordered list of `{ value, label?, axis?, stroke? }` entries (`stroke` is `"none"` or `{ color?, width?, dash? }`). |

## What stays physical

Layout words and layout coordinates follow the deck's direction (`start` is the left edge in a left-to-right deck and the right edge in a right-to-left one), and what names a place in a picture or a part of a plot stays physical in every language: an image's `focus` and `callouts`, a chart's `legend` and data label `position`, the `left` and `right` of a table cell's borders, and cell and shape `padding`. Do not rename those.

## Also new in 0.34

Nothing to change for these: a slide's own `language`, image `callouts`, `dot` and `plantuml` diagram syntaxes, and a `duration` on a timeline event.

## Hosts that draw gallery icons

Decks do not change: `"icon": "lucide:truck"` means what it meant. What changes is how a host registers the gallery's icon sets. In 0.33
`galleryIconSets` was a catalog that loaded whole sets as modules, so every server bundle carried Lucide and Tabler. In 0.34 the icon
data is static files in `@openpresentation/gallery` (`dist/icons/`, exported as `@openpresentation/gallery/icons/*`), and a deck reads
only the icons it names.

| Host | In 0.33 | In 0.34 |
| --- | --- | --- |
| Node, Bun or Deno: core's `convert`, `open`, `validate`, the CLI, the stdio MCP server | Nothing | Nothing |
| A script that registers its own catalogs | `[gallery, galleryIconSets]` | `[gallery, galleryIconSets()]` |
| A bundled Node server (esbuild, webpack, Next.js; ESM or CommonJS) | Nothing (the sets were in the bundle) | Nothing when it is deployed with its `node_modules`. A deploy of traced files only (Next.js standalone, a serverless function) includes `node_modules/@openpresentation/gallery/dist/icons/**`, or bundles the sets it wants: `galleryIconSets({ lucide })` with `import lucide from "@openpresentation/gallery/icons/lucide.icons.json" with { type: "json" }`. |
| A browser page | `[gallery, galleryIconSets]` | `[gallery, galleryIconSets(fetchIcons("/opf-icons/"))]`, and the build copies the icon files to `/opf-icons/` (below) |
| A Worker | `[gallery, galleryIconSets]` | `[gallery, galleryIconSets(fetchIcons(new URL("/opf-icons/", request.url), env.ASSETS))]` with the files in its static assets, or a bundled set as above. `@openpresentation/mcp`'s `defaultSources()` registers no icon set there; pass `sources.iconSets`. |
| The headless editor | `await loadIconSets(editor)`, then `setIcon` and `composeSlide` | `await loadIconSets(editor)` draws the deck's icons, as before. After `setIcon`, `await change.ready` before `composeSlide`. The canvas needs nothing. |

The copy, from the folder that has `node_modules/@openpresentation/gallery` (all 7,238 files; or only the six set-level `*.json`
files, which a deck then reads a whole set at a time):

```sh
node -e "require('fs').cpSync('node_modules/@openpresentation/gallery/dist/icons', 'public/opf-icons', { recursive: true })"
```

An icon that cannot be loaded (a file that is not served, offline) no longer blocks anything: the slide draws without it and
`opf/icon-unknown` says which icon and why. See [Icons, "Loading"](../icons.md#loading).

## Check the result

```sh
opf validate deck.opf.json --fail-on warning
```

The fragments of the changelog say why each change was made: [run language](../../changes/fa-38-run-language.md), [start and end](../../changes/fa-37-start-end.md), [placement units](../../changes/fa-35-placement-units.md), [closed objects](../../changes/fa-36-closed-objects-and-messages.md), [reference lines](../../changes/lh-110-explicit-chart-reference-lines.md), [icon files](../../changes/rr-63-icon-files.md).

## Check the result with one slide

Start with a copy of a deck that uses the old region names. In a left-to-right deck, changing a promoted region from `left` to `start` keeps its position. Switch the slide’s language to `ar-SA` and the same region moves to the right. An image’s `focus` remains a physical position in its picture. Check both the layout and the crop when adapting a deck for another language.

Run the validator, render a PDF and export a PowerPoint copy from the same source:

```sh
npx opf validate deck.opf.json --format text
npx opf convert deck.opf.json review.pdf
npx opf convert deck.opf.json review.pptx
```

Resolve errors before comparing the outputs. A finding at `chart.referenceLines` with the rule `opf/chart-reference-unsupported-type` means that chart type cannot draw the references. Choose a supported chart type or remove those references. The warning `opf/shape-off-slide` means the entire overlay or image callout is outside the slide. Check its anchor and units. A shape intentionally crossing the edge can remain partly outside.

## Inspect the visual changes

| If the deck contains | What to check |
| --- | --- |
| A single statement, quote or metric | A short message can grow to fill the slide. A lone figure of six characters or fewer can reach 252 reference pixels. Eligible display text on one line uses −1.5% tracking. On two lines, the tighter 1.0 em pitch applies when it permits a larger fit. Review the PNG before adjusting font sizes manually. |
| Charts | Supply the target in `referenceLines`. Confirm the units match the plotted values. Inspect reference labels near bars, gaps in area charts and the fill on radar charts. An overlay attached to a chart point follows its category and series. See the [reference-line deck](../../examples/technical/explicit-chart-reference-lines.opf.json) and the [chart-point overlay deck](../../examples/technical/chart-point-overlays.opf.json). |
| A timeline, picture or hierarchy | A timeline event can express relative duration. Image callouts use the visible picture frame. Org chart, hierarchy and Venn layouts export editable shapes. Check your labels at the final slide size. See the [duration timeline](../../examples/technical/duration-timeline.opf.json) and [image callouts](../../examples/technical/image-callouts.opf.json). |
| Diagrams and SmartArt | Use Mermaid, Graphviz DOT or supported PlantUML syntax. Read the [diagram guide](../diagrams.md) for the supported families and input restrictions. Import a SmartArt graphic to recover its text and hierarchy, then inspect its mapping. |
| Multilingual content | Set `language` on a slide to select its writing direction, script fonts and numbering defaults. Use a Unicode numbering-system override such as `ar-SA-u-nu-latn` for Latin digits in OPF-generated numbers. Authored text retains the digits you typed. |

## Inspect the PowerPoint handoff

Open the exported file in the application your audience uses. Check a wrapped title in Outline view: every slide title now uses the Title placeholder. Change the theme fonts to inspect headings and body runs. Charts keep explicit font names. Body text boxes are still ordinary shapes, and names in the Selection Pane are internal. Compare Aptos baselines if vertical alignment is critical: Windows PowerPoint draws Aptos text about 0.06 em higher than the OPF preview.

Inspect chart, table, logo and quote-photo descriptions. OPF supplies descriptions when authored alternative text is missing. On import, a chart or table description in the generated form is never read as authored `alt`, also after a rename in PowerPoint made it stale; a logo or photo description is left out while it equals the generated one. Review the named layouts, notes page and document properties when handing off a template. Extended charts include a picture fallback for applications that cannot draw them, such as Keynote.

Keynote 15.1.1 opened all 67 qualification files without repair. Every slide title arrives as the slide's title with its lines, and layout names and speaker notes are kept. Keynote draws some things differently: sketch and compound outlines as plain lines, a translucent or tiled background as opaque or as one tile, a lines-only radar filled, a gap in an area chart bridged, direct line labels dropped, and elbow connectors on its own route. Without Aptos installed it substitutes another face, so line widths differ. Letter spacing and Keynote's UI-only views (navigator, outline, notes page, document properties) were not checked. The full list is in [issue #1278](https://github.com/OpenPresentation/opf/issues/1278).

## Update an editor or agent integration

In a host that supplies `textMeasurement`, `composeSlide` reuses measurements of the same string at the same size and style within a call. Keep passing the correct fonts for each slide. For a host that draws icons, use the registration examples above.

In an MCP Apps client, open the editor with `open_editor`. The viewer exposes `read_deck`, `select_slide` and `edit_deck` for working with the open deck. Read it back after an edit to verify the change. For Claude Desktop, use the desktop bundle attached to the release. See the [MCP guide](../mcp.md) for client setup and viewer capabilities.
