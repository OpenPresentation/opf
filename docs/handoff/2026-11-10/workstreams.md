## Resource and reporting policy

- Use one heavy LOCAL build/test aggregate at a time. Source review, documentation, bounded public reads and remote CI can run in parallel. No duplicate watchers, dev servers or ad hoc CI polling loops.
- Coordinator owns integration/publication bookkeeping. Keep feature agents on distinct product lanes; completing an audit frees capacity for another independent task.
- Progress updates use **completed since last update / actively running / blocked or awaiting owner / next gate**. Name the exact scope that passed. Report newly shipped features separately from tests, reports and evidence packets.
- After any material change, update this board and the dated handoff. Each source item retains its PR, fragment, program burndown/progress line and vetoable decisions. No completed result stays local-only; pending checks/publication are labelled pending.
