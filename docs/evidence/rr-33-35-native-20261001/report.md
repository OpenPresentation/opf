## Findings

### F1 (fail, RR-34) Citation markers draw about 0.75x smaller in PowerPoint than in the preview (same raise).
- where: rr34-02-citations s1-s4, rr34-03 s1-s3, rr34-04 s2, rr34-05 s2, rr34-06 s1-s2
- expected: marker the same size and raise as the preview (sz 0.7 of the body, baseline 30000)
- actual: PowerPoint applies its own superscript reduction on top of the explicit sz: digit 1 height 9 px vs 12 px in the preview (measured on the first marker of rr34-02 s1 to s4 and rr34-03 s1; 5 pairs), baseline raise equal (5-6 px). Font dialog still reads 30 % and 13.13 pt.
- likely repo: pptx export (write the marker run at the body size and let baseline do the reduction, or measure the marker as PowerPoint draws it); core docs claim "preview and PowerPoint agree by construction"

### F2 (fail, RR-35) Chartex axis titles are blank in PowerPoint and lost on save.
- where: rr35-06-chartex s1, s3, s4, s5, s10
- expected: axis titles Step/Delta, Bin/Count, Region/Sales, Stage, Spread visible; fromPptx(saved) returns axisTitles
- actual: cx:title text emptied by PowerPoint (<cx:v></cx:v>), HasTitle true with Text "", nothing drawn, import of the saved file loses axisTitles on these 5 slides (61 of 66 RR-35 slides import as expected)
- likely repo: pptx export (cx:title/cx:tx/cx:txData/cx:v without cx:f; use cx:rich)

### F3 (review, RR-35) Heading line breaks differ between export and preview (export wraps to two lines, preview keeps one).
- where: rr35-01 s9, rr35-02 s6, rr35-03 s1, rr35-05 s7, rr35-06 s2 and s10, rr35-08 s1 and s2
- expected: same heading lines in the preview and the file
- actual: the file has "OPF heading ... line 1" shapes and the chart starts at 213 px; the preview chart starts at 148 px (single line). On other slides both wrap but at different words. All 4:3 titles in rr35-08 wrap in the file only.
- likely repo: core composition / preview parity (text measure for headings differs between the export and the render path); not caused by RR-35

### F4 (review, RR-35) Single-series bar/column charts draw the per-point palette in PowerPoint; the preview draws one colour; white inside labels land on pale bars.
- where: rr35-03 s1-s4, s8, s12 and rr35-04 control
- expected: one series colour, label contrast per bar
- actual: per-point dPt colours in the file (e.g. 2874A6, 5499C7); Q4 bar pale green with white inside labels
- likely repo: pptx export vs preview (pre-existing, visible on the control slide too)

### F5 (review, RR-35) Radar data labels collide with the category labels in PowerPoint.
- where: rr35-04 s9
- expected: labels above the points as in the preview
- actual: "20Q2" and "22/Q4" overprint at the left and right vertices (no dLblPos is allowed on radar)
- likely repo: inherent PowerPoint behaviour; consider a note or label-free radar default

### F6 (review, RR-35) Treemap labels sit bottom-left in PowerPoint, centred in the preview.
- where: rr35-06 s8
- expected: centre
- actual: bottom-left of each tile
- likely repo: render preview (match PowerPoint) 

### F7 (review, RR-34) Check text says the wrapped caption has two lines and the long footnotes three or four; manifest, preview and PowerPoint have three and two.
- where: rr34-01 s6, rr34-03 s3 (check wording)
- expected: n/a
- actual: wording stale in the manifest checks
- likely repo: manifest generator text

### F8 (review, RR-34) The supplied RR-34 decks store references under supplement.metadata.references (an older exporter build; the importer at opf-pptx 6d96333 reads them exactly); the branch tip (02809bc and later) stores a top-level key and its importer reports invalid-document-provenance and restores only the cited references on these decks.
