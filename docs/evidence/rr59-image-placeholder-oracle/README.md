# RR-59 exact image placeholder panel oracle

The existing installed CLI export test counts names by the prefix `OPF image placeholder`. In reviewed PPTX source `006e8a7df9c19e85b230a27f19794e5356cdac78`, image-provenance.js defines the semantic panel as `/^OPF image placeholder \d+$/`; the accessible group and its label/icon parts intentionally share that prefix. One placeholder therefore produced a false count of four. The retained [original-failure.log](original-failure.log) follows 77 successful conversion checks.

[slide1.xml](slide1.xml) is actual PPTX output from the explicitly staged core/renderer/PPTX/editor/CLI/gallery graph. It contains one exact panel, one group with `descr="Image unavailable: Image"`, two label lines, and no native picture. [convert.json](convert.json) records its unresolved-image warning. These are local artifact results, not registry qualification.

The helper now counts exact panel names. Installed assertions still require exactly one placeholder, no native picture and the unavailable-image label. No grouping requirement is added to older published PPTX output. The regression covers grouped and older ungrouped shapes, a missing panel, two distinct placeholders and similarly named ordinary shapes. Runtime/export code, versions, baselines and tolerances are unchanged.

The same source CLI harness also exported through genuine locked published renderer/PPTX 0.18.0 packages in the isolated CI worktree. [published-0180-slide1.xml](published-0180-slide1.xml) has one ungrouped accessible panel and two ordinary text shapes; the exact helper still counts one. Both actual XML captures form a regression and preserve count1, no-picture and label assertions. This is a published-peer compatibility proof, not a complete registry CLI qualification. Full corrected peer replay remains required before approval.
