## Schema and explicit replacements

- **Dormant schema writer:** shell `handleSchemaValueApply:2372–2384` also clones and calls `commitDraftDocument`, but has no call site or rendered prop reference. `SchemaActionDock:5673` is defined but never mounted. The rendered `SchemaAccordionSidebar:2673–2683` only navigates to a path. Do not present this dormant callback as a currently reachable editing defect; do not activate it as part of a source-preservation fix.
- **Raw JSON import:** shell `applyLocalRawOpf:1513–1559` intentionally replaces the current draft and accepted document, and records a local version. It trims the incoming text at 1514 and pretty-serializes the parsed object at 1529; `handleSubmit:1577–1579` also passes a trimmed prompt. Replacement is intentional, but loss of the supplied JSON bytes is avoidable. A separate narrow improvement could retain the original input after parse/schema validation, including leading/trailing whitespace, in draft/accepted/local-version strings. Keep explicit replacement semantics distinct from editing the prior document; decide its history contract explicitly.
- **Canvas JSON file import:** `components/author/workbench/opf-canvas-workbench.tsx:72–96` parses the file into a semantic transfer object, previews that document, then performs an explicit public-editor root replacement. The file's raw text is discarded at 82. Carrying imported raw source through preview/apply is a distinct contract change. The existing regression proves exact restoration of the *preceding authored source* on undo; it does not promise byte-identical retention of imported file text. Native PPTX import necessarily starts from semantics, not a JSON source string.

## Recommended next bounded work

1. **First prevent preset undo from discarding later edits.** Retain an exact before/after source pair and document identity for a contiguous preset group. Disable/clear the group after any unrelated source/format/root change; guard Undo against the exact expected current source before restoring. Alternatively implement guarded inverse operations for only the preset-owned fields/catalog additions. Do not blindly restore a whole old document, and do not treat a warning-free serializer as sufficient. A small browser regression should apply a preset, edit unrelated content, then attempt Undo all; also cover New run/import. Exact contiguous undo should be checked separately. No such regression was executed here.
2. **Smallest formatting correction: local author + filename transactions.** Reuse the current source bridge and public editor session rather than adding another serializer/history system. Read/commit current draft, validate the desired semantic result, skip true no-ops, guard the expected current source, then perform one editor operation so the bridge records exact before/after bytes. Preserve the filename clean/accepted rule and name/filename normalization. Test LF/CRLF, escaping, unchanged rich/notes/metadata, add/change/remove/no-op, one-step exact undo/redo, duplicate keys, and a pending canvas draft. These are proposed checks, not new evidence.
3. **Then route local gallery/preset apply through the same transaction**, preserving all catalog additions and addressing the preset undo guard above. Leave the dormant schema callback and raw import contract to explicit, separately bounded changes.

The installed public `@openpresentation/opf-editor@0.8.0` entrypoint declares `applyPatch`, `set`, `undo`, `redo`, and subscription snapshots (`dist/index.d.ts:20–24,50–76`). These are semantic APIs, not raw JSON editors. The app already has `updateJsonSource` (`lib/playground/json-source-edit.ts:13–92`) and `createCanvasSourceBridge` (`lib/playground/canvas-source.ts:10–44`) for raw preservation. Merely replacing `toJsonText` with `updateJsonSource` fixes current output but cannot establish exact history: `useOpfEditorSession:26,43–44` intentionally skips bridge callbacks for source-buffer synchronization. Route the local action through the existing session/bridge, and handle rejected callbacks as the current canvas host does; a successful semantic patch alone is not proof that the raw source was accepted.

This audit excludes ColorRef canvas fidelity, geometry, native Header/Footer, native compatibility, fonts, deployment, and the unresolved completion-popup cause. No package release is required merely to inspect or later repair these application-local writer paths.
