# Quote consumer integration follow-up

Read-only audit after standalone core quote API PR #46. Exact downstream bases: renderer d8696224e7a99618701e641ef7573ef394489885; PPTX 383666b366b8c9b8ed8e7e72934d1d3fd0fb634d; editor e8bdedf7f80e2eab0ff7d869b9436cd2050e426d.

- Core candidate scoring must measure both body and footer, use requested-minus-fitted reductions per part and a documented payload overflow penalty, and version the changed scoring algorithm. Keep explicit modes, weights, source order and parent-before-child decisions. Code remains incomplete. Do not mislabel new behavior as grid-score-v1.
- Accepted leaf geometry should carry the complete quote result. Fit once against final rounded item boxes; renderer/export consume those styles/lines/boxes without re-fitting. Avoid both legacy body fitting and a second complete fit for the same accepted leaf. Candidate exploration is separate from acceptance.
- Strict composition currently matches diagnostic paths exactly to item paths. A quote body diagnostic uses `.text`; descendant diagnostics must be matched with a dot boundary so inherited strict settings cannot miss them. Do not let `blocks.1` capture `blocks.10`.
- Pagination treats quotes as atomic and already rejects non-fitting atomic content. Verify complete quote/source metadata preservation and all-or-nothing rejection for irreducible footer overflow; no silent footer truncation or partial pages.
- Renderer `renderTextBox` already accepts `fit` and `textStyle`. `renderQuote` can consume accepted parts directly. It currently deduplicates diagnostics by code:path, so body/footer overlap reasons sharing a path need deliberate reporting. Invalid available part boxes have no fit: do not fall back to a fresh fit or silently omit source content. Explicit rendering rejection is preferable when geometry is unusable. Warning-mode text overflow can still show all retained lines with diagnostics.
- Renderer `renderResolvedSlide` already exists. Use it with a provider that throws after resolution to prove no quote re-measurement; inspect whether unrelated decoration/font operations still need a provider and scope the test to quotes.
- Converter `addSlide` loops composed items, then passes only payload/region/context to `addPayload`. Pass the accepted quote geometry through that boundary rather than recomputing. `addMeasuredPayloadText` currently always resolves/refits; add a shared-fit/style path or a separate part consumer, with no font measurement after acceptance. Native lines should preserve exact accepted positions/styles and all text, including mappings at the core boundary.
- Parent item text currently represents legacy plain quote body; decide its compatibility contract explicitly if replacing it with the shared body fit including generated quotation marks. Existing renderer ignores it for quote rendering. Audit editor selection/source offsets and public tests before changing it.
- `layoutQuote` retains 18px insets/40px footer, but can raise nominal font size to honor an explicit readability floor. This is intentionally stricter than legacy fitText capping the floor at requested size. Full consumer tests must cover minFontSize > 17, wide/portrait, nested groups, source-only/attribution-only, string shorthand, tiny cells and irreducible overflow.
- Binding already resolves font-family substitutions before composition, so the primitive's requestedStyle may see a pre-resolved family. Broader original-requested-font provenance is still a font-roadmap requirement; do not overstate the standalone part field as preserving the entire original design request through all engines.
- Test complete local/packed/candidate cross-repository behavior before advancing source CI refs. Actual registry verification refs remain on published packages. Keep integration drafts unpublished until coherent core/renderer/converter checks, real browser bounds and native PowerPoint fixtures pass. Full layout repair, code/metric/timeline/chart internals, font shaping and macOS checks remain separate unfinished requirements.
