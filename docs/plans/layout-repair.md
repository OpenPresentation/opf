## Published payload-fit gaps

The registry-only probe `node scripts/probe-payload-fit-gaps.mjs <registry-consumer> [output-prefix]` reproduces two schema-valid counterexamples with installed core 0.7.0 and renderer 0.5.1. The [source fixture](../evidence/payload-fit-gaps-2026-09-09.opf.json) and [report](../evidence/payload-fit-gaps-2026-09-09.json) record package versions/registry lock integrities and exact font/source hashes. They use bundled Carlito/Cousine advances; neither browser glyph bounds nor native raster equivalence is asserted.

- A short quote with a long attribution receives no composition diagnostic, but the renderer reports text overflow in the footer.
- A long code language label measures 4200.68 pixels against 1128.8 available, but neither composition nor renderer reports overflow. Core estimates the code body without the real internal insets or label; the unreleased explanation now correctly lists code among incomplete payloads.

The probe deliberately asserts the published gaps. It is a historical reproduction command, not a claim that overflowing output is acceptable or a general quality gate for a future corrected release. Use the preserved fixture as an acceptance input for shared quote/code placement and diagnostics. Keep complete code coverage marked unmeasured until its label, body and internal constraints are actually shared. The coverage-only correction preserves geometry and passes all six explanation tests on Node 20/24 and all 420 core tests plus composition/pagination/data/rich-text/list suites on Node 24.

## Earlier quote checkpoints and next acceptance criteria

The following standalone checkpoints are historical; the quote integration is now published as recorded above. Their source-only evidence must not be confused with the later actual registry and native evidence.

The standalone API below is merged in core PR #46 (`6d8df02940deec8f1fa89192d10576d6048de341`) after all core/coordinated/Windows/macOS checks and review passed. Continue the [exact consumer integration plan](shared-quote-integration.md) on `codex/shared-quote-integration-20260909`; it records the important strict-path, rounding, source-mapping and measurement-reuse boundaries. The primitive remains unreleased and is not yet connected to the other engines.

Branch `codex/shared-quote-layout-20260909` starts the shared-measurement increment with an additive standalone `layoutQuote` API. It returns body/footer available boxes, complete display text, source ranges, requested/resolved styles, fits and reasoned diagnostics. It keeps the current 18-pixel insets and footer reservation for compatible readable cases, raises nominal text sizes when an explicit readability floor requires it, and leaves invalid available dimensions visible without inventing a one-pixel fit. Text-fit, out-of-cell and conservative line-box overlap failures can reject strictly. These line boxes do not establish glyph-outline or native raster equivalence.

This API alone does not connect the three engines or repair layouts. Existing `composeSlide`, preview and PowerPoint output remain unchanged and still report quote/code as incomplete coverage. Next, consume the same result in candidate scoring, accepted geometry, rendering and native export, with no independent re-fitting after acceptance; then add code internals and dynamic repair/pagination. No publication is warranted from the standalone primitive alone.

Candidate verification: all 426 core tests and composition/nesting/pagination/data/rich-text/list suites pass on Windows Node 20/24. Six quote tests cover legacy readable geometry, immutable source/mappings (including Unicode and whitespace), requested/resolved styles, strict failure, line-box overlap, invalid internal dimensions and scaled readability floors. Public root/focused declarations compile. `node scripts/test-quote-layout-geometry.mjs <registry-consumer> [report.json]` adds four actual-font wide/portrait cases against the release-plan renderer; both supported runtimes produce the same [source/runtime/font-bound report](../evidence/shared-quote-layout-2026-09-09.json). The first portrait fixture used wrong dimension fields and was rejected by the exact-dimension assertion; the final fixture uses schema-valid `widthInches`/`heightInches` and validates before measurement. Coordinated CI now executes this check after installing actual registry packages. Review and complete CI remain gates on this candidate.

1. Share payload-internal measurement and placement between core composition, renderer and converter. Start with quote body/footer and code language/body, then metric value/labels, timeline annotations and chart labels. Reuse complete payload geometry in scoring, preview and native export; do not copy formulas into another subsystem. Diagnose complete internal overflow/collisions. Preserve requested/resolved font paths and state which measurements are estimates. Add wide/portrait, oversized and mixed-style fixtures before changing selection behavior.
2. Build a bounded repair operation that generates candidate arrangements and weight allocations, enforces an explicit readability policy and evaluates measurable hierarchy, balance, whitespace, media proportions and density. Existing manual modes/weights/regions need explicit preservation or user-authorized relaxation. Include the current arrangement as a stability preference; avoid unnecessary movement after small edits. Report candidate costs, rejected constraints, reasons and the measurement scope. No content deletion, truncation, summarization or implicit undersizing is allowed.
3. When arrangement cannot fit, invoke explicit pagination only under the caller's policy. Return ordinary accepted slides, complete source mappings and diagnostics, with all-or-nothing failure for irreducible content. Preview and export must consume those same slides. Headings, rich runs, metadata, notes and every source character require preservation tests.
4. Expose one guarded operation through APIs, CLI and the six existing skills as appropriate, and add a canvas **Auto arrange** draft preview with cancel/commit and one undo step. Stale drafts must reject safely. Headless callers and human controls must use the same underlying operation and font provider.
5. Establish layout quality evidence beyond regression hashes: representative and unseen content, varied dimensions/density, malformed and valid-but-poor layouts, scripts/fonts, nested groups and impossible constraints. Track readability and visual coherence separately from geometry stability. Execute real browser edit/undo/export/reimport and native PowerPoint checks on the accepted documents. Missing macOS PowerPoint/Keynote evidence stays explicit.

## Font work continues alongside layout

The [font roadmap](font-roadmap.md) and [fidelity evidence](../font-fidelity.md) remain required. Exact font provenance/hashes, variant-specific substitution, shaping/fallback/bidirectional coverage, line breaks and native slide raster comparisons must be evaluated separately. The current Carlito Arabic error is an observed coverage gap, not a reason to remove multilingual source content. Essential bundled fonts must remain offline; proprietary reference fonts must not be redistributed. Matching widths, readable editable text or unchanged image hashes do not establish pixel equivalence.
