# Deterministic layout and repair

This work implements the [ecosystem objective](ecosystem-objective-2026-09-09.md) in reviewable increments. It does not introduce a model, account, key, network or paid-service dependency into OPF. Proprietary applications remain optional compatibility-test environments.

## Implemented first increment: explain existing selection

Branch `codex/layout-repair-20260909` adds opt-in `composeSlide(slide, {explain:true, ...resolvedOptions})`. The result reports the versioned `grid-score-v1` candidate costs, selected column count, fixed-mode/region reasons, measurement-provider status and incomplete payload coverage. Strict overflow errors retain the same explanation. Core 0.7.0 is already published and does not include this API; a future release is required.

The geometry and selection algorithm remain unchanged. Costs expose current heuristics; they are not a polished-layout guarantee. See [the exact rules and scope](../dynamic-composition.md#explain-automatic-selection-next-core-release).

Local Windows verification on Node 20 and 24: 417 core tests, composition/nesting/pagination/data/rich-text/list suites, 11 CLI unit tests and 69 command checks pass. Six new tests cover geometry/content/measurement-call preservation across dimensions and modes, component cost accounting, configured weights/regions, candidate caps, reserved slots, tied scores, unsupported payload paths and strict error explanations. Public root and focused declaration imports compile. Typecheck, lint (existing warnings), 126 example files, schema/breaking gates, six portable skills with 17 helper checks and dependency audit pass. The root dependency tree was refreshed from the merged lockfile after an initial stale generator-15 installation caused the generator-16 type-contract test to fail; the locked rerun passes. Windows still skips the file-symlink CLI case when privileges are unavailable; no OS setting was changed.

## Next increments and acceptance criteria

1. Share payload-internal measurement and placement between core composition, renderer and converter. Start with quote body/footer, then metric value/labels, timeline annotations and chart labels. Reuse complete payload geometry in scoring, preview and native export; do not copy formulas into another subsystem. Diagnose complete internal overflow/collisions. Preserve requested/resolved font paths and state which measurements are estimates. Add wide/portrait, oversized and mixed-style fixtures before changing selection behavior.
2. Build a bounded repair operation that generates candidate arrangements and weight allocations, enforces an explicit readability policy and evaluates measurable hierarchy, balance, whitespace, media proportions and density. Existing manual modes/weights/regions need explicit preservation or user-authorized relaxation. Include the current arrangement as a stability preference; avoid unnecessary movement after small edits. Report candidate costs, rejected constraints, reasons and the measurement scope. No content deletion, truncation, summarization or implicit undersizing is allowed.
3. When arrangement cannot fit, invoke explicit pagination only under the caller's policy. Return ordinary accepted slides, complete source mappings and diagnostics, with all-or-nothing failure for irreducible content. Preview and export must consume those same slides. Headings, rich runs, metadata, notes and every source character require preservation tests.
4. Expose one guarded operation through APIs, CLI and the six existing skills as appropriate, and add a canvas **Auto arrange** draft preview with cancel/commit and one undo step. Stale drafts must reject safely. Headless callers and human controls must use the same underlying operation and font provider.
5. Establish layout quality evidence beyond regression hashes: representative and unseen content, varied dimensions/density, malformed and valid-but-poor layouts, scripts/fonts, nested groups and impossible constraints. Track readability and visual coherence separately from geometry stability. Execute real browser edit/undo/export/reimport and native PowerPoint checks on the accepted documents. Missing macOS PowerPoint/Keynote evidence stays explicit.

## Font work continues alongside layout

The [font roadmap](font-roadmap.md) and [fidelity evidence](../font-fidelity.md) remain required. Exact font provenance/hashes, variant-specific substitution, shaping/fallback/bidirectional coverage, line breaks and native slide raster comparisons must be evaluated separately. The current Carlito Arabic error is an observed coverage gap, not a reason to remove multilingual source content. Essential bundled fonts must remain offline; proprietary reference fonts must not be redistributed. Matching widths, readable editable text or unchanged image hashes do not establish pixel equivalence.
