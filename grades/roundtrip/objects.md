# Object kinds: what OPF 0.36.0's objects became in Keynote 16.0 (pass A)

Generated by `scripts/rt_objects.py` + `scripts/rt_report.py` from every opened file (no sampling). Data: `objects.json` (one record per object, link, notes, hidden slide). Source of each outcome: Keynote's object model (`probe.json`, aligned 1:1 with back.pptx's top-level elements, 0 mismatches) and back.pptx (Keynote's own PowerPoint export) for what the dictionary cannot show (links, bullets, crops, chart types). All SAW from those files unless a cell says inferred.

Files: 0.36.0 + main slide-links: default 37 files, native 22 files, static 1 files. The five `experiments-fonttest` files are one deck (coverage-images) five times, so their pictures and links count five times. 0.35.1 counts are in `objects.json` (`aggregate0351`). Static mode was opened only for `layouts-ordinary` (every other static file equals default byte for byte in its slides).

Outcomes: **native** = same Keynote object kind and the same text / rows x columns / chart type / crop; **changed** = still editable but different (how in the right column); **picture**; **dropped**.

## What a Keynote user can and cannot edit, per kind

- **slide title**: Edit: the title is the layout's title placeholder (isDefaultTitle on every slide); a title OPF wrapped over two lines in default mode is the placeholder plus a second, ordinary text box (they do not reflow together). Keynote shrinks a title that no longer fits (Helvetica is wider than Aptos) and writes the shrunk size back. A centered title placeholder (ctrTitle) comes back as an ordinary title.
- **body text**: Edit: every line is its own text box in default mode (typing does not reflow into the next line); in native mode one paragraph box per text region, re-wrapped by Keynote. Font face is Helvetica on screen (Aptos missing), but the file keeps the name Aptos.
- **other text**: Edit: captions, metrics, code, quotes, timeline and card text are ordinary text boxes. Text inside a non-rectangular shape (step badges, diagram nodes, vertical text) becomes a group of the shape and a separate text box: move the group, edit the text box; the text no longer belongs to the shape.
- **list items**: Edit: bullets and numbers are real list styles (buChar / buAutoNum in back.pptx, from the shape or the layout), not typed characters. In default mode each line is a box, so a list item cannot gain a line by typing; numbering is per box via startAt. In native mode Keynote's list levels work.
- **table**: Edit: a native Keynote table, same rows and columns, header row recognized (header row count 1), no merges in pass A to test. All cells are text (numbers such as "$4.2M" or "42" are not numeric cells: format "automatic", value a string), so sorting and formulas treat them as text. Fills move into a table style on export; right alignment of number columns is not written back.
- **chart (native)**: Edit: native Keynote charts with their data (Edit Chart Data; values, series and categories survive into back.pptx). Stacked line charts become plain line charts. Highlight charts (two series) keep both series. Hidden value axes stay hidden (as "no labels"). Category column header of the data sheet is lost.
- **chart (extended)**: None in pass A: OPF 0.36.0 wrote no cx: (extended) chart part in any opened file.
- **shape**: Edit: native shapes with their preset geometry; rare presets (chartX, chartStar, chartPlus, cloudCallout) and diagram arrow heads become groups of freeform parts.
- **line/connector**: Edit: OPF writes lines as p:sp prstGeom line, never p:cxnSp, so Keynote has free lines (class "line"), not connection lines; one zero-length timeline line is dropped.
- **group**: OPF writes no groups except a native diagram's group; Keynote itself creates 116 groups (see "other text", "shape").
- **diagram**: SmartArt (graphicFrame dgm) arrives as a picture: not editable. OPF's own diagram (a group of shapes and lines) stays an editable group.
- **picture**: Edit: native images. Crops survive (a:srcRect within 1/100000). Rounded-rectangle and ellipse picture shapes become a custom outline mask (custGeom). A letterboxed picture (negative srcRect, "contain" fit) becomes a frame sized to the image, with a rectangle behind it in a group when it had an outline. The Description is the shape's name ("OPF image 1"), never OPF's alt text.
- **link on text**: Edit: web links on runs survive as web links with the same URL; Keynote recolors linked runs blue (0000EE) and ignores OPF's "link color = text color" extension.
- **link on a shape**: Edit: links on shapes (social footers, video frames) survive as web links on the shape.
- **link to a slide**: Edit: every slide jump (run, shape, table cell, to a hidden slide) survives as ppaction://hlinksldjump to the same slide; whether a click follows it is a UI check.
- **presenter notes**: Edit: notes come through verbatim (probe and back.pptx).
- **footer / slide number / date**: Edit: a footer text stays text; the live slide-number field stays a live field inside an ordinary text item (scripting shows U+FFFC), not Keynote's Slide Number switch ("slide numbers showing" is false); the box shrinks to the number. Static numbers (--slide-numbers static) are plain text.
- **hidden slide**: Kept: the one hidden slide (slide-links slide 4) is skipped in Keynote and show="0" in back.pptx.
- **transition/timing**: None in pass A (OPF has no transitions). Keynote reports "no transition effect" on every slide and writes an empty p:transition (spd=med, advClick) into every slide of back.pptx.
- **empty text box**: Blank-line boxes OPF writes (empty paragraphs, mostly in language decks) are dropped by Keynote; nothing visible is lost.

## Notes on the method

- Kinds are read from OPF's shape names (`OPF heading slides.N.title line K` = slide title, `OPF list` / native body with buChar or buAutoNum = list items, `OPF text` / native body = body text, `OPF furniture` or sldNum/ftr/dt placeholder = footer, other text-bearing shapes = other text, `prstGeom line` = line) and the DrawingML element. Keynote keeps every OPF name (a picture with a `title` gets `title`+`name`), which is what makes object-level matching possible.
- "Text differs" was never seen: every text box that arrived kept its exact text (whitespace-normalized).
- Font substitution (Aptos drawn as Helvetica) is not counted as "changed" here; see `text.json` and answers.md section 3.
- Things only the user interface can tell are in `../ui-checks.md` (RT section).
