SH-09: pyramids and matrices, written to PowerPoint as live SmartArt. A layout region's new `arrangement` (`"pyramid"` or `"matrix"`) draws its lone list of one level as PowerPoint's Basic Pyramid (1 to 8 levels, the first at the top) or Basic Matrix (up to four quadrants over a diamond), with PowerPoint's own geometry, every node in the primary color outlined in the background, and one text size for every node, the list's role size or larger, never smaller (an entry that does not fit keeps the list). The gallery adds the `pyramid` and `matrix` layouts (32 layouts). Core exports the geometry and paint (`pyramidNodes`, `matrixNodes`, `arrangementPaint`) and the domain PowerPoint was compared on (`SMART_ART_DOMAIN`, `smartArtUnavailable`); the preview draws the nodes under the centered entries. The PPTX export writes live SmartArt where the instance lies in that domain: a `p:graphicFrame` with OPF's data model (explicit run sizes with `custT`, so PowerPoint keeps them), OPF's own colors and quick style parts, a drawing from core's geometry and no layout part (`r:lo` empty: OPF never writes a SmartArt layout definition); elsewhere, and with `smartArt: "shapes"` (CLI `--smart-art shapes`), native `trapezoid`, `roundRect` and `diamond` shapes under the measured lines, with the info finding `pptx/smartart-unavailable` and its reason. Import reads an unchanged OPF SmartArt (`OPF_SMARTART_V1`) back as its list on its layout, and an edited one or a PowerPoint-authored Basic Pyramid or Basic Matrix from its data model (the nodes in `cxn` order with their run properties). See `docs/smartart.md`.
