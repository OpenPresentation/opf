RR-62: `@openpresentation/opf/node`, core's Node-only file API, and `opf convert`.
    - `convert(input, output, options?)` turns a `.pptx`, `.opf.md`, `.yaml`/`.yml` or `.json` file, a deck object or PPTX bytes into a `.pdf`, `.pptx`, `.png`, `.svg`, `.zip`, `.opf.md`, `.yaml`/`.yml` or `.json` file, the formats named by the extensions (`slides/deck.png` writes `slides/deck-001.png`, ...; one selected slide is written to the output itself; a `.zip` holds PNG slides, or SVG with `format: "svg"`). Everything is produced before anything is written, each file atomically, parent folders created; an existing output needs `force: true`. Images resolve next to the input file. `convert(input, { format })` returns `{ files: [{ name, type, bytes }], findings }` and writes nothing.
    - `open(pathOrBytes)` returns the presentation of a deck file, or imports a `.pptx` (path or bytes); an invalid deck throws `OPFValidationError` with findings located by line and column. `save(deck, path, { validate })` writes the form the extension names, atomically, and refuses an invalid deck unless `validate: false`.
    - Typed errors with a `code` (`OPFApiError`, `OPFExportError`, `OPFImportError`): `peer-not-installed` with the install command, `peer-too-old`, `peer-load-failed`, `invalid-option`, `invalid-presentation`, `input-not-found`, `output-exists`, `no-slides`, `export-failed`, `import-failed`.
    - The export and import engine, the lazy loading of `@openpresentation/opf-render` and `@openpresentation/opf-pptx` (now optional peers of core) and the fonts are behind it; the office font pack is prepared once per process (byte-identical output). `/node` re-exports the rest of core, so `import * as opf from "@openpresentation/opf/node"` covers an application. The root and every other subpath stay free of the file system (`check:browser-safe`).
    - CLI: `opf convert <input> <output>` with the flags, report and exit codes of `opf export`; `render`, `export` and `import` run core's engine.
