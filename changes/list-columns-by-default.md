Breaking (0.35 layout simplification, step 7): the layout region key `listColumns` is removed. A list of more than 6 entries now flows into up to three columns in any layout region without an `arrangement` (or with the `numbered` one, the agenda's), as `listColumns: "auto"` let it, and keeps the columns only when they set it at least as large as the same list in one column and do not overflow where one column fits, so a default never sets a list smaller. A region made for a list (`list` its first accepted kind, as on `agenda`, `faq` and `list`) keeps the rule `listColumns: "auto"` had (LH-184: columns up to a type-scale step under one column whose lines would run past the reading measure), except that columns that overflow give way to one column that fits at least as large. A region with a diagram or the `steps` sequence keeps the list in one column; the implicit row below a layout's grid too. A list payload's own `columns` (1, 2, 3 or `"auto"`) still chooses. A record that still sets `listColumns` fails the layout schema: `opf validate` reports `opf/catalog-record` at the key, says what replaced it and offers the safe fix `remove:listColumns`; an engine handed the record directly ignores it. The gallery `agenda`, `faq` and `list` records drop the key. The editor's layout inspector has no "List columns" field (`REGION_KEYS` and `LayoutRegion` lose `listColumns`; core's `LayoutRegion` too, and new `regionListColumns(region)` says whether a region's long list may take columns).

In a row of cells sized by `composition.weights`, a list whose cell is narrower than its longest word no longer breaks inside the word: the row is rebalanced (the list's cell widens to the narrowest width at which every word holds at its starting size, so at any size it is set at there; an icon list is measured with its chips, and the other cells give that width up while none of their text is set smaller), or, when they cannot, the blocks are stacked in one column, kept only when no block reads smaller there (guarded rule `list-words`). The list is never set smaller to keep its words whole. Known limit: a row too crowded for either, such as weights 3:3:1 with two long paragraphs beside a list of long words (the "Crowded row" slide of `list-words-row.test.mjs`), keeps its weights and still breaks the words; the list keeps its size.
