LH-42, LH-77, LH-85 (output-changing for slides with several lists, a one-entry described list or a nested list): lists stay whole. `listColumns: "auto"` (and a list payload's `columns: "auto"`) never deals a list of 6 or fewer entries across columns (`LIST_WHOLE_ENTRIES`), so "Queue | Route | Resolve" no longer reads as a table row. A region that receives 2 or more lists and nothing else lays them out one list per cell, a card when the slide draws cards, in a grid of 2 to 4 columns for 2 to 4 lists, 3 for a multiple of 3, otherwise 4 (`listGridShape`; narrower and portrait regions take fewer columns); each row is as tall as its tallest list needs with descriptions and nested entries counted, at the largest size at which every row fits, and the region's lists share that size, so a list no longer draws over the next row. A list of exactly one entry with a description (and no numbering) draws as a heading: the entry bold at `LIST_HEADING_SCALE` (1.25) times the list size with no bullet, over its description at the list size (`ListFitOptions.heading`, `ListEntryLayout.heading`); the PPTX export records the bold heading as the list's own look, so import returns the plain entry. The bullets now alternate • and an en dash by level (`LIST_MARKERS`, as PowerPoint's default levels do) instead of •, ◦ and ▪, which most bundled faces (Roboto, Open Sans, Montserrat, Lora, Poppins and others) lack and the preview drew as a missing-glyph box; the PPTX export writes the same characters. The stacked-column measure of a described list no longer counts it one size step too tall below the description floor. The gallery's list, agenda, agenda-split and faq layouts draw these changes.
