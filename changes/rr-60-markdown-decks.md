RR-60: Markdown decks (`deck.opf.md`) are a native input and output of every command, and core has one entry point to read and write a deck in any form. Core: `readDeck(text, { format, filename, catalogs, validate })` returns the deck with the `validate` report of it for JSON, YAML or Markdown, every finding located in the text that was read (JSON syntax errors are `opf/json-syntax` with line and column), and `writeDeck(presentation, { format | filename })` writes it; both are exported from the root and from the new subpath `@openpresentation/opf/deck`, with `deckFormatOf(filename)` (`.opf.md` is Markdown, `.yaml` and `.yml` are YAML, anything else JSON; the content is never sniffed and a plain `.md` file is never a deck). `fromMarkdown` now returns the full `validate` report like `fromYaml` (`schemaValid`, `checks`, and `template` and `unfilledVariables` for a template). CLI: a file ending `.opf.md` is a Markdown deck in `validate`, `render`, `export`, `create --from`, `edit`, `format` (canonical Markdown; `--check` works), `merge`, `diff`, `stats`, `paginate`, `embed`, `fill`, `import-data` and `to-md`; `--input-format` takes `markdown` (alias `md`) for stdin and other names; a Markdown syntax error exits 2 with `line:column` and located findings under `markdown` (`opf validate` reports `markdown/<rule>` findings and exits 1); a command writes Markdown for an output ending `.opf.md` or `--format markdown|md`, else the format it read, and warns on stderr when a rewrite moves content into `opf-slide`/`opf-block` fences. `opf stats` now reads YAML and Markdown decks, and a JSON syntax error in any deck input now names its line and column. JSON stays canonical; `from-md` and `to-md` are unchanged. The Markdown example `examples/markdown/quarterly-review.md` is now `quarterly-review.opf.md`.
