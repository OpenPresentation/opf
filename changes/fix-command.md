`opf fix <deck> [output]` (`-i`, `--check`, `--format json|text`) applies the safe fixes of a deck's findings, the first step of the 0.35 migration (`opf fix deck.opf.json -i`, then validate). It validates the deck as `opf validate` does, applies each finding's fix marked `safe` (`use-max-1`, `remove:listColumns`, `use-arrangement`, `rename-arrangement`, `rename-layout`, `rename-region`, `remove-layout-auto`, `use-current-record` on an unedited 0.34 copy, a renamed icon, ...), one per finding, and validates again, round after round, since an error in the deck's own keys hides the later checks, until no safe fix is left (at most 10 rounds). It works on the deck's own layout records (`catalogs.custom`), which `opf embed -i` leaves alone, as well as on stale copies of built-in layouts. A fix not marked safe is never applied: its finding stays in the report and in `fix.unsafe`. The report lists each fix applied (`fix.applied`: round, rule id, path, fix id, title) and the findings that remain; the deck is written with the fixes even when findings remain, and the exit status is 1 when findings at or above `--fail-on` remain, when the rounds ran out, or when `--check` finds a safe fix to apply. Core exports the same as `fix(deck, options)` (`FixOptions` with `maxRounds`, `FixResult`, `AppliedFix`, `DEFAULT_FIX_ROUNDS`); in Node it registers the gallery when `catalogs` is omitted. The message of an `opf/catalog-record` finding on a stale embedded copy of a built-in layout now starts with what the copy is ("catalogs.default.layouts.cover is an unedited copy of OPF 0.34's release of the built-in layout 'cover': must be equal to one of the allowed values"), so a reader of messages alone learns the cause.
