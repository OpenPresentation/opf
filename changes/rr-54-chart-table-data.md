RR-54 (additive schema plus one behaviour change; lockstep with the renderer, PPTX and editor later): chart and table data. Contract: [docs/chart-table-data.md](docs/chart-table-data.md).
    - **Behaviour change (strict chart numbers):** core `chartNumber` is the one rule for chart values: a finite number, or a trimmed string in strict decimal syntax (`"12"`, `"-3.5"`, `"1e6"`). Anything else (`"12%"`, `"$5"`, `"(5)"`, `"1,234"`, `"Q1"`, booleans) is a gap and a `chart-value-not-numeric` validator warning, never a guessed value. Once the renderer and PPTX adopt it, a deck whose chart cells hold `"12%"` or `"$5"` previews and exports a gap where the exporter used to strip the characters and write 12 or 5. Data import (`createDataContent`, `opf import-data`) already used this rule and now calls `chartNumber`.
    - **Schema:** `NumberFormat` (the `NumberVariable.format` syntax, now shared by it); `DataColumn` (`{ name, format }`) wherever a chart, dataset or table column is a string; `StyledTableCell.format` (a body cell's own format wins over its column's); `ChartData.source` and `Dataset.source` provenance (`DataSourceRef`: `src`, `sheet`, `range`, `fields`, `retrieved`, `description`), which engines never read; top-level `datasets` with `{ "dataset": "<id>", "fields"? }` as the third `chart.data` branch and as a dataset-backed table form (`dataset`, `fields`, no `rows`/`columns`); `chart.mapping` (`category`, `x`, `series` by column name). A document that uses none of them validates as before; `pnpm check:breaking` reports none.
    - **Core API** (`@openpresentation/opf` and `@openpresentation/opf/data`): `chartNumber`, `formatDataNumber`, `numberFormatError`, `excelNumberFormat` and `numberFormatFromExcel` (round-trip every NumberFormat through an Excel format code), `inlineDatasets`, `inlineTableData`, `inlineChartData`, `resolveChartData` (the positional `[category, (x,) ...series]` table after datasets, fields and mapping), `resolveTableData`, `tableCellDisplayValue`, `datasetDiagnostics`, `unusedDatasets`, `isXYChartType`, `isDatasetRef`, and the `DataDiagnostic` and data types.
    - **Validation and lint:** errors `dataset-unknown`, `dataset-field-unknown`, `data-column-duplicate`, `chart-mapping-unknown-column` and `number-format-invalid`; warnings `chart-value-not-numeric`, `chart-data-source-unresolved` (a `ChartDataSource`, which no engine loads, [opf#240](https://github.com/OpenPresentation/opf/issues/240) descoped) and `chart-mapping-adapted`; lint keeps them as `opf/<code>` and adds the warning `opf/unused-dataset`. The bundled examples that show the `ChartDataSource` form keep it and carry the new advisory.
    - **Core integration:** `composeSlide`, `layoutTable` (which measures formatted cell text and reports it as the cell `value`) and pagination accept dataset-backed tables and charts; conversions, Markdown, format, diff and the audit keep or read the new fields; `resolveVariables` fills dataset rows.
    - **CLI:** `opf import-data --dataset <id>` writes the imported data into `datasets.<id>` (with the file as its `source`) and references it from the new table or chart.
