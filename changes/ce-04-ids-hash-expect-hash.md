CE-04, CE-05: ids, id-addressed paths, `documentHash`, `expectHash` and patch scope, new `@openpresentation/opf/ids` entry (all also on the package root). `assignIds(document, { generate? })` fills the missing `id` of slides and content payloads deterministically (`slide-1`, `block-1`, ... skipping ids in use) and never changes an existing one; it returns `{ document, patch, assigned }` and throws `OPFIdError` for a `generate` that returns an unusable id. In an array, the pointer token `@intro` names the element whose `id` is `intro` (`/slides/@kpis/blocks/@note/text`): `applyPatch`, `applyPatchWithInverse`, `readPointer`, `getAtPointer` and `hasPointer` resolve it (an object key that starts with `@` is still a plain key), `resolveIdPointer` and `toIdPointer` convert a pointer, `resolveIdPatch` and `toIdPatch` a whole patch operation by operation, and the new error codes are `patch-id-not-found` and `patch-id-ambiguous`; inverse patches stay in index form. `documentHash(document)` is `sha256:` and the SHA-256 of the document's key-sorted canonical JSON (RFC 8785), in pure synchronous JavaScript that is the same in Node, browsers and edge runtimes; `applyPatch`, `applyPatchWithInverse` and `edit` take `expectHash` and throw `OPFPatchHashError` (`patch-hash-mismatch`, with `expected` and `actual`) before applying anything when the document changed, or `invalid-expect-hash` for a value that is not a hash. `touches(patch, document?)` returns what a patch reads and writes (`reads`, `writes`, each with `pointer`, `idPointer`, `kind`, `ids` and `slideIds`, plus the union and the kinds) for conflict detection and permission checks. `walkPatch`, the one loop under patch application, is exported from `/patch` for these callers.
