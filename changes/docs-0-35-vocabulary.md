0.35 layout simplification, step 9 (no drawing changes): a writing command that refuses a deck (`opf convert`, `opf paginate`, `opf embed`, `opf edit`, `opf fill`; `invalid-document` or `findings-at-fail-on`) now names `opf fix <deck> -i` when some of its findings carry a safe fix ("2 findings carry a safe fix: `opf fix <deck> -i` applies them, then validate again."), before the `opf embed <deck> -i` sentence it already adds for stale embedded copies of built-in layouts. The docs, the package READMEs and the six skills (which the CLI installs and the MCP server serves) use the 0.35 vocabulary: a layout is a record with regions, a block's `region` pins it to one or names a cell of the 3 x 3 grid on a slide without a layout, and an automatic slide is arranged by `composition.mode`, `columns`, `weights` and groups. The skills' shared glossary adds "Layout and region" and says how `composition` steers a slide; the skills teach `design.titlePosition`, a region's `flow`, `max: 1` and `arrangement`, and the migration path `opf fix deck.opf.json -i`, then `opf validate`. The removed 0.34 words (promoted regions, `listColumns`, `flow: "none"`, `layout: "auto"`, the `flow` and `agenda-split` layouts, 0.34 region names) remain only in `docs/migrations/0.35.md`. The migration note puts what 0.34.2 already shipped (the eight renamed Lucide icons and the icon set versions, `;` number format sections, and the fixes that need no deck change) under "Already in 0.34.2", names each removed region key's safe fix, and ends with `opf fix deck.opf.json -i` before `opf validate`.
