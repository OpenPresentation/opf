Placed texts with a run-in heading no longer crash (opf#1469), and `opf fix` leaves no `layouts.auto` record behind (opf#1471). A valid deck whose blocks name their cells (`region`) and open with a short "Label:" (`{"blocks":[{"region":"top:start","text":"a: b"},{"region":"bottom:end","text":"c"}]}`) stopped `opf validate`, every preview and the PowerPoint export with "Cannot read properties of undefined (reading 'some')", and, from 0.36.0, `opf fix` of the 0.34 form of such a slide. Composition re-fitted a placed tile, a text tile and a foot-band text from the authored string and left the run-in runs on a fit made without them; each re-fit now lays out the runs, and the SVG renderer draws the authored text when it is handed runs without a fit made from them. Output of a slide that drew before is unchanged. The safe fix `remove-layout-auto` also removes the embedded layout record `auto` when it fails the layout schema and no slide names it after the fix (with several slides, the fix of the last one carries the removal), so the fixed deck validates; a valid record `auto`, a record a slide still names, and every other record stay.
