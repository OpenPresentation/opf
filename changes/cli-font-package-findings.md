A deck whose fonts need a font package that is not installed (a design that names Consolas is drawn with Cousine, from `@expo-google-fonts/cousine`, which the quickstart does not install) no longer makes `opf validate` fail with `internal-error` (exit 2): it is a `fonts/font-package-not-installed` warning that names the package, the faces that need it and the one install command, and the layout is then estimated (`checks.layout: "estimated"`) rather than measured with another face. `opf doctor <deck>` now answers for that deck: the drawn formats are missing only the font packages the deck's faces need (`deckFonts`), and the packages it does not use are listed apart (`fontPackages.others`), so doctor no longer lists Caladea, Arimo, Tinos, Cousine, Gelasio and Noto Sans as missing for a Roboto deck that `opf convert` draws; without a deck, the font packages no longer decide readiness. `opf convert` reports a face drawn with another face (Aptos with Intos) as one `fonts/font-substituted` info finding per requested family, with the face drawn instead, how close it is and why (a proprietary font OPF does not bundle); every deck `opf create` writes by default gets one or two of them. The renderer's missing-font-package error is a correct sentence that names each package with its faces (`details.faces`), for example "This presentation needs a font package that is not installed (an optional peer dependency of @openpresentation/opf-render): @expo-google-fonts/cousine (Cousine)."
