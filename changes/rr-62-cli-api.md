RR-62: `@openpresentation/cli/api`, the format-oriented library API of the CLI package. `readDeck`, `writeDeck`, `validate` and `assertValid` are core's own (re-exported, with `defaultCatalog`); `exportDeck(presentation, { format: "pdf" | "png" | "svg" | "pptx", fonts, fontDirs, catalogs, slides, includeHidden, paginate, scale, pdfMode, svgFonts, chartex, provenance, imageFormat, date, assetDir, zip, filename })` returns `{ files: [{ name, type, bytes }], findings }` (one file per slide for `svg` and `png`, or one zip with `zip: true`; one file for `pdf` and `pptx`) with the bundled open fonts, no network, no system fonts and no clock unless `date` is passed; `importDeck(bytes, { catalogs, signals })` reads a PPTX into a presentation. `@openpresentation/opf-render` and `@openpresentation/opf-pptx` stay optional peers, loaded the first time a function needs them; a missing, old or broken one throws `OPFExportError` or `OPFImportError` with `code` `peer-not-installed`, `peer-too-old` or `peer-load-failed` and the install command (other codes: `invalid-option`, `invalid-presentation`, `no-slides`, `all-slides-hidden`, `export-failed`, `import-failed`; `findings` carry the located findings). `opf render`, `opf export` and `opf import` now run the same engine as `exportDeck` and `importDeck`: their options, JSON reports, error codes and exit codes are unchanged. Core is now a regular dependency of the CLI (`@openpresentation/opf`, `^0.16.0`) instead of a bundled copy, so the `opf` command, `@openpresentation/cli/api` and an application that imports core directly run one core (one set of error classes, one catalog, no version skew); `opf --version` reports the installed core. The package declares an `exports` map (`./api` with `dist/api.d.ts`, and `./package.json`); `opf` is still the `bin`.
