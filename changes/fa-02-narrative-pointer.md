FA-02 (breaking, pre-v1, no aliases): a narrative is a plan and lives in the catalog; the deck holds a pointer. The root `narrative` is a plain string (a catalog id, an HTTPS URL or a `pkg:` reference) and the `Narrative` and `NarrativeBeat` definitions are removed from `opf.schema.json`; a custom narrative is a record in `catalogs.narratives.records`. `slides[].beat` keeps the slide-to-beat link. In the narrative record schema, `durationRange { minMinutes, maxMinutes }` becomes `duration { min, max }` (minutes), a beat's `slideType` becomes `type` (the `Slide.type` values: text, list, image, video, chart, table, code, metric, quote, timeline; `shape` is gone), `layoutHint` becomes `layout`, and `slideCount` is removed (one beat is one slide). All 48 bundled records and the example decks are migrated, and `bundle` follows a beat's `layout`. New `validate` findings: a warning about a `slides[].beat` id the resolved narrative does not define (`opf/unknown-beat`), about a root `duration` outside the narrative's `duration` range (`opf/duration-outside-narrative`) and about an inline record whose `duration.min` exceeds `duration.max` (`opf/narrative-duration-range`), and `opf/unused-beat` (content, info) for a beat no slide references; `opf/unknown-beat` is a `references` finding and the duration findings are `content` findings. `check:spec` rejects an inverted range in a bundled record. The `thoughtCues` description no longer claims they reach presenter notes, and the root `duration` description names its real readers (the opf-render presenter timer and `validate`).
