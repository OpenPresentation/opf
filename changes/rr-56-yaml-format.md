RR-56: OPF as YAML. Core `@openpresentation/opf/yaml`: `fromYaml(text, { aliases, validate })` reads a deck written as strict, JSON-compatible YAML 1.2 (one document, a mapping at the root, no custom tags, duplicate keys, non-string keys or non-finite numbers; anchors, aliases and merge keys only with `aliases: true`, capped at 100 aliases) and returns `{ document, valid, diagnostics, counts }` with lint-shaped diagnostics (`yaml/...` for syntax and dialect errors, `opf/...` for the OPF lint findings) that carry the offset, line and column of the YAML; `toYaml(document, { schemaComment })` writes canonical YAML (schema key order, two-space block style, no folding, ambiguous strings such as `"yes"` and `"2026-10-01"` quoted) that is read back before it is returned, and throws `OPFYamlError` for an invalid deck; `lintYamlSource`, `parseYamlData`, `yamlLocator`, `scanYamlComments` and `YAML_SCHEMA_URL` complete it. CLI: `opf from-yaml` and `opf to-yaml`; every command that reads a deck or patch reads a file ending `.yaml`/`.yml` (stdin and other names follow the global `--input-format <json|yaml>`, default JSON; a YAML error exits 2 with line and column), and every command that writes a deck writes YAML for an output ending `.yaml`/`.yml` or with `--format yaml` (otherwise the format that was read). Commands that rewrite a YAML file do not preserve comments and print a warning on stderr. See [docs/yaml.md](docs/yaml.md).
