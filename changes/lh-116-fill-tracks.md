LH-116, LH-101, LH-102 and the widened LH-80, LH-64, LH-47 and LH-10 (layout harvest; output-changing for automatic slides with a picture track under a long title, lone code panels, under-filled layout bodies, rows of cards that mix a table or code with other kinds, automatic grids with a short last row, and long paragraphs in full-width layout regions). An automatic picture track spans the title band only when the title fits one line beside it (after LH-51's steps); otherwise the tag, title and subtitle take the full width and the track bleeds from the body top to the side and foot. A track is no longer kept when it would wrap a table cell the slide set on one line. A lone code panel grows its code in type-scale steps (up to the code display size) and hugs it in the middle of the body; only code that covers at least 60% of the body takes the whole body, its lines in the middle of the panel (new `layoutCode` option `fill`; `codeLayout.bounds` is then the panel). A layout body of text, lists, quotes, metrics, code, tables or timelines (pictures only in a bled region) that covers under 60% of the body height sits in the middle of the space under the headings, its regions taking their need and its cards hugging, when it moves as one and no block reads smaller. A row of middle- or bottom-anchored cards with a table, code panel or timeline among other kinds starts at the card top instead of three anchors. In automatic composition the cells of the scored grid's short last row stretch to the full width, unless every block is a picture or video. A paragraph in a layout region keeps the reading measure (about 70 average characters of its size), unless the body would then not grow (LH-48), since a readable size outranks the measure. Each rule is guarded like the other wave 3 rules: no block's body size is smaller; of the 844 LH-27 corpus slides none gained a finding or a smaller size. Preview and PPTX export read the geometry from core and agree.
