Selected text in the editor's code surfaces is readable in the light and the dark scheme (4.5:1 or better, focused or not). The CodeMirror views (source pane, JSON editor) are flagged dark when their `--opf-ui-*` tokens resolve to a dark color scheme and follow a later change of the page, a forced-light surface or `prefers-color-scheme` (new `src/source-color-scheme.js`), so CodeMirror's own light selection (`#d7d4f0` behind light text) is no longer used on a dark surface; the selection tint comes from `--opf-ui-accent` with a selector that out-specifies CodeMirror's focused rule in any stylesheet order and is one rule for the source pane and the standalone editor (the source pane's separate 16% rule is gone). The handoff prompt, the data grid's text areas and the numbering preview get a native `::selection` from the same tint and `--opf-ui-fg`. `--opf-ui-warn` in the light scheme is `hsl(28 75% 30%)` (was `38%`, 4.5:1 only before any tint), so selected numbers keep 4.5:1. The new browser test `test/selection-contrast-browser.mjs` selects text in each surface by keyboard and by mouse, focused and not, in both schemes and asserts 4.5:1 against the computed selection background.
