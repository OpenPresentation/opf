FR-10 (part 1): a variable can carry translations. A text, list, url or image variable takes `translations`, a map from a language tag to `{ "value": ... }` in the form of the variable's own value; a date variable's entries are `{ "format": ... }`, because the date is the same in every language and how it is written is not. The language of the place where the variable is drawn selects the entry: the slide's declared `language`, else the deck's, then the tag with its last subtag removed (`de-AT`, then `de`), without regard to case, else `value`. It applies to an inline `{{id}}` and a whole `var:id` field alike, in titles, text, notes, captions and links; a language read from the text selects nothing, so a deck with no declared language draws `value` as before. A template may hold translations without a `value` (the variable is filled where the language selects one). `maxLength`, `maxLines` and `maxItems` apply to every translation and report the translation's path. Two keys that differ only in case are the warning `opf/variable-translation-duplicate`, and a translation no declared language selects the warning `opf/variable-translation-unused`. `opf fill` and `fill()` remove a variable's translations when a record gives a value without translations (reported as `translationsRemoved`; a date's formats stay), and a record may give `{ "value": ..., "translations": ... }` itself. The editor's Fill template panel lists translations as rows with Add translation (the deck's and slides' languages first), through `setVariableTranslation` and `removeVariableTranslation`. Variables resolve before the PowerPoint export, so each slide's text is in its language; nothing new is stored in the file. A deck with no translations validates, draws and exports exactly as before. See `docs/templates-and-variables.md` and `examples/technical/variable-translations.opf.json`.
