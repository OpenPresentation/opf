0.35 migration of self-contained decks: a deck that `opf embed` filled with copies of the built-in layouts before 0.35 failed the 0.35 layout schema with no way forward. `catalogs.default` mirrors the built-in records (a customized layout belongs in `catalogs.custom`), so now `embed()` (and `opf embed -i`) replaces each such copy with the current record first, whatever release wrote it and whether it was edited, and lists it in the new `EmbedResult.refreshed` (`RefreshedRecord`: `how` `current` or `renamed`, `changesDrawing` when the record changed): the copy takes the current record and each pin of its slides the region's 0.35 name, and a copy of `flow`, `vertical-flow` or `agenda-split` moves its slides to the replacement and is dropped (as `rename-layout` does); the 0.35 engine draws the slides. Other invalid content is still refused. `opf validate` says what such a copy is ("a copy of the built-in layout 'cover' from before OPF 0.35") and gives it one fix, `use-current-record` (or `rename-layout`), safe and marked `changesDrawing`, which `opf fix -i` applies; a slide on an embedded record that fails its schema is no longer told the record is not embedded. Custom layout records get a help that names the replacement and a safe fix for `sequence` (`use-arrangement`), `pyramidDirection` (`use-inverted-pyramid`, `use-pyramid`) and the `flow` and `vertical-flow` arrangements (`rename-arrangement`), two fixes for `role: "secondary"`, and an embedded record's 0.33 `left` or `right` alignment the safe `change-to:start` or `change-to:end`. `opf/region-unknown` for a 0.34 region name of a built-in layout names the 0.35 region with the safe fix `rename-region`, and a pin on a block drawn as the automatic foot band (the comparison's `verdict` text) is now reported instead of dropped. The CLI's writing commands (`opf convert`, ...) name `opf embed <deck> -i` when a deck fails because of such copies.
