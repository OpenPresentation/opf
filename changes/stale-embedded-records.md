0.35 migration of self-contained decks (no drawing changes): a deck that `opf embed` filled with copies of the built-in layouts before 0.35 failed the 0.35 layout schema with no way forward. Now `embed()` (and `opf embed -i`) makes each such copy valid first without changing what it draws, and lists it in the new `EmbedResult.refreshed` (`RefreshedRecord`): an unedited copy of the 0.34 release takes the current record and each pin of its slides the region's 0.35 name, an unedited copy of `flow`, `vertical-flow` or `agenda-split` moves its slides to the replacement and is dropped, and any other copy gets the safe fix of each removed key; other invalid content is still refused. Whether a copy is unedited is decided by its content hash against every version of the built-in record released before 0.35 (a fixed table in core). `opf validate` says what such a copy is ("an unedited copy of OPF 0.34's release of the built-in layout 'cover'") and adds the fix `use-current-record` (safe for an unedited 0.34 copy, offered for an earlier or edited one) or `rename-layout`; a slide on an embedded record that fails its schema is no longer told the record is not embedded. Custom layout records get a help that names the replacement and a safe fix for `sequence` (`use-arrangement`), `pyramidDirection` (`use-inverted-pyramid`, `use-pyramid`) and the `flow` and `vertical-flow` arrangements (`rename-arrangement`), two fixes for `role: "secondary"`, and an embedded record's 0.33 `left` or `right` alignment the safe `change-to:start` or `change-to:end`. `opf/region-unknown` for a 0.34 region name of a built-in layout names the 0.35 region with the safe fix `rename-region`, and a pin on a block drawn as the automatic foot band (the comparison's `verdict` text) is now reported instead of dropped. The CLI's writing commands (`opf convert`, ...) name `opf embed <deck> -i` when a deck fails because of such copies.
