Breaking (0.35 layout simplification, step 2; no drawing changes): the built-in layouts name their body regions with seven standard words, `body` (the main content), `lead` (an opening block above it), `aside` (supporting content beside or under it), `media` (a picture or video), and `first`, `second` and `third` (parallel columns); `title` and `subtitle` and every role are unchanged. 32 gallery layout records are renamed (for example chart-beside's `chart` and `notes` are `body` and `aside`, comparison's `verdict` is `aside`, dashboard's `kpis` and `charts` are `lead` and `body`); they draw exactly as before, and `docs/migrations/0.35.md` lists every old and new name. A block pinned to a 0.34 name is reported as `opf/region-unknown` and binds by kind. Core's closing-note rule (LH-170) reads the `aside` of a layout that also has a `first` region as its verdict, where it read a region named `verdict`. PPTX export names the placeholders of a built-in layout and its `OPF_LAYOUT_V1` region map after the new names; import of a 0.34 file keeps a restored old pin (reported, bound by kind) and pins no block whose placeholder the tag names by an old region. The editor's source hints for a built-in region now list the keys of the kinds it accepts, since no built-in region is named like a slide key. The layout sampler, the gallery examples and the other example decks use the new names (the sampler keeps one pin, on its table slide, where a pin keeps the layout's composition).
