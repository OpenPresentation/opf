LH-104 (output-changing for the `image` layout and for automatic slides with one picture beside other blocks): a picture fit `auto` (`fit: "auto"` on an image block, `design.imageFit: "auto"` on a slide, deck, theme or layout) covers the frame when the crop keeps at least 85% of the picture along the cropped dimension (at most 7.5% off each edge, from the EXIF-corrected proportions against the frame) and contains it otherwise; an SVG, or a picture whose size core cannot read from the document, is always contained, and an authored focus or the LH-84 portrait focus still places a cover crop. Core decides it (`fitImage` takes `auto`; new on `/composition`: `autoImageFit`, `coverKept`, `AUTO_FIT_MIN_KEPT`, the `ImageFitOption` type), so the preview and the PPTX export draw the same fit; `ComposedItem.image.fit` is the fit it took and `autoFit: true` says it was `auto`. The gallery `image` layout's default fit changes from `contain` to `auto`: a picture close to the frame's shape now fills it with a light crop (with a title, the region is about 2.24:1, so a 16:9 photo is still shown whole), any other picture is shown whole as before. The automatic picture track (LH-80) takes only the shares whose crop `auto` would take, instead of any crop that keeps half of the picture; a cover picture that no share crops that lightly gets a track that keeps at least half of it only when the slide reads better with it (a larger smallest body size or fewer findings), so a 16:10 photo beside text mostly stays whole in the flow. The editor offers `auto` as an image fit and as a design `imageFit`.
