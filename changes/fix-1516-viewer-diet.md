The MCP viewer (`ui://opf/deck`) is 285,269 bytes smaller in its JSON-RPC frame (9,501,842 to 9,216,573, 1,269,187 bytes of headroom under the SDK's 10 MiB stdio limit, and the test's headroom floor is 1,000,000 again), with build-time changes whose results are proven identical (opf#1516). Core's generator writes the font policy, the DrawingML preset geometry and the engine vocabularies in a compact form (`scripts/compact-literal.mjs`: each repeated string named once, each repeated row shape built by a function), and stops unless what it builds has the same JSON text as the spec file; `FONT_POLICY`, `LANGUAGES`, `CHART_TYPES`, `SOCIAL_PLATFORMS` and the preset shapes keep their values, types and freezing, and load in the same time. The precompiled validators build enum, additional-property and bound errors (`minimum`, `maximum`, `exclusiveMinimum`, `minItems` and the like) with three more helpers that derive params and message from the schema, each chosen only where Ajv's own code is the same; every error still equals Ajv's property by property. The viewer's build writes the gallery's records and the renderer's font manifest as the same compact expression instead of JSON text; other consumers of both packages are unchanged, and the viewer starts in the same time (Chromium, 40 runs, median difference -4.1 ms). See `docs/programs/release-readiness/mcp-viewer-size.md`.
