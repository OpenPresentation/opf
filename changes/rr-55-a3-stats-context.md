RR-55 part A3 (breaking, no aliases; lockstep with the renderer, PPTX and editor later): `stats`, `resolveSlideContext`, the `fonts` handle, and a smaller package root. Guide: [docs/stats.md](docs/stats.md).
    - **New `stats(presentation, options?)` and `opf stats <file|-> [--format json|text] [--per-slide]`:** neutral, structural facts about a deck, never severities or thresholds: deck metadata and references, people, slides (hidden, sections, layouts), payload kinds, words in content and in notes, notes coverage, images (alt, decorative, missing alt, logos, watermarks, backgrounds), charts, tables, datasets and their sources, citations, variables, assets (embedded, files, remote, registry), header and footer, fonts, colour variables, and an estimated speaking time (130 wpm, labelled `estimate`). It does not compose, measure or validate, so it needs no fonts and works on a deck that fails validation; the 126 bundled examples take 18 ms in total (0.14 ms each) against 46 ms for `validate(deck, { only: ['format'] })`. Output is deterministic with a stable key order.
    - **New `resolveSlideContext(presentation, index, { fonts?, catalogs?, slideNumber?, slideCount?, date? })`:** one slide's canvas, layout, theme and font families (slide design, then deck design, then theme, then the default font scheme) as the `ComposeSlideOptions` that `composeSlide` takes, plus `diagnostics` (`unresolved-font-scheme`, `unresolved-layout`, `unresolved-theme`, `unresolved-color-scheme`) and the records it resolved from. Core pagination and the layout checks of `validate` use it instead of two hand-written copies of the chain.
    - **Breaking, `ComposeSlideOptions.fonts` is now `fontFamilies`** (`{ heading, body, code, accent? }`), and so is the `fonts` option of `layoutQuote`, `layoutMetric`, `layoutCode` and `layoutTimeline`, which frees `fonts` for the shared fonts handle.
    - **Breaking, deck-level verbs take `{ fonts }`:** `paginate` and `paginateSlide` read `fonts.textMeasurement` (the new structural `Fonts` type: at least `{ textMeasurement? }`; the renderer's richer handle extends it) and no longer read a top-level `textMeasurement`. `docs/quickstart.md` passed `fonts` to `paginate`, where it was ignored; it now shows `{ fonts }`. The `slideOptions` hook of `paginate` is removed: `resolveSlideContext` supersedes it and no package used it.
    - **Breaking, the package root keeps app-level names only:** the layout engine (`composeSlide`, `resolveCanvasDimensions`, `fitText`/`fitList`/`fitRichText`, `layoutX`, `resolveFontFamilies`, `resolveFontSchemeReference`, `DEFAULT_FONT_SCHEME`, `OPFCompositionError`, numbering, footnotes/citations/captions, colour (`colorContrast`, `resolveColorRef`, `normalizeHexColor`, ...), code syntax, metric trend, pattern fills, chart options, script fonts and text direction) is exported from `@openpresentation/opf/composition` only, and the symbol-font tables from `@openpresentation/opf/symbol-font-encodings` only. The chart, table and dataset helpers (`chartNumber`, `formatDataNumber`, `resolveChartData`, `inlineDatasets`, ...), font policy, variables, catalogs, schemas, pagination and bundling stay at the root. `/composition` gains `normalizeHexColor`, `resolveColorRef`, `resolveScriptFonts`, `resolveSlideDirection`, `scriptFontRole`, the code-syntax, metric-trend and pattern-fill names. A host that feature-detects an engine name on the root (`typeof core.resolveScriptFonts === "function"`) must import `/composition`, or it silently loses the feature.
    - **CLI:** `opf render --paginate` passes the loaded fonts as `{ fonts }`.
