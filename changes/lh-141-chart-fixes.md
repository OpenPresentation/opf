LH-141, LH-142, LH-143 (output-changing for charts with whole-number values of four digits or more, for horizontal stacked bar charts whose every segment is labeled, and for charts whose legend is wider than the header row): three chart follow-ups from the Claude Design chart comparison, decided once in core and drawn by both engines. See `docs/chart-options.md`.
    - **Thousands grouped by the deck language (LH-141).** A series of whole numbers with a value of four digits or more, and no number format of its own, prints its default value labels grouped ("6,240"; "6.240" in a German deck; the locale's own separator from `Intl`), and so do the value list and the doughnut hole of a pie, a line's end labels and the labels of a stacked chart's segments. A metric's numeric value of four integer digits or more groups too (a string value is the author's text and is kept). In PPTX the series' own data labels take the number format `#,##0` (the cache and the value axis keep General), so PowerPoint's labels agree with the preview. A format the author wrote is never regrouped, and a series with a fraction keeps the General form. New core exports: `groupNumber`, `groupsThousands`, `NUMBER_GROUPING_MIN`, `GROUPED_LABEL_CODE`. Not done: value axis tick labels, waterfall, funnel, treemap and histogram labels stay as they were.
    - **Labels or an axis, not both (LH-142).** A horizontal stacked bar chart whose every segment with a value carries it inside (not a 100% chart, not a chart with a value axis title) drops its value axis, tick labels and gridlines in the preview and in PPTX (`stack.valueAxis === false`, core `chartValueAxisHidden`; the plot grows by the tick row). One segment too narrow for its value keeps the axis. A stacked bar chart whose bars align to a table's rows keeps its axis.
    - **A wide header legend wraps instead of moving to the side (LH-143).** A header legend (LH-81) wider than the header row used to move to a side legend when the preview's font measured it too wide and stay on top when the PPTX export's font measured it narrower, so the same chart had two plot widths. The entries now wrap onto a second row (`CHART_HEADER_LEGEND_ROWS`, `chartHeader`), so both engines put the legend on top and keep the plot at the chart's width whichever font measures it; only an entry wider than the row, or a legend of more than two rows, keeps the side legend. This changes every column, bar, line, area and combo chart whose legend did not fit one row.
