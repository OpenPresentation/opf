RR-63 (breaking for hosts that register the gallery icon sets): a host pays for the icons its decks draw and for nothing else. In 0.33 `galleryIconSets` of `@openpresentation/gallery/icon-sets` was a catalog whose loaders imported a whole set as a module by a path every bundler follows, and core's Node defaults registered it, so any server bundle of core's Node build carried Lucide and Tabler (2.2 MB in an esbuild bundle; pptx.dev's Worker grew from 34.0 to 56.1 MiB between 0.32.1 and 0.33.0, about 6.4 MiB of it icon data) and a deck with three icons loaded two whole sets. Now the icon data is plain static files in the gallery package under `dist/icons/`: `<set>.json` (license, copyright, viewBox, style and every icon name: 33 KB for Lucide, 82 KB for Tabler), `<set>/<name>.json` (one icon, about 150 bytes) and `<set>.tags.json` (search keywords, read only by a search). `galleryIconSets` is a function, `galleryIconSets(load?)`, that registers the two sets over those files and reads each set's index once and one file per icon a deck names; `load(path)` resolves a file's JSON value, defaults to reading the installed files in Node, Bun and Deno, and `fetchIcons(baseUrl)` is the `load` for files a host serves. The `@openpresentation/gallery/icon-sets/<id>` whole-set modules are removed. Core's icon loaders are called with `{ icons: [names] }` (a search asks `{ tags: true }`) and may resolve with a record whose `names` lists every icon and whose `icons` holds the ones asked for; a loader that ignores the request and resolves with the whole record works as before. A loader that fails no longer rejects `ensureIcons`: the set's icons get `opf/icon-unknown` ("The icon set lucide is registered but could not be loaded: ..."); every other finding text is unchanged. Core's Node defaults, the CLI and the stdio MCP server register `galleryIconSets()`, so `convert`, `open`, `opf convert`, `opf validate` and the MCP draw and check icons with no setup, and a server bundle of any of them carries no icon data (an esbuild bundle of the Node build's `validate`: 6,429 to 4,239 KiB; the full MCP Worker: 32.4 to 30.2 MB). The editor's `loadIconSets(source, ids, { icons, tags })` loads only the icons asked for, its search reads names and keywords, and its icon picker reads the path data of the icons on the page it shows. What a host writes now: `galleryIconSets()` where it wrote `galleryIconSets` (Node), or `galleryIconSets(fetchIcons("/opf-icons/"))` in a browser page or a Worker, with `node_modules/@openpresentation/gallery/dist/icons/` copied to `/opf-icons/` by its build. See docs/icons.md, "Loading".
