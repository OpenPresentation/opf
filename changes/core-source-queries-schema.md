`@openpresentation/opf/schema` (new, browser-safe subpath): the field model of a document, read from the JSON Schemas, for source editors, the CLI and agents. The schema navigation helpers move here from the editor (`resolveSchema`, `schemaVariants`, `schemaType`, `activeSchema`, `schemaAtPath`, `schemaLabel`, `createSchemaValue`, `listSchemaFields`, `splitOpfPath`) with the same behavior; a path into an embedded catalog record (`catalogs.<group>.themes.<id>.background`) now resolves instead of throwing, and a union is entered through the form that has the member (`audience/0`, the list form). New `describeField(path, document?)` returns a `FieldInfo` for any position: the types, description, enum values, default, examples, whether the parent requires it, the `oneOf` variants with the one a template should use (`primary`), the ranked `children` (required first, then the curated `COMMON_KEYS` order of the deck, slide and design, then alphabetical; promoted regions, `extensions` and `$schema` are `advanced`), the item schema of an array (`itemInfo`), the entry schema of a map (`entryInfo`), `requiredChildren` and `freeText`; an unknown path returns `{ known: false }`. New `catalogKindAt(path, document?)` names the catalog a reference field points into (`layouts`, `themes`, `colorSchemes`, `fontSchemes`, `narratives`, `audiences`, `purposes`, `tones`) from a new `x-opf-catalog` annotation next to the `CatalogReference` uses in `opf.schema.json` and `theme.schema.json` (an annotation: validation is unchanged); `language` is an engine vocabulary and is not a reference, a language's `fontScheme` and `googleFontScheme` are.
