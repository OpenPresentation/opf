Source editor keyboard parity, phase 0 (completion): in the JSON source editor, `Tab` now accepts the selected suggestion (it indented the whole line and closed the list), `Enter` accepts it at once instead of inserting a line when pressed right after a keystroke (the list is reused while you keep typing the same token, `validFor`, and the 75 ms interaction delay and the 100 ms typing debounce are gone; a Tab or Enter that arrives while the first query is still answering waits for it), `Ctrl+Space` (and `Cmd+I` on macOS) opens the completion list, also right after a finished string, instead of the options dialog, and `Ctrl+N` and `Ctrl+P` move the selection on macOS. The options dialog is on `Alt+Shift+O` (and, with `completions: false`, on `Ctrl+Space`); a click on an enum or catalog value only places the caret, it no longer opens the dialog and takes the focus, and `Tab` and `Shift+Tab` stay inside the dialog (`Escape` returns to the editor) instead of leaving it open behind the page. With several cursors the list stays closed, so `Tab` and `Enter` keep their plain meaning at every cursor. Cases: `test/source-keyboard-browser.mjs` (`J-ACC`, `J-CTRL`, `X-DLG`, `J-FLOW`).
