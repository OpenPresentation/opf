RR-20 (release records; no package change): the release plan, compatibility matrix, quickstart, live-editor guide, README, CLI README and the other docs and skills that name the published set adopt the 0.13 set: core 0.13.0 (gitHead 209e3a2, RR-54 chart and table data), opf-render 0.13.1 (gitHead e6665f1, Sharp 0.35.5), opf-pptx 0.13.2 (gitHead 673dbba, Sharp 0.35.5), opf-editor 0.12.1 (gitHead 1d4af4e, the RR-54 data grid; replaces the unpublished 0.12.0) and CLI 0.11.0 (gitHead 1bd4923, bundles core 0.13.0). Renderer, PPTX and editor floor core `^0.13.0` and the renderer peer `^0.13.1`. The published-matrix consumer and the registry consumer move to that set, the compatibility matrix records the 0.12.2 set as the previous one, and `engines.node` is documented as `>=22` for the current set. The quickstart's `paginatePresentation(document, options)` no longer passes a `fonts` option, which the function does not have (it resolves the font scheme itself). `scripts/registry-golden.mjs` drops the RR-41 retained golden: no release-plan core ships that corpus any more, so the registry run selects the lock's core golden (corpus digest `394c4ce7...`). The installed-parity harness links an installed package copy's node_modules entry by entry when npm nested a dependency into it (opf-render 0.13.1 ships its own pako 1.0.11), instead of failing with EEXIST (`scripts/published-matrix/link-modules.mjs`).
