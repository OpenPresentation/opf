Breaking (0.35 layout simplification, step 3; no drawing changes): a layout region says how it draws its content with one key, `arrangement`, which merges `sequence`, `arrangement` and `pyramidDirection`. Its values are `steps` and `numbered` (step badges, formerly `sequence`), `pyramid`, `inverted-pyramid` (formerly `pyramid` with `pyramidDirection: "down"`), `matrix`, `cycle`, `chevrons`, `process` and `vertical-process` (formerly `flow` and `vertical-flow`, now PowerPoint's names Basic Process and Vertical Process), `org-chart`, `hierarchy` and `venn`; `sequence` and `pyramidDirection` are removed, and a record that still uses them or an old value fails the layout schema (`opf/catalog-record`). The `metrics` key is unchanged. The gallery records `agenda`, `agenda-split`, `process`, `flow`, `vertical-flow` and `inverted-pyramid` changed accordingly and draw exactly as before; layout ids are unchanged. The `drawing` declaration is for the gallery stability check, which draws the 0.34 records with the 0.35 engine: there the 0.34 values `flow`, `vertical-flow` and `pyramidDirection` no longer read, so those three records draw a list or an upright pyramid, while the 0.35 records draw as the 0.34 records did. Core's `LayoutRegion` has the one `arrangement` (`regionSequence` and `regionDiagram` read the two families; new `REGION_ARRANGEMENTS`, `SEQUENCE_ARRANGEMENTS`), a composed arrangement's `kind` is the region's value (`process`, `vertical-process`, `inverted-pyramid`; no `pyramidDirection`), and the renderer's SVG trace `data-opf-arrangement` follows it. PPTX export writes the new kinds in its SmartArt and arrangement tags; import maps PowerPoint's Basic Process, Vertical Process and Inverted Pyramid to the new values on the same `flow`, `vertical-flow` and `inverted-pyramid` layouts, and reads the `flow` and `vertical-flow` tags of a 0.34 file. `docs/migrations/0.35.md` lists every old key and value.
