LH-106 (output-changing for decks whose language has digits of its own, and for fractional numbers in decks whose language writes a decimal comma): numbers in languages with their own digits are now consistent, in the preview and in PowerPoint. Every number the engines generate from a numeric value (a metric's value and delta, chart labels, ticks and percentages, table cells that hold numbers, step badges and agenda numerals, number variables on a slide) is drawn through one core function (`formatNumber`) in the numbering system of the slide's language, else the deck's: an `ar-SA` deck now draws `٩٩٩` beside `١,٠٠٠` instead of `999` beside `١٬٠٠٠`, `fa-IR` draws Persian digits (`۱٬۰۰۰`), and `ar-AE`, `ar-MA`, a bare `ar`, `hi-IN` and `en-*` Latin digits, with the locale's separators (`2,5` and `1.234,50` in German). OPF draws a numbering system only where PowerPoint draws the same digits: Arabic-Indic digits take the Latin comma, period and percent sign as PowerPoint's charts do, a native chart's number formats carry PowerPoint's numeral-shape prefix (`[$-2000000]` Arabic-Indic, `[$-3000000]` Persian, `[$-4000000]` Devanagari, `[$-5000000]` Bengali; removed again on import), and systems PowerPoint does not draw (Thai, Myanmar, ...) are drawn in Latin digits. Numbers PowerPoint draws itself stay Latin in every language: `{{slide.number}}` and `{{deck.slideCount}}` (a live field), and numbered-list markers except Arabic-Indic with a period or a closing parenthesis (PowerPoint's `hindiNumPeriod` and `hindiNumParenR`). Text the author typed is never rewritten. To choose Latin digits, tag the deck or slide with the standard BCP 47 extension `-u-nu-latn` (`"language": "ar-SA-u-nu-latn"`); `-u-nu-arab` chooses Arabic-Indic digits, and `opf/language-tag` warns about a numbering system OPF does not draw. The locale data is a table in core read from `Intl` once (`scripts/build-number-locales.mjs`), never at render time, so every runtime draws the same text. The export no longer fails on generated digits: an `ar-SA` deck whose text has no Arabic (a title "T" and the metric 1000) threw `OPFFontError missing-glyph`; `loadFonts({ scripts: 'auto' })`, `fonts.ensure` and `fonts.pending` now offer the faces of the digits each slide generates. PowerPoint's `lang` is written without the extension (`ar-SA`) and the tag as written comes back on import; a dataset table records the language its numbers were shown in, so its provenance still restores.
