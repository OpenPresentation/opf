Breaking (0.35 layout simplification, step 8; a slide in cells without a layout draws as before): one `region` key for the 3 x 3 cells. A slide without a layout places a block in a cell of its grid with the block's own `region`, the key a block already uses to pin itself to a layout region: `{ "region": "top:start", "text": "..." }` in the slide's `blocks` (a column band `start` ... `start+center+end`, a row band `top` ... `top+middle+bottom`, or rows, a colon, then columns, 48 cells; `ContentPayload.region`'s pattern takes them). The 48 slide keys that named the cells (the promoted regions `"top:start": { ... }`) are removed with no alias. A slide places every block in a cell or none (a block that names none beside one that does is `opf/schema`); blocks that name the same cell stack in it in source order, as a group's blocks would (never an error); two different cells may not overlap, and a block in a cell has no slide edge to bleed to (`placement`, `opf/image-placement-invalid`). On a slide with a layout a cell word names no region of it: `opf/region-unknown`, and the block binds by kind. Validation reports a removed key (`opf/schema` at `/slides/N/<key>`) with what replaced it, no near-miss suggestions, and the safe fix `cells-to-blocks`, which moves every cell key of the slide into a block that names its cell, in reading order of the cells, copying each payload as written (a key written like a cell, such as `left` or `start:top`, names the cell it means; on a slide with a layout the fix is `cells-to-layout-blocks`, safe and marked `changesDrawing`, which keeps the layout and moves the content into blocks without `region` that bind to its regions by kind); a `region` written like a cell but not one (`start:top`, `bottom+middle`, `top:left`) gets the grammar as help and the fix `change-to:<cell>`; `describeFinding` words both. `composeSlide` composes a slide whose blocks name cells exactly as 0.34 composed the same content under the slide keys (the 52 examples, migrated by the fix: 967 slides, every composed field equal) and writes the result's paths as the author's (`slides.N.blocks.I`; the group of a cell that several blocks name keeps the cell's path, `slides.N.top:start`); it ignores a removed key. Core: `promotedRegionKeys` (`@openpresentation/opf/validator`) is `gridCells`, and `@openpresentation/opf/composition` adds `gridCells`, `isGridCell`, `cellBlocks` and `cellsInReadingOrder`; `isPromotedRegionKey` (`@openpresentation/opf/schema`) is removed (no slide key is advanced but `extensions`); `stats` counts `payloads.cells` (root blocks in cells) instead of `payloads.regions`; citations number the blocks of a slide's cells cell by cell in reading order (they numbered the keys in alphabetical order); the convert functions `blocksToRegions`, `regionsToBlocks`, `moveRegion`, `demoteImage`, `splitSlide` and `mergeSlides` work on the blocks' cells (the loss they report is "cell placement"); a Markdown block's `region=top:start` is that block's `region`. Render: `RenderBinding.regionKey` is removed and `contentItems` holds root payloads only (a block in a cell is in `blocks`). PPTX: export stores a block's cell as its `region` pin in the content record (a block named for its path, `slides.N.blocks.I`), and import of a 0.34 file rebuilds its cell keys (the record's `regions` form) as blocks that name the cells, in the order 0.34 walked them, so the records read in that order still find their payloads (on a slide with a layout, without `region`); the pictures-only export reads a slide's cells in reading order for the picture's alternative text. Editor: a slide whose blocks are in cells shows each cell as a virtual container (`#<cell>`, `promoted`), a block moved or pasted into it names the cell, a block inserted among them takes its neighbor's cell, source completions offer the cells only on a slide without a layout, and `isPromotedRegion` is removed. The examples, the gallery example generator, the docs, the skills and the fixtures use the new key; `docs/migrations/0.35.md` lists every change.
