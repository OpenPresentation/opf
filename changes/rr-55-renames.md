RR-55 (breaking, no deprecation; core 0.14.0 and CLI): short verbs that mirror the CLI, and `presentation` for the deck. Old names are deleted, not aliased.
    - **Renamed functions:** `paginatePresentation` is `paginate`, `bundlePresentation` is `bundle`, `formatPresentation` is `format`, `diffPresentations` is `diff`, `mergePresentations` is `merge`, `markdownToOpf` is `fromMarkdown`, `opfToMarkdown` is `toMarkdown`, `createDataContent` is `importData`, `excelNumberFormat` is `toExcelNumberFormat` and `numberFormatFromExcel` is `fromExcelNumberFormat`. `paginateSlide` and the other slide-level and `resolveX`/`layoutX`/`fitX`/`formatX` names stay.
    - **Renamed classes and types:** `PatchError`, `PatchValidationError` and `FormatError` are `OPFPatchError`, `OPFPatchValidationError` and `OPFFormatError`, like the other `OPF*Error` classes. `MarkdownToOpfOptions`/`MarkdownToOpfResult` are `FromMarkdownOptions`/`FromMarkdownResult`, `OpfToMarkdownOptions`/`OpfToMarkdownResult` are `ToMarkdownOptions`/`ToMarkdownResult`, and `DataContentOptions` is `ImportDataOptions`.
    - **`document` is `presentation`:** the Markdown result (`fromMarkdown(...).presentation`), the result of `applyPatchWithInverse` and the `document` option of `convertContent` (`/convert`) now say `presentation`, which is what `paginate`, `bundle` and `resolveVariables` already returned.
    - **The verbs of the CLI are exported from the root:** `import * as opf from "@openpresentation/opf"` has `validate`, `paginate`, `bundle`, `stats`, `diff`, `merge`, `format`, `fromMarkdown`, `toMarkdown`, `applyPatch` and `importData`, with the error classes and result types of those modules; every verb keeps its subpath.
    - **No guards for old option names:** a function ignores an option it does not know (a leftover `fonts: { heading, body }` on `composeSlide`, or a top-level `textMeasurement` on `paginate`), so rename them. `opf/variable-unfilled` is a `format` rule, so `validate(deck, { only: ['format'] })`, `assertValid` and every command that writes a deck still reject a deck with an unfilled required variable.
    - **Unresolved layout, theme and colour scheme ids fall back and never throw:** a slide with no `layout`, or an id no catalog defines, composes with no layout record (automatic composition; a title-only slide is a vertically centred cover); an unknown theme uses `minimal` and an unknown colour scheme `cool-horizon`, reported as `unresolved-layout`, `unresolved-theme` and the new `unresolved-color-scheme`. `paginate` no longer throws `OPFPaginationError` for them and passes the diagnostics to `onDiagnostic`. `resolveSlideContext` also returns `darkBackground`. The `Slide.layout` schema description states the rule.
