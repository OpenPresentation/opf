A PowerPoint export can name the application it is for: `reader: "keynote"` (`opf convert deck.opf.json deck.pptx --reader keynote`, core's `convert` and opf-pptx's `toPptx`) sets `typefaces: "safe"`, static slide numbers (`slideNumbers: "static"`, opf-pptx `slideNumberFields: "static"`) and `smartArt: "shapes"` in one option, each of which Keynote 16.0 showed helping there; `smartArt: "shapes"` made no slide worse across 152 slides. A bare slide number stays a live field. `bodyText: "native"` is not in the set: Keynote lays a body placeholder out wider than OPF's measured boxes (2 slides worse, 4 better), so a caller adds it. The three-option set was not run in Keynote itself; two passes bracket it. An option given beside the reader wins (`--reader keynote --typefaces selected` keeps the deck's faces), and the `pptx/typeface-not-office-safe` note follows the typefaces in effect and now names `--reader keynote`. What it costs a PowerPoint reader of the same file: Arial, Georgia and Courier New replace the deck's faces, slide numbers with words around them are fixed text that PowerPoint does not renumber, and there is no live SmartArt, so it is not a generally safer export. `reader: "powerpoint"` is the default and changes nothing. Any other value is an error (`invalid-option` in core, exit 2 in the CLI, `invalid-reader-option` in opf-pptx), and so is a reader with `as: "images"`; core refuses `reader` on an opf-pptx that predates it (`peer-too-old`). opf-pptx exports `READERS` and `readerOptions(reader)`, which returns the option set.
