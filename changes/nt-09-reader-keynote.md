A PowerPoint export can name the application it is for: `reader: "keynote"` (`opf convert deck.opf.json deck.pptx --reader keynote`, core's `convert` and opf-pptx's `toPptx`) sets `typefaces: "safe"`, static slide numbers (`slideNumbers: "static"`, opf-pptx `slideNumberFields: "static"`), `smartArt: "shapes"` and `bodyText: "native"` in one option, each of which the 0.36.0 Keynote round saw help there; a file exported with the whole set has not been opened in Keynote yet. An option given beside it wins (`--reader keynote --typefaces selected` keeps the deck's faces), and the `pptx/typeface-not-office-safe` note follows the typefaces in effect and now names `--reader keynote`. What it costs a PowerPoint reader of the same file: Arial, Georgia and Courier New replace the deck's faces, slide numbers with words around them are fixed text that PowerPoint does not renumber, there is no live SmartArt, and body paragraphs wrap in the application, so it is not a generally safer export. `reader: "powerpoint"` is the default and changes nothing. Any other value is an error (`invalid-option` in core, exit 2 in the CLI, `invalid-reader-option` in opf-pptx), and so is a reader with `as: "images"`; core refuses `reader` on an opf-pptx that predates it (`peer-too-old`). opf-pptx exports `READERS` and `readerOptions(reader)`, which returns the option set.
