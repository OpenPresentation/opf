SH-13: PlantUML diagrams. A `diagram` takes `syntax: "plantuml"` (the schema's `Diagram.syntax` is now `"mermaid" | "dot" | "plantuml"`) and a Markdown ```` ```plantuml ```` fence is one. OPF reads PlantUML itself (no PlantUML code ships) and draws each kind as the pele family of the same kind: sequence, class and state diagrams as themselves, activity diagrams (the current syntax) and component and deployment diagrams as flowcharts, use case diagrams, mind maps and gantt charts (scheduled by OPF in working days). They are sized, painted in the deck's colors and fonts, previewed and exported as native PowerPoint shapes (SH-07) as that family is, and `fromPptx` reads an unchanged group or picture back as its PlantUML source. Styling (skinparam, themes, colors) is ignored. Every other PlantUML kind (timing, object, network, Salt, JSON, YAML, WBS, ...), the legacy activity syntax and the preprocessor are refused with a finding at their line, never approximated. Core exports `plantumlToMermaid` and `PLANTUML_DIAGRAMS` from `@openpresentation/opf/composition`; the editor offers the `plantuml` fence. A code block in the `plantuml` language is now written to Markdown as an `opf-block`.
