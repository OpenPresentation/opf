The preview draws "đ" (U+0111) correctly in Aptos text (opf#1472). The bundled Intos stand-in has a wrong glyph for it in its regular and bold sans faces (Intos, Intos Display, Intos Narrow): a mirrored d with a bar, which read as a barred b ("rađaju" looked like "rab̄aju"), and a bold d whose bar was drawn as broken blocks. Every Croatian, Bosnian, Serbian (Latin) and Vietnamese text in a default-theme deck was affected; the PowerPoint export was not. The font files stay byte for byte as upstream ships them. A table of known bad glyphs (`GLYPH_DEFECTS`, with the file's SHA-256 and the upstream commit it was seen at) now makes the script-font planner draw that one character with Arimo (then Noto Sans, then Roboto) in the same weight, scaled so it keeps the advance the Intos glyph had. A line measures, wraps and is placed exactly as before, in the SVG, PNG and PDF output and in the editor; only the outline of the letter changes. A new test audits the outlines of every bundled face (stroke letters against their base letters), so a new font with the same defect fails it and a fixed upstream release makes the table entry fail as stale. Italic faces, Intos Serif and the PowerPoint export are unchanged. Intos Serif has no glyph for "ƀ" (U+0180); the existing glyph fallback already draws it with Noto Sans.
