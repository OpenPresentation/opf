SH-12: Graphviz DOT diagrams. A `diagram` takes `syntax: "dot"` (the schema's `Diagram.syntax` is now `"mermaid" | "dot"`) and a Markdown ```` ```dot ```` fence is one. OPF reads the DOT language itself (no Graphviz code ships) and gives the graph to pele's layered layout as a flowchart, so a DOT diagram is sized, painted in the deck's colors and fonts, previewed and exported as native PowerPoint shapes (SH-07) exactly as a flowchart is, and `fromPptx` reads an unchanged group or picture back as its DOT source. `rankdir`, node shapes (mapped to pele's shapes and so to DrawingML presets; the default ellipse is a stadium), edge styles, arrowheads, `dir`, `minlen`, labels and their escapes, records, `strict` and `subgraph cluster_*` groups are drawn; colors, fonts and sizes are the deck's. A graph whose `layout` names another engine (neato, fdp, sfdp, circo, twopi, osage, patchwork), or an HTML table label, is refused with a finding at its line and column, never approximated. Core exports `dotToMermaid`, `DOT_SHAPES` and `DOT_LAYOUT_ENGINES` from `@openpresentation/opf/composition`; the editor offers the `dot` fence. A code block in the `dot` language is now written to Markdown as an `opf-block`.
