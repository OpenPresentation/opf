Explicit chart reference lines are never dropped silently. A bar chart with a `legend`, `dataLabels` or `axisTitles` now draws its `referenceLines` (it drew none and reported nothing). The stacked forms take them too (`stacked-column`, `stacked-bar`, `stacked-line`, `stacked-line-with-markers`, `stacked-area`, on the stack total; PPTX draws them as overlays). A nonempty `referenceLines` on a type without one value axis is the located error `opf/chart-reference-unsupported-type`, which names the property and the supported types; the schema's type condition is gone. The editor's chart-type switch refuses such a switch with `chart-reference-lines-unsupported`, or removes exactly those references with `removeReferenceLines: true` and reports them in `loss`; the built-in control asks first. A reference no longer switches off the emphasis the slide's texts name (a chart with references keeps its series names at regular weight, so a title still cannot move its plot). A reference label that meets another label or a data line is the new warning `opf/chart-label-collision` instead of `opf/text-overflow`. PPTX: a line of no width is written transparent rather than as PowerPoint's hairline, a stacked line chart with references stays stacked, and an unchanged export imports each reference as authored (no explicit defaults, color names kept).
