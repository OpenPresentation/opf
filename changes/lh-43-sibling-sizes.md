LH-43 and LH-17 (layout harvest; output-changing for slides whose body text shrinks): sibling blocks share one fitted size, and a block that shrinks takes a size of a small type scale. The blocks of one kind in a template region now read at one size whatever the region's arrangement (every row of a grid, not only each row; a row; a stacked column), and so do the cells of an automatic grid across its rows; blocks drawn below a layout's grid (`layout-unplaced`) read at the size of the parallel primary regions they continue, while a lone primary region such as a statement's message keeps its own. Sibling metrics share their sizes role by role (value, unit, label, description, delta, trend), through the new `layoutMetric` option `roleSizes`. A sibling that the shared size would make overflow keeps its own fit, as before. A text or list that does not fit at its starting size now steps down the type scale (from `minFontSize` up by a ratio of (28/16)^¼, rounded to whole reference pixels: 16, 18, 21, 24, 28 and 32 px at the default floor) instead of taking any size between, so a deck's fitted body sizes are a few and siblings of different kinds land on the same ones; a block that fits at its starting size keeps it. Per slide and deterministic, so the preview and the PPTX export, which both read the sizes from core, agree. Of the 360 composition goldens, 40 moved and none gained a finding.
