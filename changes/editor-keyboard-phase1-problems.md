Source editor keyboard parity, phase 1 (problems): every finding that has a place in the text is underlined (errors, warnings and notes, the schema and reference findings of JSON too, and the YAML and Markdown findings that carry a range), not only JSON syntax errors, and the squiggle's tooltip says what is wrong, what could come next and how many quick fixes there are, in one message instead of the browser's own. JSON syntax comes from core's recovery analyzer (`@openpresentation/opf/source`): one problem per cause, at the cause, up to five (a key with no value is `design` needs a value, on its own line, with "Add { }" and "Remove "design""), 150 ms after the last key, and held back while a list of keys is open next to it. Schema findings are written in plain words from their keyword and parameters (`titleAlignment` must be left, center or right, but is `middle`. Next: did you mean `center`?; `slids` is not a property of the deck; the required-property row is merged into the rename). The panel rows show `Ln 3, Col 5`, the message, `Next: ...`, the rule and quick fix buttons, in position order, with a shape for the severity; `normalizeFinding` keeps `help`, `location`, `validation`, `suggestions` and `fixes`. Keys: `F8` and `Shift+F8` select the next and previous problem and say it, `Cmd/Ctrl+.` lists the quick fixes at the caret (one undo step each: the syntax repairs, "Change to ...", "Rename to ...", "Remove property", "Add `slides`", "Wrap in a list", "Add a slide", "Remove the first/second", and the patch and focus fixes core ships), `Cmd/Ctrl+Shift+M` moves focus to the panel (arrows, Home, End, Enter, Escape, `Cmd/Ctrl+.`), `Ctrl+M` (`Ctrl+Shift+M` on macOS) toggles Tab leaving the editor, and `Cmd/Ctrl+/` in JSON says that JSON has no comments. Screen readers: a polite live region says the number of suggestions, the selected item with the first sentence of its documentation, `Inserted design`, the snippet's tab stops, the problem under the caret and the problem count once it settles; every suggestion has an accessible name with its kind and position; `aria-description` names the keys. New on the pane: `getProblems()`, `nextProblem()`, `previousProblem()`, `showProblem(index)` and `triggerCompletion()`; on the code editor: `setProblems`, `getProblems`, `triggerQuickFix` and `applyFix`. The "Ln n" of a finding row now also says the column.
