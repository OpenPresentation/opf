`fix()` and `opf fix` keep the safe-fix promise. By default they apply only the safe fixes of the checks that repair the document (new `FIX_REPAIR_CATEGORIES`: format, references, policy, layout); an audit's safe fix (accessibility, content, such as a language tag in the wrong case) waits for `fix(deck, { audits: true })` or `opf fix --audits`, and `opf fix` lists such findings in `fix.audits`. `use-readable-color` (`opf/text-contrast`) is no longer safe: it replaced a color the author wrote, so `fix` never applies it and the editor's Review panel shows its warning. A safe fix that can change how a slide draws says so: new `changesDrawing` on a finding's fix (finding schema), on `FixResult.applied[]`, on `embed()`'s `refreshed[]`, and in `opf fix`'s report (`fix.applied[].changesDrawing`, the count `fix.changesDrawing`, "(changes the drawing)" in `--format text`); marked are `rename-layout` from `agenda-split` and `flow`, `remove:contentDirection`, `remove:chartPrimary` outside a layout record, and `remove:listColumns` other than a list region's `"auto"`, and the Review panel shows them with the same warning. `remove:contentDirection` and `remove:chartPrimary` no longer leave an empty `"design": {}` (slide, deck, theme or layout record). A `focus` fix (`focus-language`) is never applied nor counted; new `isSafePatch(fix)` is the test `fix` uses. The migration note's Hosts section says to repair before drawing (`toSvg` throws `invalid-opf` on an unrepaired 0.34 deck) and to take `embed()`'s document when `refreshed` is non-empty.
