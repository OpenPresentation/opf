SH-16: every live SmartArt has a picture fallback for apps that do not lay SmartArt out. The PPTX export writes each live pyramid or matrix as an `mc:AlternateContent`: the `mc:Choice` is the SmartArt frame as before, requiring `dgm1612` (`http://schemas.microsoft.com/office/drawing/2016/12/diagram`, Office's 2016 SmartArt extensions, which PowerPoint for Microsoft 365 takes), and the `mc:Fallback` is a picture of the same frame, id and name: OPF's preview of that frame (opf-render's SVG of the slide cut to the arrangement and its entries, text as glyph outlines when the export has the fonts handle) as an `asvg:svgBlip` over a PNG at 192 dpi, with the outline as its alt text, one entry a line. The drawing part stays. Without opf-render or an SVG rasterizer (a browser passes `svgRasterizer`) the arrangement is written as native shapes, with `pptx/smartart-unavailable` naming the fallback picture. Import reads the wrapped frame from its `mc:Choice`, and in `full` provenance a fallback picture that survived alone (OPF_SMARTART_V1 with the media keys of its SVG and PNG) imports as the same list on the same layout; a replaced one reports `invalid-smartart-provenance` and imports as a picture. PowerPoint keeps the SmartArt live when it saves the file again, but writes the bare frame and drops the fallback. See `docs/smartart.md`.
