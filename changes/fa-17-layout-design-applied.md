FA-17: a layout record's `design` now applies in full. Every shared key (`titleAlignment`, `contentAlignment`, `contentBox`, `contentDirection`, `chartPrimary`, `imageFill`, `listBullet`) resolves with one merge, per key: the slide's `design`, then the deck's `design`, then the layout record's `design`, then the engine default. Before, composition applied only `contentDirection`, `chartPrimary` and `slideImage.position` from the record, so a layout that set `contentAlignment: center` rendered left unless a host copied the value into `design`. New exports (root and `./composition` entries): `resolveDesignHints`, `DESIGN_HINT_KEYS`, and the types `DesignHints`, `DesignHintKey`, `DesignHintSource`, `ResolvedDesignHints`, `ResolveDesignHintsOptions`. `composeSlide()` returns the effective values as `SlideComposition.design`, which the audit's image-resolution rule, the renderer and the PPTX exporter read instead of re-deriving them. Composition now reads `presentation.design` for `titleAlignment`, `contentAlignment` and `contentBox`, so pagination and the audit no longer pass them. A listBullet `image` without a resolvable logo reports `unresolved-content` at the slide's `layout` reference when the record supplied it. None of the 126 bundled example decks changes (each sets the keys on the deck).
