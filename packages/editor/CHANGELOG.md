# Changelog

## Unreleased

- RR-25: deck-wide find and replace, image crop with a focal point, and the phone and tablet layout. New entry points `/find` (`collectSearchFields`, `findMatches`, `replaceAll` as one undoable change, `replaceMatch`, `planReplace`, `applyTextEdits`: match case, whole word and regular expressions with `$1`, `$<name>` and `$&`; a match inside one rich-text run keeps every run's formatting and a match across runs takes the first matched character's formatting), `/find-panel` (`createFindPanel`, `installFindShortcuts`: Ctrl/Cmd+F, Ctrl/Cmd+H, results that go to the match on the canvas, replace one and replace all with Undo, accessible), `/image-crop` and `/image-cropper` (an in-canvas crop layer with drag handles, aspect lock, a focal point tool, exact numbers, keyboard and touch; Apply is one undoable change that writes the cropped pixels as a new asset because OPF has no crop or focal point field yet, and Restore original goes back). `createCanvasEditor` gains `reveal(path)`, `cropImage(path)`, `cropping` and the `imageTools` option; touch screens get larger selection targets and keyboard-aware editing. The playground gets Find, a Picture section, and a phone and tablet layout with a bottom bar and a bottom sheet. Tests: `test/find-replace.mjs`, `test/image-crop.mjs`, and the browser tests `find-replace-browser`, `image-crop-browser` (including a PPTX export check) and `mobile-browser` (six emulated devices).

- RR-22: autosave and restore. New entry points `/persistence` (`createPersistence`: debounced autosave of the working document and its undo history to IndexedDB, with localStorage as the fallback, an offer to restore a stored copy that differs from the starting document, `markSaved`, `rebase`, the `beforeunload` warning while the document has unsaved changes, and storage adapters) and `/persistence-ui` (a restore prompt and an autosave indicator as plain DOM). The session gains `exportHistory()` and `restoreState({ document, undo, redo })` (one `restore` event; a history that does not replay against the document is refused with `invalid-history`), and `EditorEvent.type` gains `"restore"`. Local only, nothing is sent anywhere; private browsing, blocked or full storage degrade with a visible note. The playground enables it (key `opf-editor-playground`; `globalThis.OPF_EDITOR_HOST.persistence` or `?persist=<key>` to configure, `?persist=0` to turn off) and marks the document saved on Save OPF; the gallery handoff is neither autosaved nor warned about.

- RR-21: slide management. New entry points `/slides` (`addSlide` with a layout choice, `duplicateSlides`, `removeSlides`, `moveSlides`, `moveSlidesBy`, `setHidden`, `setSection`, `addSection`, `renameSection`, `removeSection`, `moveSection`, `listSections`, with `prepare…` dry runs), `/outline` (the outline model and its edits), `/slide-manager` (the slide navigator and the slide sorter grid: selection, drag and drop and Alt+arrow reorder, toolbar and context menu, announcements) and `/outline-view` (the editable outline with promote, demote and move). Every operation is one validated patch and one undo step; sections are the OPF `section` label on consecutive slides and `hidden` is the OPF flag. Session API, document model and PPTX export are unchanged. The playground gains the toolbar, section headers, an Add with layout dialog and Slide, Sorter and Outline views. Split and merge appear in the slide menu when the host passes the RR-26 content actions.

- RR-24: data grid and table and chart row and column operations. New entry points `/data-grid` (`createDataGrid`: a `role="grid"` spreadsheet-like DOM grid for chart inline data and tables with keyboard editing, TSV/CSV paste, TSV copy, a toolbar for row and column operations and a number-format control; `resolveDataGridTarget`, `describeDataGrid`, `gridRangeText`, `gridCellIssues` and the generic `prepare*` and session forms), `/chart-data` (`setChartCells`, `pasteChartText`, insert, delete, move and sort rows and columns, `transposeChart`, `renameChartSeries`, `renameChartCategory`) and `/grid-text` (`parseDelimited`, `toDelimited`, `parseGridNumber`, `formatGridNumber`, `resolveNumberFormat`). `/tables` gains `insertTableRows`, `deleteTableRows`, `moveTableRows`, `insertTableColumns`, `deleteTableColumns`, `moveTableColumns`, `sortTableRows` (stable, typed, empty cells last), `setTableHeader`, `setTableCells` and `pasteTableText` (merged cells grow, shrink and move whole, or the change is refused with the reason; a table style this package wrote stays correct), plus `readTableStyleOfTable` and `applyTableStyleToTable`. Every operation is one validated, undoable patch; an empty chart cell is a gap, never 0; numbers are read in one stated number format ("1,234.56" or "1.234,56") and anything else is refused inline. The playground has an Edit data button (Content tab) that opens the grid over the bottom of the canvas, and keeps a chart or table selected when an operation makes its selected cell vanish. Documented in `docs/data-grid.md`; tests `test/data-grid.mjs` and `test/data-grid-browser.mjs` (`npm run test:data-grid-browser`, in CI).

- RR-29: the Review panel, the editor's face of core's design and accessibility audit (`opf audit`, `@openpresentation/opf/audit`). New entry points: `/review` (headless: `runAudit`, `reviewFindings`, `findingTarget`, `applyReviewFix`, `setReviewAltText`, `markDecorative`, `filterFindings`, `countFindings`; no DOM) and `/review-panel` (`createReviewPanel`). The panel lists the findings with a severity word (never colour alone), the slide and the rule id; goes to the content a finding is about (the slide and the nearest existing field); offers safe quick fixes as single undoable, validated session edits (switch a failing text colour to the readable one, type alt text in the panel, which an `asset:` reference stores on the asset, and mark a picture decorative as an explicit choice); updates live after every edit and Undo; filters by severity and by slide; hides a check and shows it again; and is operable from the keyboard (arrow keys, Home and End move between findings; Escape cancels the alt-text field; focus stays on the finding after a fix). The playground gains a Review tab (its layout notes section is renamed "Layout notes") that audits with the preview's own script-aware text measurement. Needs core after 0.11.4: the modules read core from the namespace and report `audit-unavailable` on an older core. Tests: `test/review.mjs` (model) and `test/review-panel-browser.mjs` (the built playground).

- RR-32: templates and variables. New entry points `/templates` (the headless fill model: `listTemplateFields`, `templateStatus`, `previewTemplate`, `createTemplateFill` with one undoable `apply`, `declareVariable`, `setTemplate`, `insertVariableToken`, `variableToken`, `suggestVariableId`, `fieldTextToValue`) and `/template-panel` (`createTemplatePanel`: typed inputs for text, number, date, color, link, list and image (asset pick or upload), filled and unfilled state, live preview, fill, and token insertion into selected text). The playground gains a **Fill template** dialog (`examples/template-controls.js`). The canvas now draws the document as authored (`renderOptions.variables` defaults to `false`, a renderer option of the same release), so a template's `{{tokens}}` stay visible and an inline edit never overwrites one; hosts that want resolved values pass `variables`. Needs the core release that ships `resolveVariables`; with an older core the new modules load and throw `templates-unavailable`, and documents without variables behave as before. Tests: `test/templates.mjs` (headless) and `test/template-panel-browser.mjs` (the playground in a real browser).

- RR-26: the content conversions move to core and grow. `/block-convert` now calls `@openpresentation/opf/convert` (core, unreleased: this change needs the core release that lists it, so the release-prep PR raises the `@openpresentation/opf` floor): the pairs gain list and table, timeline and table, text and table, table to list, timeline and a set of metric blocks, a group of metric blocks to a table, quote attribution parsing, timeline date parsing, list indentation levels and fenced code with its language and file name (code to text is now lossless through a fence; `fences: "never"` restores the old loss report). `convertBlock` and `prepareBlockConversion` take core's conversion options; `switchDimension(..., { convert: true, conversion })` passes them; `metricGroupForSelection` is new. New entry point `/content-actions`: `shiftListItems` (indent and outdent list items), `groupBlocks`/`ungroupBlock`, `placeBlocksInRegions`/`regionsAsBlocks`/`moveSlideRegion`, `moveImageToDesign`/`moveImageToContent` (slide image, background, watermark and back), `splitSlideByBlocks`, `splitSlideOnOverflow`, `mergeSlides` and `unpaginateSlides`, each with a `prepare...` form, a loss report and one undo step. The design controls panel gains list level buttons, group of metrics, group and ungroup, image destination and a `slide-content` section (blocks to regions and back, design images into the content); each shows what the change would not carry over before it is applied. Slide split and merge are in the playground slide menu (the slide manager's `contentActions` option).

- RR-31: one JSON Patch module. The session's `applyPatch`, `undo`, `redo`, `applyJsonPatch` and `invertJsonPatch` now run on core's `@openpresentation/opf/patch` (the same RFC 6902 implementation `opf edit`, `opf diff` and `opf merge` use) instead of a private copy, and patches may use `move` and `copy` as well as `add`, `replace`, `remove` and `test`. Behavior is otherwise unchanged: one undo step per transaction, the same events (`patch`, `undo`, `redo` with `patches`, `inversePatches` and `redoPatches`), the same `OPFEditorError` codes (core's `PatchError` codes are mapped one to one, and `details.index` names the failing operation), dotted OPF paths and `rejectInvalid`. Pointers are now strict RFC 6901: an invalid escape such as `~2` or an array index with a leading zero is rejected. A move or copy inverse is a remove plus an add, so the inverse of a `move` is two operations. **Requires a core release that contains `@openpresentation/opf/patch`** (the next core release); the core floor in `dependencies` is raised in the release-prep PR, so until then `npm run test:packed` (published dependencies) cannot pass, so CI skips it (feature-detecting the `./patch` export) until that release. New test `test/patch.mjs`.

- RR-06 (gaps): image upload, every background and every header/footer part in the design controls. `/assets` (`applyImageUpload`, `readImageFile`, `checkImageBytes`, `prepareImageAsset`, `setAssetAlt`): a local PNG, JPEG, GIF, WebP or SVG is validated by its bytes and size (default 2 MiB), added to `assets` as a data URI and used by a logo (all 12 variants), organization logo, watermark, slide image, background or zone image in one undo step; `onAddAsset` lets a host store images itself. `/backgrounds` (`setBackground`, `normalizeBackground`, `readBackground`, `PATTERN_PRESETS`): theme slot, solid, linear gradient with ColorRef stops, image with fit and the 54 DrawingML patterns, with validation and removal (`switchDimension(editor, "backgrounds", null)`). `setHeaderFooterZone` validates and exposes every zone part (date and date format, slide number format, organization, socials, section, image) and `designWarnings` reports an organization or social zone with nothing to show. `createDesignControls` gains a `background` section, a one-zone header/footer editor with every part, file pickers and alt text on every image field, and the `onAddAsset` and `maxImageBytes` options.

- RR-18: playground example only (no change to `src/`). At 600px and narrower the page stacks the slide strip above the workspace and lets the document and canvas bars wrap, instead of keeping a 148px slide rail beside a 227px canvas whose header buttons ran off the page (the document scrolled to 560px at 375px wide). The Review panel names a style fallback inside one family by its weight or italic ("Roboto 800: that weight is not available, so Roboto 700 is drawn; wrapping may change.") rather than "Roboto → Roboto · Approximate substitute"; a replacement by a different family keeps its message. `test/playground-base-fonts.mjs` asserts both.

- RR-06: editor dimension switching and editable design options (FF-16 completed). New entry points: `/block-convert` (`convertBlock`, `blockConversionTargets`, `prepareBlockConversion`: text-keeping conversions between text, list, quote, metric, code, timeline, chart and table with a loss report and refusals; `switchDimension(editor, "blocks", kind, { path, convert: true })` uses it, replacement stays the default), `/design-options` (`setDesignOption` for title and content alignment, content direction, primary chart, picture bullets, content box, accent font, logo, organization logo, watermark and slide image; `setLogoVariant`, `setHeaderFooterZone`, `designWarnings`), `/tables` (`setTableStyle`, `mergeTableCells`, `splitTableCell`, `setTableCellStyle`; merging never hides text) and `/design-controls` (`createDesignControls`: the labelled, keyboard-operable panel the playground now mounts in its Design and Content tabs). `/switches` gains `listSwitchOptions`, `compatibleChartTypes` and `currentSwitchValue`. Every change is one undo step. The playground status line no longer stays on "Loading fonts…" after a font-scheme or language change made from a control.

## 0.10.2

- Release 0.10.2 (patch: pointer caret entry and the `textEntry` option; keyboard entry, `beginEdit(path)` and every export are unchanged; no public export removed). Dependencies are unchanged: core floor `@openpresentation/opf` ^0.11.2, optional renderer peer ^0.11.0, development renderer ^0.11.2 and PPTX ^0.11.1. Hosts and tests that called `dblclick()` on a text target and then relied on all text being selected should enter with the keyboard (focus the target, press Enter) or pass `textEntry: "dblclick"`; details below (#48).

- Editor canvas: one click puts the caret where you click. A single press (mouse, pen, or a touch tap) on editable text now enters inline editing at the nearest character boundary, replacing the old hover, click, double-click (select all), click sequence with the PowerPoint / Google Slides convention. Press and drag selects the range from the press to the release point; while editing, a native double-click selects a word and a triple-click a line or paragraph; clicking another text target commits the current edit (an invalid edit still refuses) and enters the new one in the same click. Enter, Space or F2 on a focused target (and `canvas.beginEdit(path)`) still select all text; Escape leaves editing and keeps the box selected. Rich text uses the rich input's own pointer mapping with the same gestures (double-click selects a word, triple-click a paragraph) and never selects all on pointer entry. Images, charts and other non-text targets keep click-to-select and double-click-for-properties. Plain-text carets are resolved from the traced SVG lines (`data-opf-source-*` / `data-opf-text-*`, including tab and other tspan segments) and converted to input offsets, so CRLF sources, tabs, wrapped whitespace and bidi isolate marks map exactly; a line that does not match its traced source falls back to a hidden copy of the positioned textarea. New source file `src/text-pointer.js` (internal; no new package export).
- New `createCanvasEditor` option `textEntry: "click" | "dblclick"` (default `"click"`). `"dblclick"` keeps the old select-then-double-click gesture, but the double-click now also places the caret at the pointer (no select-all). Behaviour change for hosts and tests: `dblclick()` on the default canvas enters editing at the click and then selects the word under the pointer instead of selecting everything; use keyboard entry (focus the target, press Enter) where select-all is expected, or pass `textEntry: "dblclick"`. Playground copy now says "Click to edit".
- New `test/click-entry-browser.mjs` (`npm run test:click-entry-browser`, run in CI and release): titles, a wrapped subtitle with double spaces and a tab, a wrapped bullet, centered and right-aligned titles, footer furniture, a CRLF text, rich text, drag selection, word/paragraph selection, commit-and-enter, invalid-edit refusal, keyboard entry, Escape, images and charts, layout handle drags, `textEntry: "dblclick"`, the textarea fallback and a touch tap. `test/code-browser.mjs`, `test/metric-browser.mjs` and `test/rich-input-browser.mjs` enter with the keyboard where they assert select-all.

Source the author applies is shown byte for byte (JSON escapes such as `\/`, `\u00e9` and `\n`, irregular whitespace, key order), and slide edits rewrite only the tokens that change, so Escape, Undo and Redo restore the exact prior bytes instead of a `JSON.stringify` respelling.
  The internal `src/exact-source.js` (`updateJsonSource`, `createSourceMemory`, `findDuplicateKey`; not a package export) keeps a bounded memory of recently seen documents (64 sources, 8 MB in total, oldest evicted first) and coalesces typing drafts. A remembered source replaces the current one only when both are byte-equal outside the edited nodes, so manual respellings are never reverted. Adding or removing array elements or object keys keeps every untouched sibling token (removal is by tree range, so it also works for inline containers; reordering an array moves the exact element tokens, in one parse, so a move in a 4 MB deck takes about 150 ms); keys named like Object.prototype members (`__proto__`, `constructor`) are ordinary keys; only typing into one string value coalesces intermediate states, every discrete edit stays exactly restorable; the result is always verified to parse to the edited document, and if an in-place edit cannot do that it falls back to indented JSON for that edit. The playground rejects repeated object keys on Apply.
  Limit: a source longer than 2,000,000 characters is not remembered. Edits still work, but restoring an edited value then uses normalized JSON spelling, and the playground says so in the source dialog footer and status line. Covered by `test/exact-source.mjs` (in `npm test`) and `test/playground-source.mjs` (in `npm run test:playground`). The JSON editor entrypoints are unchanged.
