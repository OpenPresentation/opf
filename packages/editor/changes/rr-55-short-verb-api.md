RR-55 (breaking, with core 0.14.0, renderer 0.14.0 and PPTX 0.14.0; old names are deleted, not aliased): the editor uses core's one checker, one Finding format, one slide context and the renderer's one fonts handle.
    - Validation: every edit runs `validate(presentation, { only: ["format"] })` (no layout is built) and `rejectInvalid` follows `valid`. `editor.validation` and the `validation` of every change, event and snapshot are core's `ValidationReport` (`valid`, `findings`, `counts`), not `{ valid, errors, warnings, result }`; `OPFEditorError.issues` holds the error findings. `validateOpfDocument` and the `validate` option of `createEditorSession` are removed. `catalog` and `references` findings (an unknown variable, a missing asset) are no longer part of the per-edit check; the schema inspector lists them as notes.
    - Review panel: it runs core's full `validate(presentation)` once the document has been quiet for `delay` ms (default 300), not per keystroke, and lists the findings grouped by category (format, references, policy, accessibility, layout, content) with their severity. A fix is core's `FindingFix` (`title`, RFC 6902 `patch`), applied as one undoable edit. New optional `review(presentation, { signal, report, validateOptions })` hook returns a `FindingReport` from a hosted reviewer such as pptx.dev; its findings are merged with core's by `Finding.source` and listed in the same panel (`reviewLabel`, `autoReview`, `panel.review()`, `panel.schedule()`). `getAuditOptions` is now `getValidateOptions` (core's `ValidateOptions`: `fonts`, `severity`, `ignore`, ...). `ReviewFinding` is core's `Finding` plus `id`, `dottedPath` and a `slide` that is `null` for the deck; `ReviewReport` is core's `FindingReport` plus `sources`. Removed: `runAudit`, `auditAvailable` and the audit-only types. Added to `/review`: `mergeFindingReports`, `groupFindings`, `sortFindings`, `reviewCategories`. Rule ids are `opf/<rule>`.
    - Slide context: `editor.composeSlide` and `editor.paginateSlide` resolve the slide's canvas, layout, theme, colour scheme and font families with core's `resolveSlideContext` instead of the editor's own copy of that chain (`resolveSlideFonts` is removed; read `resolveSlideContext(presentation, index).options.fontFamilies`). An unknown layout, theme, colour scheme or font-scheme id never throws; `onDiagnostic` hears `unresolved-layout`, `unresolved-theme`, `unresolved-color-scheme` and `unresolved-font-scheme`. A slide with no layout composes with no layout record, as in the renderer and the PowerPoint export.
    - Fonts: `createCanvasEditor(container, { fonts })`, `exportDeck(deck, { fonts })`, `editor.composeSlide(i, { fonts })` and `editor.paginateSlide(i, { fonts })` take the renderer's `loadFonts()` handle (`@openpresentation/opf-render/fonts-browser`). The handle's `pending` and `ensure` are the font gate, so `createFontGate` and the `registry` option of `exportDeck` are removed; `whenFontsReady(fonts, ...)` takes the handle. `renderOptions.textMeasurement` and a top-level `textMeasurement` are not read. The PDF now embeds the registry's faces, script faces included, under the same license rule as the SVG (OFL-1.1, Apache-2.0, MIT or UFL-1.0): a face that fails it is given to neither, reported once as `export-font-license`, and when that leaves the PDF converter no face for some text the export rejects with `export-fonts-unlicensed`; the fonts handle itself is never passed to `svgToPdf`. `splitSlideOnOverflow` and `prepareSplitSlideOnOverflow` take core `paginate` options (`{ fonts }`).
    - Core names: `createDataContent` is `importData`, `PatchError` is `OPFPatchError`, `applyPatchWithInverse(...)` returns `.presentation` (it was `.document`), the `convertContent` option is `{ presentation }` (it was `{ document }`), engine names are imported from `@openpresentation/opf/composition`. Every `typeof core.x === "function"` feature detection is removed (`auditAvailable`, `chartOptionsAvailable`, `numberingAvailable`, `templatesAvailable`, `supportsChartTableData` and the "unavailable" errors with them, and the local `font-defaults.js` copy of core's default font scheme); a missing export now fails at load, and `test/core-features.mjs` fails by name when a linked package lacks one.
    - New `deckStats(editor, options)`: core's `stats` of the open presentation (counts, words, notes coverage, images and alt text, speaking time), neutral facts with no severities.
    - `document` is `presentation` in the editor's own API, as in core and PowerPoint: `editor.presentation` (it was `editor.document`), the `presentation` of every snapshot, change, `prepare...` result, `parseOpfTransfer`/`prepareOpfImport` result and `restoreState` state, the `presentation` option of `createCanvasEditor`, the `presentation` that `onRender`, `onDraft`, `onCommit` and the template panel's `renderPreview` hand over, and the `presentation` of a stored autosave record. The autosave key prefix moves from `opf-editor/v1/` to `opf-editor/v2/` (record version 2), so a copy saved by an earlier version is never read. A DOM `document` option stays: `createTextInput`, `createCatalogSelect`, `installFindShortcuts`, `loadImagePixels` and `cropImagePixels` take `{ document }` for the page's DOM document.
