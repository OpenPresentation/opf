RR-99 (needs core with FA-33): the layout editor, `createLayoutEditor` from `@openpresentation/opf-editor/layout-editor`, a Figma-style GUI for building one layout record (`direction` plus an ordered `regions` list of regions and splits). It is a tool palette (Select V, Split into a row R, Split into a column C, Insert region I, Heading regions T, Hand H or Space, Preview P), a canvas (a 16:9 frame with drag-to-resize dividers that snap and show their ratio, double-click to equalize, drag to reorder or move between splits with drop indicators, Delete that collapses a one-child split, and a context menu with wrap in row or column, unwrap, duplicate, delete and rename), a layers tree (`role="tree"`) and an inspector for the layout, splits and regions (`auto` only in a column, inherited anchors shown as inherited, `accepts` chips). Core validates live (`opf/layout-template` and `opf/layout-region`) and the findings are highlighted on the canvas and in the layers; the editor has its own undo and redo, where one drag is one step; Preview draws sample content with the host's `toSvg` and fonts handle, or a wireframe. The parts are exported separately (`createLayoutToolPalette`, `createLayoutCanvas`, `createLayoutTree`, `createLayoutInspector`, `createLayoutModel`), with `getRecord`, `setRecord`, `onChange`, `saveToDeck(editor)` (through `saveCustomLayout`, which now takes `{ replace: true }` to edit a layout the deck already has) and `applyToSlide(editor, slideIndex)`. The pure tree operations are `@openpresentation/opf-editor/layout-tree`. Keyboard: arrows between siblings, Enter into a split, Esc up, `[` and `]` to reorder, Cmd or Ctrl+D to duplicate, arrows on a divider; touch density uses 40px controls. The playground has a Layouts view that uses it. This replaces `openCustomLayoutEditor` (`/custom-layout-editor`), which is removed with no alias.
