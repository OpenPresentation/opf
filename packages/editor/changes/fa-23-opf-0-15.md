FA-23 (breaking, OPF 0.15): the editor moves onto core 0.15's catalog host API, backgrounds and image blocks.
    - Catalogs come from the host. `createEditorSession(doc, { catalogs })` registers a `Catalog[]` (for example `defaultCatalog` from `@openpresentation/opf/catalog`; the library itself imports no catalog data), `editor.catalogs` and `editor.setCatalogs()` read and replace it, and `mergeCatalogs` is the one merge: the same list reaches core resolution and validation, every picker, the canvas renderer, PDF/PNG/SVG export and the playground's PPTX export. `catalogSources` and the bundled-catalog fallback are removed.
    - Pickers list core's `catalogRecords` and write the reference it gives (`id` or `name:id`). Languages are BCP-47 tags from core's `LANGUAGES`; chart types and social platforms are core's `CHART_TYPES` and `SOCIAL_PLATFORMS`, labelled from the host's display metadata (`vocabularies`, the shape of `catalogDisplay`).
    - A theme switch no longer copies the theme's colour scheme, font scheme, background and size into the design: it removes those overrides at the switched scope so the theme's own apply (on a slide whose deck sets one, the theme's value is written on the slide).
    - Saving, copying (`serializeOpfTransfer`) and `exportDeck` embed every referenced record with core's `embed` (`prepareSave`, `saveDocument`), so a saved document renders the same with no catalog registered. Inserting pasted slides uses core's `copySlides` instead of renaming records to `import-<id>`, and `prepareOpfImport` returns the `renamed` records and `addedGroups` so the host can tell the user.
    - New explicit "Update from catalog": `checkCatalogUpdates` lists the embedded records whose catalog record changed and `applyCatalogUpdate` applies only the approved ones as one undoable step; the design panel's new `catalog` section shows them with the `opf/unresolved-reference` and `opf/undeclared-catalog` findings (`referenceFindings`). Each edit is checked with the `format` category plus the two catalog reference rules, against the session's catalogs.
    - Editing a record that lives under `catalogs.default` or a named group (a layout, theme, colour or font scheme) forks it into `catalogs.custom` as `<id>-custom` (or a given id): every reference follows, the original is dropped, the fork and the edit are one undo step, and the change carries `forked` and a `notice` that the record no longer receives catalog updates. `moveToCustom` does the same on request (core's `moveToCustom`) and is offered for `opf/catalog-record-not-in-source`. A host catalogs list that is not catalogs throws `invalid-catalogs`. `createCanvasEditor`'s `catalogs` option is now declared.
    - Backgrounds use the flat image form `{ type: "image", src, alt, fit, focus, opacity, overlay }` with the fits cover, contain, stretch and tile, and the image-source shorthand (`asset:`, `https://`, `data:`, `./`, `../`). New `/image-options` (`setImageTreatment`, `readImageTreatments`) and the panel's `image` section set an image block's fit, focus, shape, corner radius, border, opacity, recolor, overlay, aspect ratio and placement (edge, size, inset); the `image-treatments` switch takes those fields for an image block. `design.imageFit` is the default fit design option.
    - Removed: the `slideImage` design option and panel section, `design.imageFill`, the slide-image targets of `moveImageToDesign` and `IMAGE_DESTINATIONS`, the slide-image crop, and every image-bleed path. The gallery loader embeds an item's record under its catalog group and no longer fetches missing layout records.
