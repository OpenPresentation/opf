# Changelog

## Unreleased

## 0.14.0 (2026-10-07)

- FA-09 (additive schema; lockstep with the renderer, PPTX and editor): `Chart.alt`, the text alternative for a chart (what the data shows, not "a chart"). `""` marks a chart decorative, like an empty `Asset.alt`. The preview exposes it as the chart's accessible name, the PowerPoint export writes it as the chart frame's `descr` and import reads it back. Core: `validate`'s `opf/chart-text-alternative` reads `chart.alt` first (a non-blank alt passes; without alt, text beside the chart still passes; `alt: ""` is reported as info so the choice is reviewed), its quick fix focuses the `alt` field, and `opf/poor-alt-text` also checks chart alt text (a bare "chart", a URL, a leading "chart of", over 250 characters). The Markdown chart fence takes it as ` ```chart column alt="..." ` (`markdown/chart-attributes` for an unknown attribute); a chart with `alt` converts to and from Markdown natively.
- FA-10: `title`, `subtitle`, `tag` and `quote.text` accept `string | TextRun[]` (the same `TextRun`, including `color`, links, `cite` and `footnote`), so one word of an action title can carry the accent color and a headline claim or a quote can carry a citation marker. A string is unchanged byte for byte. `composeSlide` fits a `TextRun[]` heading through the rich-text layouter (`RichTextFit` on the item), `layoutQuote` fits a rich body (`QuoteTextPart.runs`, `fit` may be a `RichTextFit`; `QuoteLayoutOptions.citationMarker`), and heading markers are numbered before the body (tag, title, subtitle, then regions, blocks and the root payload). `var:<id>` keeps a rich text variable's runs in a heading, `validate` checks contrast per heading and quote run, pagination slices a rich quote, and Markdown keeps inline formatting in `#`, `##` and quote text both ways (the `formatting-dropped` warning now covers only a quote's attribution and source).
- RR-56: OPF as YAML. Core `@openpresentation/opf/yaml`: `fromYaml(text, { aliases, validate })` reads a deck written as strict, JSON-compatible YAML 1.2 (one document, a mapping at the root, no custom tags, duplicate keys, non-string keys or non-finite numbers; anchors, aliases and merge keys only with `aliases: true`, capped at 100 aliases) and returns the deck and its `validate` report, `{ presentation, valid, findings, counts, schemaValid, checks }`, whose findings (`yaml/...` for syntax and dialect errors, `opf/...` for the `validate` findings; `validate` options pick the rules) carry the offset, line and column of the YAML; `toYaml(presentation, { schemaComment })` writes canonical YAML (schema key order, two-space block style, no folding, ambiguous strings such as `"yes"` and `"2026-10-01"` quoted) that is read back before it is returned, and throws `OPFYamlError` for an invalid deck; `parseYamlData`, `scanYamlComments` and `YAML_SCHEMA_URL` complete it. CLI: `opf from-yaml` and `opf to-yaml`; every command that reads a deck or patch reads a file ending `.yaml`/`.yml` (stdin and other names follow the global `--input-format <json|yaml>`, default JSON; a YAML error exits 2 with line and column, and `opf validate` reports it as a `yaml/...` finding with exit 1), and every command that writes a deck writes YAML for an output ending `.yaml`/`.yml` or with `--format yaml` (otherwise the format that was read). Commands that rewrite a YAML file do not preserve comments and print a warning on stderr. See [docs/yaml.md](docs/yaml.md).
- FA-02 (breaking, pre-v1, no aliases): a narrative is a plan and lives in the catalog; the deck holds a pointer. The root `narrative` is a plain string (a catalog id, an HTTPS URL or a `pkg:` reference) and the `Narrative` and `NarrativeBeat` definitions are removed from `opf.schema.json`; a custom narrative is a record in `catalogs.narratives.records`. `slides[].beat` keeps the slide-to-beat link. In the narrative record schema, `durationRange { minMinutes, maxMinutes }` becomes `duration { min, max }` (minutes), a beat's `slideType` becomes `type` (the `Slide.type` values: text, list, image, video, chart, table, code, metric, quote, timeline; `shape` is gone), `layoutHint` becomes `layout`, and `slideCount` is removed (one beat is one slide). All 48 bundled records and the example decks are migrated, and `bundle` follows a beat's `layout`. New `validate` findings: a warning about a `slides[].beat` id the resolved narrative does not define (`opf/unknown-beat`), about a root `duration` outside the narrative's `duration` range (`opf/duration-outside-narrative`) and about an inline record whose `duration.min` exceeds `duration.max` (`opf/narrative-duration-range`), and `opf/unused-beat` (content, info) for a beat no slide references; `opf/unknown-beat` is a `references` finding and the duration findings are `content` findings. `check:spec` rejects an inverted range in a bundled record. The `thoughtCues` description no longer claims they reach presenter notes, and the root `duration` description names its real readers (the opf-render presenter timer and `validate`).
- FA-03 (breaking catalog and schema change, pre-v1, no aliases; needs a minor bump): the chart-type and audience catalogs are clean. The 50 deprecated chart-type records and the 6 deprecated plural audience records are deleted, so the bundled catalog holds no deprecated record and a retired id (`clustered-column`, `sparkline`, `dot-plot`, `australia`, `executives`, ...) is an `unknown <kind> catalog id` warning. The `deprecation` field and the `opf/deprecated-catalog-id` warning of `validate` stay for after v1.
    - **Ids:** every active chart-type id loses its `-3x` suffix: `stacked-column`, `stacked-bar`, `stacked-line`, `stacked-line-with-markers`, `stacked-area`, `100pct-stacked-column`, `100pct-stacked-bar` and `100pct-stacked-area`. There is no alias for the old ids. The bundled examples, `spec/reference/engine-defaults.json` and `chartOptionTarget` use the new ids (`chartOptionTarget` no longer resolves deprecated ids).
    - **Chart-type record shape:** `name` is now the human display name (`Stacked Column`, the old `label`); `label` is removed. `slideNumber` is removed, and so are the template-workbook fields no engine reads: `workbookRange`, `columns`, `dataColumns` (with its `position`), `helperColumns`, `sampleData`, `categories`, `seriesGroups` and `useSecondaryCategories` (and the `ChartDataColumn` and `ChartSampleData` definitions). `series` and `complexity` stay: the editor's chart-type picker reads both. pptx.gallery keeps its own copy of the workbook fields under `x-gallery`.
    - **Validate:** the `opf/chart-color-only` rule skips only the chart types that exist (`histogram`, `box`, `pareto`, `waterfall`, `world`, `map`), not the deleted aliases.
    - **Sync waiver:** `scripts/sync-gallery-catalog.mjs --allow-removed <kind>:<id>[,<id>...]` is the explicit, per-id waiver of the "snapshot never loses an id" rule for removals decided on purpose; see [docs/default-catalog.md](docs/default-catalog.md).
- FA-07 (breaking, pre-v1: removed outright, no aliases; format audit, lockstep with the renderer, PPTX and editor): validation tightening and dead keys. Every description now states what core, opf-render and opf-pptx do.
    - **Tighter validation:** color-scheme slots (`accent1`-`accent6`, `dark1/2`, `light1/2`, `hyperlink`, `followedHyperlink`) and roles (`primary`, `secondary`, `accent`, `background`, `surface`, `text`, `textSecondary`) are `HexColor`, inline and in the color-scheme record schema; `SolidBackground.color`, gradient stop colors and pattern `foregroundColor`/`backgroundColor` are `ColorRef` (a name or `var:` reference there now warns when the variable is undeclared, and `validate`'s contrast rules resolve them like the preview); `TextRun.link` matches `^(https?://|mailto:|tel:)\S+$`; a gradient needs at least two stops; `Watermark` requires `src` (the object form keeps `opacity` required) and its description states the fixed frame and the default opacity; `slides[].design` cannot set `dimensions` (new `SlideDesign` definition), and a slide-level theme whose dimensions differ from the deck's is the new `validate` warning `opf/slide-theme-dimensions` (category `references`).
    - **Root `audience`** also accepts one inline Audience object, like `purpose` and `tone`; `validate` and `bundle` handle it.
    - **Removed:** `ColorScheme.custom`, `Asset.format` (use `mediaType`), the `ChartDataSource` form of `chart.data` (`src`/`sheet`/`range`/`columns`) with its `chart-data-source-unresolved` warning and `data-not-inline` reason (`data.source` provenance stays), and the `Font` definition: `FontScheme.heading`/`body`/`accent`/`code` and the font-scheme record's `code` are family-name strings.
    - **Renamed and extended:** `FontScheme.app` is `powerpoint | google-slides` (all 89 font-scheme records migrated; `resolveScriptFonts({ app })` takes the same values); `FontScheme.languageFamily` also accepts `eastAsian` (same as `ea`) and `complexScript` (same as `cs`); core reads both through the new root export `normalizeLanguageFamily(value)`.
    - **True descriptions:** `FontScheme.code` names code blocks only; `CatalogEntry.source` and `CatalogSource` say engines never fetch and the host supplies a `catalogSources` map; `Slide.video` and `ContentPayload.video` say engines draw a placeholder and native playback is out of scope.
    - **Catalog snapshot:** `font-schemes` is `subset` in `spec/catalogs/manifest.json` until pptx.gallery publishes the same records (the mirrored-kind hash guard cannot hold a core-first change).
- FA-08 (output-changing): `opf render` and `opf export` skip slides marked `hidden: true` when they write per-slide SVG or PNG files, a zip or a PDF, and keep them with the new `--include-hidden` flag (slides named with `--slides` are always written; the PPTX keeps hidden slides as hidden slides; the report lists `skippedHidden`). Output files are named by the deck's root `filename` (a trailing .pptx, .pdf, .png or .svg is dropped), else its slugified `name`, else the input file's stem, as opf-editor names its downloads, so `deck.opf.json` with the name "Q4 Review" now writes `Q4-Review.pdf`. The `hidden` and `filename` descriptions in `opf.schema.json` now state this behavior.
- RR-55 part A3 (breaking, no aliases; lockstep with the renderer, PPTX and editor later): `stats`, `resolveSlideContext`, the `fonts` handle, and a smaller package root. Guide: [docs/stats.md](docs/stats.md).
    - **New `stats(presentation, options?)` and `opf stats <file|-> [--format json|text] [--per-slide]`:** neutral, structural facts about a deck, never severities or thresholds: deck metadata and references, people, slides (hidden, sections, layouts), payload kinds, words in content and in notes, notes coverage, images (alt, decorative, missing alt, logos, watermarks, backgrounds), charts, tables, datasets and their sources, citations, variables, assets (embedded, files, remote, registry), header and footer, fonts, colour variables, and an estimated speaking time (130 wpm, labelled `estimate`). It does not compose, measure or validate, so it needs no fonts and works on a deck that fails validation; the 126 bundled examples take 18 ms in total (0.14 ms each) against 46 ms for `validate(deck, { only: ['format'] })`. Output is deterministic with a stable key order.
    - **New `resolveSlideContext(presentation, index, { fonts?, catalogs?, slideNumber?, slideCount?, date? })`:** one slide's canvas, layout, theme and font families (slide design, then deck design, then theme, then the default font scheme) as the `ComposeSlideOptions` that `composeSlide` takes, plus `diagnostics` (`unresolved-font-scheme`, `unresolved-layout`, `unresolved-theme`, `unresolved-color-scheme`) and the records it resolved from. Core pagination and the layout checks of `validate` use it instead of two hand-written copies of the chain.
    - **Breaking, `ComposeSlideOptions.fonts` is now `fontFamilies`** (`{ heading, body, code, accent? }`), and so is the `fonts` option of `layoutQuote`, `layoutMetric`, `layoutCode` and `layoutTimeline`, which frees `fonts` for the shared fonts handle.
    - **Breaking, deck-level verbs take `{ fonts }`:** `paginate` and `paginateSlide` read `fonts.textMeasurement` (the new structural `Fonts` type: at least `{ textMeasurement? }`; the renderer's richer handle extends it) and no longer read a top-level `textMeasurement`. `docs/quickstart.md` passed `fonts` to `paginate`, where it was ignored; it now shows `{ fonts }`. The `slideOptions` hook of `paginate` is removed: `resolveSlideContext` supersedes it and no package used it.
    - **Breaking, the package root keeps app-level names only:** the layout engine (`composeSlide`, `resolveCanvasDimensions`, `fitText`/`fitList`/`fitRichText`, `layoutX`, `resolveFontFamilies`, `resolveFontSchemeReference`, `DEFAULT_FONT_SCHEME`, `OPFCompositionError`, numbering, footnotes/citations/captions, colour (`colorContrast`, `resolveColorRef`, `normalizeHexColor`, ...), code syntax, metric trend, pattern fills, chart options, script fonts and text direction) is exported from `@openpresentation/opf/composition` only, and the symbol-font tables from `@openpresentation/opf/symbol-font-encodings` only. The chart, table and dataset helpers (`chartNumber`, `formatDataNumber`, `resolveChartData`, `inlineDatasets`, ...), font policy, variables, catalogs, schemas, pagination and bundling stay at the root. `/composition` gains `normalizeHexColor`, `resolveColorRef`, `resolveScriptFonts`, `resolveSlideDirection`, `scriptFontRole`, the code-syntax, metric-trend and pattern-fill names. A host that feature-detects an engine name on the root (`typeof core.resolveScriptFonts === "function"`) must import `/composition`, or it silently loses the feature.
    - **CLI:** `opf render --paginate` passes the loaded fonts as `{ fonts }`.
- RR-55 (breaking, no compatibility path): `opf render`, `opf export` and `opf import` use the 0.14 APIs of the optional peers, and their ranges are `^0.14.0` (`@openpresentation/opf-render` and `@openpresentation/opf-pptx`). A 0.13 peer exits 2 with `peer-too-old` and the install command.
    - **One fonts handle:** fonts load once with `loadFonts({ pack: "office", substitutionPolicy: "visual", scripts: "auto", presentation, faces })` from `@openpresentation/opf-render/fonts-node` (it replaces `prepareNodeFonts`) and the handle goes as `{ fonts }` to `paginate`, `renderSlideSvg`, `svgToPng`, `svgToPdf` and `toPptx`. The report's `fonts` summary (`substitutions`, `scripts`, `userFonts`) is unchanged.
    - **Per-slide SVG:** each selected slide is drawn with `renderSlideSvg(presentation, index, { fonts })`; hidden-slide handling, file numbers and the `--svg-fonts` modes are unchanged.
    - **PDF:** `--pdf-mode` defaults to `vector` and `vector` needs no probe, so `pdf.vectorSupported` is removed from the report (`pdf.mode` stays).
    - **Import:** `--signals` reads `{ presentation, signals }` from `fromPptx(bytes, { signals: true })`, and the report's `signals.version` is the version the signals carry. A finding list on a thrown peer error (`OPFRenderError`, `OPFPptxError`, `OPFValidationError`) is reported as those findings.
- RR-55 (breaking, no deprecation; core 0.14.0 and CLI): short verbs that mirror the CLI, and `presentation` for the deck. Old names are deleted, not aliased.
    - **Renamed functions:** `paginatePresentation` is `paginate`, `bundlePresentation` is `bundle`, `formatPresentation` is `format`, `diffPresentations` is `diff`, `mergePresentations` is `merge`, `markdownToOpf` is `fromMarkdown`, `opfToMarkdown` is `toMarkdown`, `createDataContent` is `importData`, `excelNumberFormat` is `toExcelNumberFormat` and `numberFormatFromExcel` is `fromExcelNumberFormat`. `paginateSlide` and the other slide-level and `resolveX`/`layoutX`/`fitX`/`formatX` names stay.
    - **Renamed classes and types:** `PatchError`, `PatchValidationError` and `FormatError` are `OPFPatchError`, `OPFPatchValidationError` and `OPFFormatError`, like the other `OPF*Error` classes. `MarkdownToOpfOptions`/`MarkdownToOpfResult` are `FromMarkdownOptions`/`FromMarkdownResult`, `OpfToMarkdownOptions`/`OpfToMarkdownResult` are `ToMarkdownOptions`/`ToMarkdownResult`, and `DataContentOptions` is `ImportDataOptions`.
    - **`document` is `presentation`:** the Markdown result (`fromMarkdown(...).presentation`), the result of `applyPatchWithInverse` and the `document` option of `convertContent` (`/convert`) now say `presentation`, which is what `paginate`, `bundle` and `resolveVariables` already returned.
    - **The verbs of the CLI are exported from the root:** `import * as opf from "@openpresentation/opf"` has `validate`, `paginate`, `bundle`, `stats`, `diff`, `merge`, `format`, `fromMarkdown`, `toMarkdown`, `applyPatch` and `importData`, with the error classes and result types of those modules; every verb keeps its subpath.
    - **No guards for old option names:** a function ignores an option it does not know (a leftover `fonts: { heading, body }` on `composeSlide`, or a top-level `textMeasurement` on `paginate`), so rename them. `opf/variable-unfilled` is a `format` rule, so `validate(deck, { only: ['format'] })`, `assertValid` and every command that writes a deck still reject a deck with an unfilled required variable.
    - **Unresolved layout, theme and colour scheme ids fall back and never throw:** a slide with no `layout`, or an id no catalog defines, composes with no layout record (automatic composition; a title-only slide is a vertically centred cover); an unknown theme uses `minimal` and an unknown colour scheme `cool-horizon`, reported as `unresolved-layout`, `unresolved-theme` and the new `unresolved-color-scheme`. `paginate` no longer throws `OPFPaginationError` for them and passes the diagnostics to `onDiagnostic`. `resolveSlideContext` also returns `darkBackground`. The `Slide.layout` schema description states the rule.
- RR-55 (breaking, no deprecation; core 0.14.0 and CLI): one checker. `validate(input, options?)` replaces `validatePresentation`, `lintSource`, `lintPresentation`, `auditSource` and `auditPresentation`, and `assertValid(presentation)` (an assertion that narrows to `Presentation`, throwing `OPFValidationError` with the `report`) replaces `assertValidPresentation`; the generic `validate(value, kind)` is internal, `validateCatalogRecord` stays and returns a report. The input is a parsed presentation or strict JSON text (line and column, duplicate keys; YAML and Markdown are never sniffed). The report is `{ valid, findings, counts, schemaValid, checks }` with `Finding`, `FindingReport` and `ValidationReport` types and the published `spec/schemas/finding.schema.json` (RFC 6902 `fixes`); findings have a stable `opf/<rule>` id, a severity and one of six categories (`format`, `references`, `policy`, `accessibility`, `layout`, `content`). `valid` means no error finding, and only `format`, `references` and `policy` findings can be errors by default; a missing `asset:` reference now makes a deck invalid. `only`, `ignore` (rule ids or categories), `severity`, `ignorePaths`, `catalogs`, `contracts`, `thresholds`, `fonts` (`textMeasurement`), `template` and `values` are the options; composition is lazy, so `{ only: ['format'] }` builds no layout and costs what `validatePresentation` cost. Rules: the 21 objective accessibility, layout and content rules stay (ids `audit/<x>` become `opf/<x>`); `font-family-count`, `slide-word-count`, `title-position` and `small-cell` and their thresholds are deleted; `unfilled-variable` and `variable-unfilled` merge into `opf/variable-unfilled`, a `format` rule (an error in a deck that is not a template, a warning in a template), so the format check and every write command still reject a deck with an unfilled required variable; an authored `overflow: "error"` is a warning; `validationRules`, `findValidationRule` and `DEFAULT_VALIDATION_THRESHOLDS` replace the audit equivalents. The `./lint` and `./audit` subpaths are removed. CLI: `opf validate` is the only checker (`--only`, `--ignore`, `--fail-on <error|warning|info>`, `--format json|text`, `--list-rules`, `--config`); `opf lint` and `opf audit` are removed; `--strict` is replaced by `--fail-on` on every command; write, render, export and import commands check `format` and `references` and report `findings`; invalid JSON is an invalid document (exit 1). Markdown results carry `findings` (`Finding & { location }`) and take `validate?: boolean | ValidateOptions`. Guide: [docs/validate.md](docs/validate.md).
- FA-08: deck-named CLI output files strip control characters with `\p{Cc}` (lint-clean; also DEL and C1 controls) instead of a `\u0000-\u001f` range. The published-packages matrix runs the font-switch harness and fixture of the published core's release tag, so an unreleased catalog shape in the checkout does not fail it.

## 0.11.0 (2026-10-06)

- RR-54 (additive schema plus one behaviour change; lockstep with the renderer, PPTX and editor later): chart and table data. Contract: [docs/chart-table-data.md](docs/chart-table-data.md).
    - **Behaviour change (strict chart numbers):** core `chartNumber` is the one rule for chart values: a finite number, or a trimmed string in strict decimal syntax (`"12"`, `"-3.5"`, `"1e6"`). Anything else (`"12%"`, `"$5"`, `"(5)"`, `"1,234"`, `"Q1"`, booleans) is a gap and a `chart-value-not-numeric` validator warning, never a guessed value. Once the renderer and PPTX adopt it, a deck whose chart cells hold `"12%"` or `"$5"` previews and exports a gap where the exporter used to strip the characters and write 12 or 5. Data import (`createDataContent`, `opf import-data`) already used this rule and now calls `chartNumber`.
    - **Schema:** `NumberFormat` (the `NumberVariable.format` syntax, now shared by it); `DataColumn` (`{ name, format }`) wherever a chart, dataset or table column is a string; `StyledTableCell.format` (a body cell's own format wins over its column's); `ChartData.source` and `Dataset.source` provenance (`DataSourceRef`: `src`, `sheet`, `range`, `fields`, `retrieved`, `description`), which engines never read; top-level `datasets` with `{ "dataset": "<id>", "fields"? }` as the third `chart.data` branch and as a dataset-backed table form (`dataset`, `fields`, no `rows`/`columns`); `chart.mapping` (`category`, `x`, `series` by column name). A document that uses none of them validates as before; `pnpm check:breaking` reports none.
    - **Core API** (`@openpresentation/opf` and `@openpresentation/opf/data`): `chartNumber`, `formatDataNumber`, `numberFormatError`, `excelNumberFormat` and `numberFormatFromExcel` (round-trip every NumberFormat through an Excel format code; literal text is quoted as one run, so `0.0 m/s` is written `0.0 "m/s"` and never leaves `/`, Excel's fraction bar, bare), `inlineDatasets`, `inlineTableData`, `inlineChartData`, `resolveChartData` (the positional `[category, (x,) ...series]` table after datasets, fields and mapping, with `hasX`; an XY chart has an X column only with three or more columns, as both engines plot today), `resolveTableData`, `tableCellDisplayValue`, `datasetDiagnostics`, `unusedDatasets`, `isXYChartType`, `isDatasetRef`, and the `DataDiagnostic` and data types.
    - **Migration help:** `suggestChartNumberFix(chart, document?, { path?, column? })` returns, for a chart value column whose text cells share one display style (`"12%"`, `"$1,234"`, `"1,234.5"`), the JSON Patch that stores the numbers and gives the column the NumberFormat that shows the same text; lint attaches it as `fixes` to each `opf/chart-value-not-numeric` warning of that column (`LintDiagnostic.fixes`, the audit fix shape). Mixed styles, `(5)`, `1.234,5` and anything the format would show differently get no fix.
    - **Validation and lint:** errors `dataset-unknown`, `dataset-field-unknown`, `data-column-duplicate`, `chart-mapping-unknown-column` and `number-format-invalid`; warnings `chart-value-not-numeric`, `chart-data-source-unresolved` (a `ChartDataSource`, which no engine loads, [opf#240](https://github.com/OpenPresentation/opf/issues/240) descoped) and `chart-mapping-adapted`; lint keeps them as `opf/<code>` and adds the warning `opf/unused-dataset`. The bundled examples that show the `ChartDataSource` form keep it and carry the new advisory.
    - **Core integration:** `composeSlide`, `layoutTable` (which measures formatted cell text and reports it as the cell `value`) and pagination accept dataset-backed tables and charts; conversions, Markdown, format, diff and the audit keep or read the new fields; `resolveVariables` fills dataset rows.
    - **CLI:** `opf import-data --dataset <id>` writes the imported data into `datasets.<id>` (with the file as its `source`; a re-import keeps the format of each column whose name is unchanged) and references it from the new table or chart.

## 0.10.1 (2026-10-06)

- RR-20 (install fix, no API or output change): `engines.node` is now the open-ended `>=22` instead of `24.x`. npm's install picker skips a version whose `engines.node` does not match the running Node and silently installs the newest one that does, so on Node 26 (current) or Node 22 `npm i @openpresentation/cli @openpresentation/opf-render @openpresentation/opf-pptx` installed the CLI, renderer and PPTX 0.7.0 with core 0.9.0 (no `export` or `render` command) instead of the latest release. The test suite and the packed installs pass on Node 22, 24 and 26, and CI now runs them on Node 22 and 26 next to Node 24 (the development runtime). A new check, `pnpm check:engines-range`, fails on a closed `engines.node` in any package.json, on a lockfile entry (the published-matrix consumer included) for a release after this fix that still declares one, and on a workflow Node version below the range.
