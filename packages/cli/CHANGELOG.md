## 0.18.0 (2026-10-10)

- RR-75 (OPF 0.18): `opf doctor`, a multi-file `opf validate`, examples, and errors that state the fix.
    - **`opf doctor [deck]`** reports, per format (json, yaml, md, svg, png, pdf, pdf-raster, pptx, pptx-import), whether this install can write it and what it misses, and prints one command that installs it all. It loads nothing: it finds the packages where the engine looks (opf-render's fonts and converters from opf-render's install) and checks their versions. With a deck, a PDF needs sharp only when the deck has pictures. JSON by default, `--format text` for people. A conversion that misses a peer exits 2 with the same one command in `install` and in the message.
    - **Install commands match the package manager** in `npm_config_user_agent` (npm, pnpm, yarn, bun) and the way the CLI is installed (global, a project, or an npx run).
    - **`opf validate` takes several files, folders and `-`**: a folder's `*.opf.json`, `*.opf.yaml`, `*.opf.yml` and `*.opf.md`, sorted, skipping `node_modules` and dot folders. One input keeps its report (now with `command`, `ok`, `input` and `outputs`); several give `{ command, ok, files, counts }`. The exit status is the worst over every file. `--format github` prints `::error`/`::warning`/`::notice` workflow annotations with the file, line and column.
    - **`opf create --example <slug>`** copies one of core's bundled example decks, and **`opf catalog examples [slug]`** lists them (`opf catalogs` counts them).
    - **Errors that state the fix:** a missing or extra argument names it and prints the command's usage (no more "Incorrect arguments"); an unknown command, option, value, catalog, id, schema or example suggests the nearest one ("Did you mean --check?"); every command has its own `--help`, `-h` and `opf help <command>`; `--name=value` works for every value option.
- RR-70 (breaking, OPF 0.18): one import for every runtime. `import * as opf from "@openpresentation/opf"` works in Node, Bun, Deno, browsers and workers through conditional exports on the root. The `node`, `bun` and `deno` conditions get the full build: core plus `open`, `save` and `convert`, whose file engine loads on the first call. The `browser`, `worker`, `workerd` and `default` conditions get a browser-safe build with the same names. There, `open`, `save` and `convert` (the in-memory `convert(deck, { format })` too, for now) reject with `OPFApiError` code `node-only`, and the message names the browser-safe alternative. Both builds share one type surface, `dist/index.d.ts`, which needs no Node types.
    - **Removed:** the `@openpresentation/opf/node` subpath, with no alias. Import `@openpresentation/opf` instead. The names are the same except `defaultCatalog`, which stays at `@openpresentation/opf/catalog`; `open`, `save` and `convert` still use the default catalog when no `catalogs` are passed.
    - **`defaultCatalog` is not in the root import.** `@openpresentation/opf/node` re-exported it; the root import carries no catalog data (FA-21), so it stays only at its own subpath. Migration, one line: `import { defaultCatalog } from "@openpresentation/opf/catalog";`. You rarely need it: `open`, `save` and `convert` default to it when no `catalogs` are passed.
    - **Removed:** the CLI-internal `@openpresentation/opf/node/engine`. The opf CLI now imports `@openpresentation/opf/internal/engine`, which is exported under the `node` condition only and is not an application API.
    - **Moved to the root:** `OPFApiError`, `OPFExportError` and `OPFImportError` are browser-safe and exported by both builds. `parseSlideSelection(selection, total, label?)` is new at the root. It reads `3`, `[1, 3]`, `"1,3-5"`, `"2-"` and `"-3"` (one-based) and throws `OPFApiError` `invalid-option` or `no-slides`. `convert`'s `slides` option also takes a single slide number.
    - **Bundlers:** a bundler that sets no runtime condition gets the browser-safe build (`default`). A Node bundle should set the `node` condition.
    - **Checks:** `check:browser-safe` bundles the root for the browser, worker and default conditions and asserts that each reaches the browser build and that its file functions throw `node-only`. `check:breaking` now also reports removed package exports.
- RR-73 (breaking, OPF 0.18): `importData` and `opf import-data` are renamed `ingest` and `opf ingest`, with no alias. The function is exported from the package root and `@openpresentation/opf/data`, and its options type `ImportDataOptions` is now `IngestOptions`; `ImportedTable`, `ImportedChart` and `OPFDataImportError` keep their names. The CLI command takes the same flags and gives the same report, output and exit codes; `opf import-data` is now an unknown command (usage error, exit 2). Replace `importData(` with `ingest(` and `opf import-data` with `opf ingest`.
- RR-74 (breaking, OPF 0.18): core's Node engine uses opf-render's 0.18 engines, and the `convert` options and the render and export flags take their 0.18 names, with no aliases. The optional peer ranges of opf-render and opf-pptx are `^0.18.0` for core and the CLI (the lockstep line; npm resolves the two together), because the engine calls `toSvg(deck, slide, options)` (slides count from 1), `toPng(svg, options)` and `toPdf(svgs, options)` in place of `renderSlideSvg`, `svgToPng` and `svgToPdf`; an older opf-render is `peer-too-old`. The output is the same bytes for the same rendering. The `opf` CLI reports the renderer's `^0.18.0` range when it is missing.
    - **Renamed `convert` options and flags:** `svgFonts` (`--svg-fonts used|none`) is `text` (`--text fonts|system|paths`); `pdfMode: "raster"` (`--pdf-mode raster`) is `raster: true` (`--raster`); `chartex` (`--chartex auto|native|fallback`) is `charts` (`--charts auto|native|picture`); `imageFormat` (`--image-format`) is `images` (`--images`); `fontDirs` (`--font-dir`, repeatable) joins `fonts`, which is a prepared fonts handle or a folder or a list of folders (`--fonts <directory>`, repeatable); `filename` is `name`, now the base name of the returned files and valid only without an output path.
    - **`text`:** `"fonts"` (the default) embeds the faces the slide's text uses, as before. `"system"` embeds none. `"paths"` draws the text as glyph outlines (the renderer's `text: "paths"`), so the SVG needs no font; the engine then passes the renderer the whole fonts handle it draws outlines from and keeps no embedded-face bookkeeping. `text` still applies to SVG output only.
    - **`zip`:** valid only without an output path (`convert(deck, { format: "svg", zip: true })`). With an output path a `.zip` name makes the archive, and `zip: true` is refused with `invalid-option`.
    - **Refused:** the 0.17 option names `svgFonts`, `pdfMode`, `chartex`, `imageFormat`, `fontDirs` and `filename` reject with `invalid-option`, and the message names the new option. The old CLI flags are usage errors (exit 2).
    - **opf-pptx:** the PowerPoint engine keeps its own option names. `charts` and `images` reach `toPptx` as `chartex` (`picture` as `fallback`) and `imageFormat`.
    - **Engine:** `embeddedFor(handle, text)` takes the `text` mode; `checkRenamedOptions` and `ResolvedExportOptions` are new in `@openpresentation/opf/internal/engine` (not an application API).
- RR-75 (breaking, OPF 0.18): the CLI is consolidated around one convert command, one output convention and fixed flag meanings, with no aliases. Every removed command and flag is a usage error (exit 2, `code: "removed-command"` or `"removed-option"`) whose message names the replacement.
    - **`opf convert` absorbs the format commands.** `opf render`, `opf export`, `opf import`, `opf from-md`, `opf to-md`, `opf from-yaml`, `opf to-yaml` and `opf create --from` are removed: `opf convert <input> <output>` does all of them, the formats named by the extensions or by `--from` and `--to`. It reads stdin (`-`, with `--from json|yaml|md|pptx`, or JSON sniffed) and writes stdout (`-`, with `--to json|yaml|md|pdf|pptx|png|svg|zip`; png and svg take one slide). On its input side a plain `.md` file is OPF Markdown. Their flags moved with them, and a flag applies only where its format is involved, otherwise it is a usage error (`code: "option-not-applicable"`): `--split` and `--title` for a Markdown input, `--aliases` for a YAML input, `--signals` for a `.pptx` input, `--schema-comment` for a YAML output, `--drop-unsupported` for a Markdown output, and the drawing and PowerPoint flags for those outputs. The format of every file is checked against its name, so a `.png` output is never written as SVG (the `render --out deck.png` class of bug). A part the Markdown dialect has no syntax for is a `markdown/embedded` (or `markdown/dropped`) warning, as `to-md --fail-on warning` treated it.
    - **One output convention.** A command that writes a deck takes an optional output after its inputs and writes stdout without one; `-i`/`--in-place` rewrites the input (`edit`, `format`, `merge` (ours), `paginate`, `embed`, and `ingest` for its `--into` deck); `format --check`, `embed --check` (exit 1 when something would be embedded) and `paginate --check` (exit 1 on overflow) write nothing. `--output`, `--out`, `--out-dir`, `--name` and `--dry-run` are removed. `opf fill`'s data is always its second argument, whatever its name (`-` reads stdin; `--data` is removed), and its optional third argument is the output, a deck name or a file name pattern: `opf fill t.opf.md clients.csv decks/qbr-{client}.opf.md` (`{n}` the record number, `{column}` a slug of its value); `--combine` writes one deck. An existing output is refused before any warning is printed.
    - **Flag meanings.** `--format` is only a report format (`json`, `text`, `github` for validate, `patch` for diff). `--from` and `--to` name deck forms and replace `--input-format` and every deck `--format`. `--data-format csv|tsv|json` names the data of `fill` and `ingest` (their `--format csv|tsv|json`). Without `--from`, stdin and names that say no form are JSON when they start with `{` or `[`, and anything else is a usage error that asks for `--from yaml|md`.
    - **One report envelope.** Every command that reports prints `{ command, ok, input, outputs: [{ file, sha256, bytes, mediaType }], findings, counts, ... }` (on stderr when stdout carries the document): `stats` puts its facts under `stats`, `diff --format json` and `skills` add their fields. Errors are `{ command, ok: false, code, error, ... }` on stderr, and a document that fails (an invalid deck, a finding at `--fail-on`) is an error report with its `findings` (`code: "invalid-document"` or `"findings-at-fail-on"`). `--json` is removed, and the reports carry no `valid` (validate keeps it), `dryRun` or `agentSkills`.
    - **`opf paginate`** measures its page breaks with the fonts `opf convert --paginate` draws with when opf-render is installed (`layout: "measured"`), else estimates them (`layout: "estimated"`, with a `hint` that names the install command); `--fonts` adds folders.
    - **Small fixes:** the dead `config` value option is gone from every command but `validate`; an empty `validate --format text` report has no leading blank line; `paginate` (and every writer) refuses an existing output before printing a fence warning.

## 0.17.0 (2026-10-09)

- RR-62: `@openpresentation/opf/node`, core's Node-only file API, and `opf convert`.
    - `convert(input, output, options?)` turns a `.pptx`, `.opf.md`, `.yaml`/`.yml` or `.json` file, a deck object or PPTX bytes into a `.pdf`, `.pptx`, `.png`, `.svg`, `.zip`, `.opf.md`, `.yaml`/`.yml` or `.json` file, the formats named by the extensions (`slides/deck.png` writes `slides/deck-001.png`, ...; one selected slide is written to the output itself; a `.zip` holds PNG slides, or SVG with `format: "svg"`). Everything is produced before anything is written, each file atomically, parent folders created; an existing output is replaced, as `save` does (`overwrite: false` refuses it; the commands keep refusing without `--force`). Images resolve next to the input file. `convert(input, { format })` returns `{ files: [{ name, type, bytes }], findings }` and writes nothing.
    - `open(pathOrBytes)` returns the presentation of a deck file, or imports a `.pptx` (path or bytes); an invalid deck throws `OPFValidationError` with findings located by line and column. `save(deck, path, { validate })` writes the form the extension names, atomically, and refuses an invalid deck unless `validate: false`.
    - Typed errors with a `code` (`OPFApiError`, `OPFExportError`, `OPFImportError`): `peer-not-installed` with the install command, `peer-too-old`, `peer-load-failed`, `invalid-option`, `invalid-presentation`, `input-not-found`, `output-exists`, `no-slides`, `export-failed`, `import-failed`.
    - The export and import engine, the lazy loading of `@openpresentation/opf-render` and `@openpresentation/opf-pptx` (now optional peers of core) and the fonts are behind it; the office font pack is prepared once per process (byte-identical output). `/node` re-exports the rest of core, so `import * as opf from "@openpresentation/opf/node"` covers an application. The root and every other subpath stay free of the file system (`check:browser-safe`).
    - CLI: `opf convert <input> <output>` with the flags, report and exit codes of `opf export`; `render`, `export` and `import` run core's engine.
- RR-62 (breaking, 0.x minor): core's `readDeck` and `writeDeck` are now `parse` and `stringify`. `parse(text, { filename?, format?, catalogs? })` returns the presentation and throws `OPFValidationError` on a syntax, schema or reference error (findings located by line and column); `validate(text)` still returns the full report. `stringify(deck, { format? | filename? })` returns the text. `@openpresentation/opf/deck` exports `parse`, `stringify`, `deckFormatOf` and `DECK_FORMATS`.
- RR-62 (breaking, 0.x minor): `@openpresentation/cli/api` is removed; the CLI is the `opf` command. Applications use `@openpresentation/opf/node` (`convert`, `open`, `save`). The CLI depends on core `^0.17.0`.
- RR-62: `opf import-data --into` is deterministic. Two runs with the same data, options and deck now write identical bytes. The new slide id is `data-` plus eight hex digits of a SHA-256 over the data text and the import options (`-2`, `-3` appended if the deck already has it) instead of a random UUID, and `--id <slideId>` names it explicitly (it fails if the deck already has the id). With `--dataset`, `source.src` is the data file's path relative to the deck's folder with `/` separators (it was relative to the working directory), and `source.retrieved` is set only by the new `--date YYYY-MM-DD` instead of the clock; with no `--date` it is absent, and a re-import no longer keeps an older `retrieved`. The command moved from `src/index.ts` to `src/import-data.ts`; core's `importData` has no clock or randomness and is unchanged.
- RR-62: `opf render` and `opf export` take the format from `--out`'s extension with the rule `opf convert` uses: `opf render deck.opf.md --out deck.png` writes a PNG file instead of a folder named `deck.png` full of SVG files. An `--out` with another file extension, or one that disagrees with `--format`, is a usage error (exit 2).
- RR-66: Windows path fixes. Commands that check whether two paths name one file (`merge --report` against the output, `import --signals` against `--out`, `edit`, `merge` and `import-data --into` writing back to their input, `format --output`) compare file identity, and names that differ only in case on Windows, instead of the resolved path text: on a case-insensitive file system `merge --report MERGED.opf.json --output merged.opf.json --force` no longer replaces the merged deck with the report, and `format deck.json --output Deck.json` rewrites the file instead of refusing it without `--force`. `import-data` and `fill --data` read the data format from the extension in any case (`DATA.TSV` is TSV, not CSV). The packed-install test (`packages/cli/test/packed.mjs --registry`) installs its global prefix beside the folder its `npm exec` step runs in, not around it, so the step finds the `opf` command on Windows ([opf#466](https://github.com/OpenPresentation/opf/issues/466)).

## 0.16.0 (2026-10-09)

- FA-27 (additive schema; lockstep with the renderer, PPTX and editor): `Table.alt`, the text alternative for a table, mirroring `Chart.alt`: what the table shows (the point and the key numbers), not "a table". `""` marks a table decorative. The preview exposes it as the table's accessible name (a labelled group; the cells stay readable), the PowerPoint export writes it as the table frame's `descr` and import reads it back. Core adds no validation rule: a native table is read cell by cell, so `validate` neither asks for a table alt nor reports an empty one, and a table keeps counting as text beside a chart for `opf/chart-text-alternative`. The Markdown dialect round trips it (a pipe table has no syntax for it, so a table with `alt` is written as an `opf-block`).
- RR-60: Markdown decks (`deck.opf.md`) are a native input and output of every command, and core has one entry point to read and write a deck in any form. Core: `readDeck(text, { format, filename, catalogs, validate })` returns the deck with the `validate` report of it for JSON, YAML or Markdown, every finding located in the text that was read (JSON syntax errors are `opf/json-syntax` with line and column), and `writeDeck(presentation, { format | filename })` writes it; both are exported from the root and from the new subpath `@openpresentation/opf/deck`, with `deckFormatOf(filename)` (`.opf.md` is Markdown, `.yaml` and `.yml` are YAML, anything else JSON; the content is never sniffed and a plain `.md` file is never a deck). `fromMarkdown` now returns the full `validate` report like `fromYaml` (`schemaValid`, `checks`, and `template` and `unfilledVariables` for a template). CLI: a file ending `.opf.md` is a Markdown deck in `validate`, `render`, `export`, `create --from`, `edit`, `format` (canonical Markdown; `--check` works), `merge`, `diff`, `stats`, `paginate`, `embed`, `fill`, `import-data` and `to-md`; `--input-format` takes `markdown` (alias `md`) for stdin and other names; a Markdown syntax error exits 2 with `line:column` and located findings under `markdown` (`opf validate` reports `markdown/<rule>` findings and exits 1); a command writes Markdown for an output ending `.opf.md` or `--format markdown|md`, else the format it read, and warns on stderr when a rewrite moves content into `opf-slide`/`opf-block` fences. `opf stats` now reads YAML and Markdown decks, and a JSON syntax error in any deck input now names its line and column. JSON stays canonical; `from-md` and `to-md` are unchanged. The Markdown example `examples/markdown/quarterly-review.md` is now `quarterly-review.opf.md`.
- RR-62: `@openpresentation/cli/api`, the format-oriented library API of the CLI package. `readDeck`, `writeDeck`, `validate` and `assertValid` are core's own (re-exported, with `defaultCatalog`); `exportDeck(presentation, { format: "pdf" | "png" | "svg" | "pptx", fonts, fontDirs, catalogs, slides, includeHidden, paginate, scale, pdfMode, svgFonts, chartex, provenance, imageFormat, date, assetDir, zip, filename })` returns `{ files: [{ name, type, bytes }], findings }` (one file per slide for `svg` and `png`, or one zip with `zip: true`; one file for `pdf` and `pptx`) with the bundled open fonts, no network, no system fonts and no clock unless `date` is passed; `importDeck(bytes, { catalogs, signals })` reads a PPTX into a presentation. `@openpresentation/opf-render` and `@openpresentation/opf-pptx` stay optional peers, loaded the first time a function needs them; a missing, old or broken one throws `OPFExportError` or `OPFImportError` with `code` `peer-not-installed`, `peer-too-old` or `peer-load-failed` and the install command (other codes: `invalid-option`, `invalid-presentation`, `no-slides`, `all-slides-hidden`, `export-failed`, `import-failed`; `findings` carry the located findings). `opf render`, `opf export` and `opf import` now run the same engine as `exportDeck` and `importDeck`: their options, JSON reports, error codes and exit codes are unchanged. Core is now a regular dependency of the CLI (`@openpresentation/opf`, `^0.16.0`) instead of a bundled copy, so the `opf` command, `@openpresentation/cli/api` and an application that imports core directly run one core (one set of error classes, one catalog, no version skew); `opf --version` reports the installed core. The package declares an `exports` map (`./api` with `dist/api.d.ts`, and `./package.json`); `opf` is still the `bin`. From opf-render 0.16 its converters (`pdf-lib`, `@resvg/resvg-js`, `sharp`) and every `@expo-google-fonts/*` package are optional peers: a missing one (renderer codes `converter-missing` and `font-resource-unavailable`) is reported as the same missing-peer error as a missing renderer, `peer-not-installed` (`peer-load-failed` when installed but unloadable), with the renderer's install command in the message and `package` or `packages`, `range`, `install` and `purpose` in the error `details` (`opf export` and `opf render` exit 2 with the same fields); the install hint lists what each output needs.
- RR-59: standalone SVG output (`--svg-fonts used`, the default) embeds the installed script font faces its text draws; `--svg-fonts none` still relies on the viewer's fonts. `opf catalog` also accepts the website's hyphenated kind names (`color-schemes`, `font-schemes`, `chart-types`), `opf fill` on an incomplete template suggests `--data`, `--examples` or `--partial`, `opf import-data --chart-type` rejects an id outside the chart-type vocabulary before writing anything, and the help names the supported Node range (`>=22`).

## 0.15.0 (2026-10-08)

- FA-20 (breaking, OPF 0.15): catalogs group the records a document embeds by the catalog they came from. `catalogs` is `{ default?: Group | false, custom?: Group, <name>: Group }`; a group is `{ source?, layouts?, themes?, colorSchemes?, fontSchemes?, narratives?, audiences?, purposes?, tones? }` with records keyed by id and no `$schema` or `id`. Every content reference (`Slide.layout`, `design.theme`, `design.colorScheme`, `design.fontScheme`, `narrative`, `audience`, `purpose`, `tone`, a theme's schemes) is a bare id or `name:id`; URL and `pkg:` references, `catalogs.<kind>.records` and `catalogs.<kind>.source` are gone, `design.theme` is a reference string only, and a reference inside an embedded record resolves in its own group first. One resolution rule for every kind (custom, default's embedded records, the catalog the host registered for its source); a reference that resolves nowhere is the warning `opf/unresolved-reference` (replacing `opf/catalog-reference`, `opf/catalog-source` and `opf/deprecated-catalog-id`, and the `unresolved-layout`, `unresolved-theme`, `unresolved-color-scheme` and `unresolved-font-scheme` diagnostics), an undeclared prefix is the error `opf/undeclared-catalog`, and a record embedded under `default` or a named group that the catalog registered for its source does not publish is the warning `opf/catalog-record-not-in-source`. Hosts register catalogs with one option on every entry point, `catalogs: Catalog[]` (`{ source, <kind>: { <id>: record } }`, the first is the host default), including `paginate`, `stats` and `resolveScriptFonts`; `strictReferences` makes `resolveSlideContext` and `paginate` throw `OPFUnresolvedReferenceError`. New helpers `embed` (replacing `bundle`), `copySlides` and `updateFromCatalog`, plus `resolveReference`, `parseReference`, `catalogRecords` and `resolveDesignRecords`. `chart.type`, the `language` tag (BCP-47 only; catalog ids such as `english-us` are invalid) and `socials` keys are engine vocabularies validated by the schema (`CHART_TYPES`, `LANGUAGES`, `SOCIAL_PLATFORMS`); a font scheme's `languages` list holds BCP-47 tags. Record schemas lose `deprecation`. The CLI command `opf bundle` is `opf embed`, `opf catalog` lists records keyed by id and drops `--all`, and a validate configuration's `catalogs` is an array of catalogs.
- FA-21 (breaking, OPF 0.15): zero built-in records. Core's root and every subpath except the new `@openpresentation/opf/catalog` import no catalog data, held by `pnpm check:catalog-free` (an esbuild metafile check with a gzip budget per entry); the root bundle drops from about 389 KB to 293 KB gzipped and `/composition` from 143 KB to 61 KB. `@openpresentation/opf/catalog` exports the full pptx.gallery catalog for hosts to register (every record of every kind the gallery publishes, 278 layouts included; the snapshot sync mirrors every kind and `--include` is gone) (`defaultCatalog`, `DEFAULT_CATALOG_SOURCE`, `catalogDisplay` with chart-type, language and social-platform display metadata, `catalogIndexes`, and the layout previews); the `./catalogs` and `./previews` subpaths and the root's `catalogs`, `catalogEntries`, `catalogIndexes`, per-kind arrays and `layoutPreviews` are gone. Without a `catalogs` option nothing is registered: only what a document embeds resolves. Theme, colour-scheme and font fallbacks are engine defaults in code (`ENGINE_DEFAULT_THEME`, `ENGINE_DEFAULT_COLOR_SCHEME`, `ENGINE_DEFAULT_FONT_SCHEME`, from `spec/reference/engine-defaults.json`; `DEFAULT_FONT_SCHEME` and `resolveFontSchemeReference` are removed), and cover detection is a record rule (a layout whose placeholders are all headings or placed images) instead of the ids `title` and `title-subtitle`. Every example deck, docs fixture and skill asset embeds the records it uses. The CLI registers the default catalog for every check, pagination, embed, render, export and Markdown or YAML conversion. `fromMarkdown` and `fromYaml` take `catalogs` for their references check.
- The optional peers `@openpresentation/opf-render` and `@openpresentation/opf-pptx` are now `^0.15.0`, the line that reads OPF 0.15 documents, and the install hint names that range.

## 0.14.0 (2026-10-07)

- FA-09 (additive schema; lockstep with the renderer, PPTX and editor): `Chart.alt`, the text alternative for a chart (what the data shows, not "a chart"). `""` marks a chart decorative, like an empty `Asset.alt`. The preview exposes it as the chart's accessible name, the PowerPoint export writes it as the chart frame's `descr` and import reads it back. Core: `validate`'s `opf/chart-text-alternative` reads `chart.alt` first (a non-blank alt passes; without alt, text beside the chart still passes; `alt: ""` is reported as info so the choice is reviewed), its quick fix focuses the `alt` field, and `opf/poor-alt-text` also checks chart alt text (a bare "chart", a URL, a leading "chart of", over 250 characters). The Markdown chart fence takes it as ` ```chart column alt="..." ` (`markdown/chart-attributes` for an unknown attribute); a chart with `alt` converts to and from Markdown natively.
- FA-10: `title`, `subtitle`, `tag` and `quote.text` accept `string | TextRun[]` (the same `TextRun`, including `color`, links, `cite` and `footnote`), so one word of an action title can carry the accent color and a headline claim or a quote can carry a citation marker.
