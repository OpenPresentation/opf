## 0.18.0 (2026-10-10)

- RR-71 (breaking, needs core 0.18.0): logos live on the organization. The cover and section logo is the primary organization's `full` logo (or the one `design.logo` names, `var:organization.beta.logo`; `design.logo: false` draws none), picked per slide as the `onLight` or `onDark` asset of its shape, and its picture carries the organization path (`organization.0.logo.full.onDark`) in its tag and in `unresolved-asset` diagnostics. A header or footer `image` that is a logo reference (`var:organization.logo.icon`, a partner's `var:organization.beta.logo.wordmark`) is an ordinary furniture picture drawn at core's row-layout box; the slide manifest records the authored reference and the content key of the embedded bytes (`images`), and import returns the reference while the picture still embeds those bytes and the stored organization has a logo for it (a replaced, foreign or provenance-less picture imports as an image). `LogoSet` import and export and the zone `logo: true` flag are removed with no alias (the furniture manifest's `logos` key is gone), and `OPF_LOGO_V1` consumes the cover picture with the organization restored from the document record (an export without it gives the primary organization the picture as its one logo). In a zone that holds a logo beside the footer text, the text part is only as wide as its words (core's row layout): the slide's `ftr` placeholder keeps that box, and the master and layout placeholder spans the zone.
- RR-72 (output-changing for decks whose header or footer repeats a part PowerPoint has no placeholder for): such a part (a logo or other zone image, socials, header text, a second footer text or date) that is drawn the same on two or more slides is written once, on the slide master when every slide that shows such furniture draws it, else on a layout shared by the slides that do (one layout per distinct set: a logo with `onLight` and `onDark` assets gets a layout per background tone). A slide that hides it uses a layout with `showMasterSp="0"`. A part on one slide only, a part with a live field and a part that slide content covers stay on the slide; the last reports `furniture-on-slide`, because PowerPoint draws master and layout shapes beneath slide content. RR-11's `ftr`, `dt` and `sldNum` placeholders, the master and layout placeholders and `p:hf` are unchanged, so Insert > Header & Footer works as before. The lifted shapes keep their `OPF_FURNITURE_V1` tags (with the slot in place of the slide part) and each slide manifest lists them under `shared`, so `fromPptx` reads them from the slide's layout and master: a master logo returns as its `var:organization.logo.*` reference on every slide, a part deleted on the master is removed from every slide, and Hide Background Graphics on a slide removes the master parts from that slide. Importers before 0.18 ignore `shared` and read the rest of the furniture; shapes on a master or layout without OPF tags (a third-party template) are still not imported. Over the 127 core examples, 81 decks move furniture off their slides and every deck imports to the same document as before.
- RR-73 (requires opf-render 0.18 for the optional peer; no `toPptx` or `fromPptx` API change): the exporter calls opf-render's renamed `toPng` where it called `svgToPng` (the default rasterizer of the PNG fallback of an SVG picture; `options.svgRasterizer` is unchanged), and the tests and scripts that draw previews use `toSvg`, `toPng` and the 1-based slide argument. The optional peer range moves to `^0.18.0` in the release-prep pull request.
- RR-20: `test:packed` installs every `test/helpers/*.mjs` next to the copied tests (RR-72's `master-furniture.mjs` was missing from the clean consumer, which failed the 0.18.0 release prep).

## 0.17.0 (2026-10-09)

- FA-31 (breaking, needs core 0.17.0): header and footer values are `{{ }}` variables in a zone's `text`. `{{slide.number}}` is a native slide-number field (the Slide Number placeholder for a one-line footer text, a live field inside the tagged shape otherwise) with the words around it as fixed runs; `{{deck.slideCount}}` and `{{slide.section}}` are fixed text, and every slide-scoped token in body text is fixed text. Each slide is composed and drawn from core's substituted slide (`resolveSlideContext(...).slide`), so text is measured with the real value and a paginated deck shows consecutive numbers. The `organization`, `speaker`, `section`, `slideNumber` and `slideNumberFormat` flags are gone with no alias, and `formatSlideNumber` and `DEFAULT_SLIDE_NUMBER_FORMAT` are removed from the furniture helpers. Import returns `{{slide.number}}` for a native slide-number field in a header or footer (a third-party PPTX with a slide-number footer included), and furniture provenance stores the authored zone text of a zone whose tokens are all built-ins (`{{organization.name}}`, `{{slide.number}}`, ...; `templates` in the slide manifest) and restores it while it draws the words still on the slide, so OPF to PPTX to OPF returns the same header and footer objects; edited words import as they stand. Organization and speaker metadata no longer come from furniture text (they return from the stored document record, which also draws a stored `{{organization.name}}`), social profiles need that record to rebuild `organization.socials`, a footer `{{slide.section}}` no longer reports `section-reference-changed`, and a moved slide keeps its live number instead of reporting `invalid-furniture-provenance`.
- RR-20: `test:packed` keeps verifying registry signatures while core's `/node` names this package as an optional peer and its version is not on npm yet: the consumer pins the tarball with an override (and core at this package's range), so `npm audit signatures` no longer asks npm for the unpublished version (ETARGET).

## 0.16.1 (2026-10-09)

- RR-59 (#214): `toPptx` no longer fails `font-unavailable` under the default (metric) font policy, office pack loaded, on engine-generated text whose weight has no metric face. That text is the "Image unavailable" placeholder label and the video caption (600), core's metric value (800) and its labels and timeline event text (500). The office pack's Intos stands in for Aptos at 400 and 700 only, so 0.16.0 refused any default-theme deck with an unresolved image (image block, quote photo, logo), a video, a metric or a timeline. DrawingML has only a bold flag, so such a run is now measured at the face PowerPoint draws it with: 700 for 600 and above, 400 below. A missing image again gives the `unresolved-asset` warning and the placeholder. The export equals the visual-policy export, and decks that exported before produce identical bytes. A `font-unavailable` for a family that is loaded, only not at the requested weight and style, now names that family, weight and style and the ones that are loaded (`details.fontWeight`, `details.italic`, `details.loadedStyles`). It no longer says that none of the replacements is loaded.

## 0.16.0 (2026-10-09)

- FA-26 (needs core 0.16.0): the export places every leaf of a layout record with nested placeholder groups (`{ "type": "group", "composition", "placeholders" }`, up to three levels) in the box core composition gives it, the same box the preview draws, and a document's own records, groups included, survive an unchanged round trip. `design.chartPrimary` exports the placeholder group it stands for, with unchanged geometry. `test/placeholder-groups.mjs` exports core's cross-engine fixture (`test/fixtures/placeholder-groups.opf.json`) and checks every native frame within 0.5 pt.
- FA-27: `Table.alt`, the table's text alternative, like `Chart.alt`. `toPptx` writes it as the table frame's `p:cNvPr/@descr`; an empty `alt` is written as PowerPoint's own decorative marker (the `adec:decorative` extension), never as `descr=""`. `fromPptx` reads the `descr` (or the decorative marker) back into `table.alt`, so alt text typed in PowerPoint on a table imports; a table whose frame has no description imports with no `alt`. Chart and table share one frame writer (`src/frame-alt.js`, formerly `chart-alt.js`). Needs the core release that adds `Table.alt`.
- RR-63 (no API change; for opf-render 0.16, whose `@resvg/resvg-js`, `sharp`, `pdf-lib` and `@expo-google-fonts/*` are optional peers): an SVG picture whose PNG fallback cannot be drawn because opf-render's PNG converter is not installed (`OPFRenderError` `converter-missing`) is reported as `svg-rasterizer-unavailable`, like a missing opf-render: the placeholder and an `unresolved-asset` diagnostic, or a `strictAssets` throw, with opf-render's install command (`npm install @resvg/resvg-js@^2.6.2`) in the message. Any other renderer failure stays `svg-render-failed`. The tests and the packed-install check list the converter and the font packages they load through opf-render as devDependencies (`@resvg/resvg-js`, the `base` and `office` packs' `@expo-google-fonts/*`), so they run against opf-render 0.15 and 0.16. The `@openpresentation/opf-render` peer range and every version are unchanged.
- RR-59 (output-changing for `full` provenance exports): a full-provenance round trip restores the absence of document-level defaults. `OPF_DOCUMENT_V1.absent` lists the defaults a document leaves to the engine (`$schema`, `name`, `language`, `design.theme`, `design.colorScheme`, `design.fontScheme`, `design.dimensions`), and `fromPptx` leaves each absent while the package still shows the default, so an untouched round trip is deep-equal to the source; a theme colour, slide size, title or run language edited in PowerPoint imports as observed. Every `full` export therefore carries the document and slide tags, also for a document that states nothing else (every other part is byte-identical; `references-only` and `false` are unchanged). Every picture path reports an unresolved source once (opf-pptx#210): a quote photo now emits `unresolved-asset` with its placeholder, so strict export (`--fail-on warning`) gates it; a local image file that cannot be read is an unresolved source (`reason: 'file-unreadable'`, `strictAssets` throws `missing-asset`) instead of failing the whole export with `pptxgen-failed` on any path; and a background picture with alt text no longer reports unreadable bytes twice. See `docs/document-roundtrip.md`.
- RR-59: report unresolved content images before exporting placeholders; preserve full-provenance inline table scalar types and authored styling only while native text, formatting, geometry and theme evidence remain unchanged; measure slide and run script fonts with the shared renderer planner while retaining selected native font names and optional custom measurement support. Native Office raster parity is a separate check. A table restored from its authored record takes its `alt` from the native frame (FA-27), so an alt edited or removed in PowerPoint is kept as PowerPoint shows it.

## 0.15.0 (2026-10-08)

- FA-23 (OPF 0.15, breaking, output-changing for every deck with a picture): backgrounds and image blocks replace `design.slideImage`, `design.imageFill` and the slide image tags.
    - An image background (`{type: "image", src, alt, fit, focus, opacity, recolor, overlay}` or an image source string; core `backgroundImage`) exports without alt text as the native slide background fill: `stretch`, `tile` at the picture's intrinsic size from the top-left corner (no longer min(w, h)/4 cells), `cover` cropped around `focus` with `a:srcRect`, `contain` fitted with `a:fillRect` insets, `recolor` as `a:grayscl`/`a:duotone` then opacity as `a:alphaModFix`. With alt text (its own only) it is a full-slide picture at the back of the slide (`OPF background slides.N`) carrying `descr`, over the colour scheme's default background colour. The overlay is one shape directly above the picture, the whole slide or an edge band.
    - Every content picture is an image block (core `item.image`): fit and focus through core's `fitImage` (`cover` is now the default; `design.imageFit` replaces `design.imageFill`), and the treatments with 0.14's slide image DrawingML (`a:prstGeom` with core's guides, `a:ln` with a miter join, `a:grayscl`/`a:duotone` then `a:alphaModFix`), the overlay directly above. A placed block (`placement`) is drawn at its band in core's item order (after the headings, above the watermark, as the preview draws it); the 15 gallery image treatments keep 0.14's frames and per-picture paint order (picture, line, overlay) where 0.15 can express them (`test/image-treatments-014.mjs` lists the five that cannot).
    - `OPF_IMAGE_V1` and `OPF_IMAGE_OVERLAY_V1` tag image block pictures (with their own fields) and their overlays, the background picture and the background overlay; import reads them back as image blocks with their treatments and placement and as the slide's image background with its alt text, fit, focus, opacity, recolor and overlay. An edited picture becomes an ordinary image (`invalid-image-provenance`). Import also reads a native background picture fill as an image background, now including `stretch`, the focus of an off-center crop and a grayscale or duotone recolor. `OPF_SLIDE_IMAGE_V1`, `OPF_SLIDE_IMAGE_OVERLAY_V1`, `invalid-slide-image-provenance` and the slide image import are removed.
- FA-23 (OPF 0.15, breaking; requires core 0.15): catalogs come only from the document and the host. `toPptx(doc, { catalogs })` and `fromPptx(bytes, { catalogs })` take core's registered catalogs (`Catalog[]`, matched by `source`, never fetched) and pass them to every core call that resolves a reference (`resolveSlideContext`, `resolveScriptFonts`), so a layout, theme or scheme that only a registered catalog holds exports exactly like an embedded one. The package ships no catalog data and never imports `@openpresentation/opf/catalog`: register the gallery snapshot explicitly (`catalogs: [defaultCatalog]`). A reference that resolves nowhere is reported once per path as core's `unresolved-reference`; the slide composes automatically and core's engine defaults are drawn (an engine-default colour scheme is named `OpenPresentation` in the theme part). The new `strictReferences` option (default: `strictAssets`) fails such an export with `OPFPptxError` `unresolved-reference` instead. Import recovers `design.colorScheme` and `design.theme` only against the host default catalog (the first registered one, as bare ids); with none registered the colour scheme imports inline and no theme id is recovered. The dominant run language imports as a BCP-47 tag (`ja-JP`), and the `language-uncatalogued` and `language-ambiguous` diagnostics are gone. Document provenance stores the grouped catalogs (`catalogs.<group>.<kind>.<id>`, pruned to the referenced records, every group declaration kept) and the slide `layoutRecord` as `{group, id, source?, record}`, so a pasted slide brings its record and group; a stored layout reference restores from the stored catalogs, a slide's own record or a catalog registered with `fromPptx`. The composition hint `imageFill` is stored as `imageFit`. Removed with no alias: `catalogSources`, the `{kind: records[]}` form of `catalogs` (refused with core's `OPFCatalogsOptionError`, code `invalid-catalogs`), catalog language ids, catalog social-platform records (core formats socials from `SOCIAL_PLATFORMS`) and the 0.14 tag shapes of catalogs and layout records.
- FA-23 (OPF 0.15, breaking): engine vocabularies and diagnostic names follow core 0.15. `chart.type` is a schema enum, so the exporter's legacy substring heuristic for other chart type ids (and the `donut` alias) is removed: such a document fails validation. The import diagnostic for a stored layout reference that resolves nowhere is `unresolved-reference` (was `unresolved-layout-reference`), and the `checkTypefaces` violation for a theme font reference that resolves to no font is `theme-reference-unresolved` (was `unresolved-theme-reference`).

Each slide is composed with the options of core's `resolveSlideContext` (the one font-family, canvas, layout and alignment chain every engine shares) instead of a hand-built copy, and a reference that matches no theme, colour scheme or layout is reported once per place as `unresolved-theme`, `unresolved-color-scheme` or `unresolved-layout` instead of `catalog-resolution-failed` refusing an unknown layout. A slide with no layout, or an unknown one, is composed with no layout record (automatic composition, as the preview does) instead of the `blank` layout, so a layout-less title-only cover is now centred vertically. Core's functions are imported by name from `@openpresentation/opf` and `@openpresentation/opf/composition`; the fallbacks for an older core (silent number-format stubs, missing script-font, chart-option, syntax-colour and trend-mark features) are removed, so a core without them fails on load instead of switching a feature off.
- FA-05 (output-changing for decks that set color-scheme roles, contain links, or use a saturated mid-tone background): the export resolves color roles through core `resolveColorRoles`, shared with the preview. The `accent` ColorRef role is the scheme `accent` (accent3), not the primary color; the `surface` override reaches cards and chart panels; and the dark-background decision uses WCAG luminance (under 0.179) instead of Rec. 601 luma, so saturated backgrounds such as red now take dark text in both engines. A link run with no color of its own is written in `a:schemeClr hlink` (the theme hyperlink color, or the slide text color where that has under 4.5:1 contrast against the slide) instead of the default text color, and a link in the bare `hlink` color imports as a link with no color.

## 0.13.0 (2026-10-06)

- RR-54 (output-changing only for decks that use the new fields, or whose chart cells held non-numeric strings; needs core with RR-54, opf#376): chart and table data in the PPTX export and import (core `docs/chart-table-data.md`).
    - Strict chart numbers: every chart value passes core `chartNumber`, replacing the exporter's lenient parse (`"1e6"` exported as 16, `"(5)"` as 5, `"Q1"` as 1, `"12%"` as 12).
