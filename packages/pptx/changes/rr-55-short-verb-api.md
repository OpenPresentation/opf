RR-55 (breaking, requires core 0.14 and, for the optional peer, opf-render 0.14; exported PPTX bytes are unchanged except for slides with no layout record, see below): the names follow core. `toPptx(presentation, { fonts })` takes the fonts handle that opf-render's `loadFonts()` returns (core's `Fonts`: at least `textMeasurement`) and no longer reads a top-level `textMeasurement` option. `fromPptx(bytes, { signals: true })` resolves to `{ presentation, signals }` (it was `{ document, signals }`). `OPFPptxError` carries `findings` (the `error` findings of core's `format` check, or the variable errors) and `diagnostics` (the layout diagnostics of `layout-overflow`) where it carried `issues`. `inventoryPptxTypefaces` is `inventoryTypefaces`, `checkPptxTypefaces` is `checkTypefaces`, and its `fonts` option is `families`; the re-declared `FontSchemeDiagnostic` type is now core's. Each slide is composed with the options of core's `resolveSlideContext` (the one font-family, canvas, layout and alignment chain every engine shares) instead of a hand-built copy, and a reference that matches no theme, colour scheme or layout is reported once per place as `unresolved-theme`, `unresolved-color-scheme` or `unresolved-layout` instead of `catalog-resolution-failed` refusing an unknown layout. A slide with no layout, or an unknown one, is composed with no layout record (automatic composition, as the preview does) instead of the `blank` layout, so a layout-less title-only cover is now centred vertically. Core's functions are imported by name from `@openpresentation/opf` and `@openpresentation/opf/composition`; the fallbacks for an older core (silent number-format stubs, missing script-font, chart-option, syntax-colour and trend-mark features) are removed, so a core without them fails on load instead of switching a feature off.
