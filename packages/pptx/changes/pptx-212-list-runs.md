opf-pptx#212: a full-provenance round trip of a list no longer bakes the list's own size, family and colour into its items. `items: ['a']` used to import as `[[{text: 'a', fontSize: 18.75, fontFamily: 'Aptos', color: '#FFFFFF'}]]`; it now imports as `['a']`, and string and rich-run items, `items` and `bullets`, descriptions, levels, numbering, wrapped and hard-broken items are deep-equal to the source after an untouched round trip. The export records the look it writes on every run of each measured list in the slide record (`OPF_SLIDE_V1.listRuns`: `{text, description?}` per list path, each `{bold, color, fontSize, fontFamily}`, never text; `full` mode only), and import removes a run value still equal to it, the absent-vs-native rule opf-pptx#211 applies to document defaults. A run value edited in PowerPoint differs from the record and comes back as observed. Runs stay separate, so the run colour record (`colors`) still lines up, and a colour reference that resolves to the list colour (the `text` role) is still restored; an authored literal colour, size or family equal to the list's own returns absent. Exports without the record (`references-only`, `provenance: false`) and older exports import as before. Output change: full-provenance exports with a list carry the `listRuns` key in their slide tag (released importers ignore it).
