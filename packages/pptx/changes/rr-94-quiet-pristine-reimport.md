RR-94: `fromPptx` of an unedited OPF export no longer reports one `*-import-reflow` diagnostic per tagged group (headings, plain text, metrics, quotes, timelines, code, furniture; about 14 on a six-slide deck). Each tagged text shape now records a fingerprint of its geometry and native text (`sig` in its tag), and a group whose shapes all still match is silent; an edited group still reports, and a tag from an earlier version, which has no fingerprint, keeps reporting. An image block authored from a relative path or http(s) URL records that source and the picture's media key in `OPF_IMAGE_V1`, and import gives the authored `src` back while the picture bytes still hash the same (a data: URI, an `asset:` reference, an absolute or parent-relative path or a file: URL is never recorded; changed bytes keep the data: URI). Every image block now carries an `OPF_IMAGE_V1` tag (an empty treatment when it has none), so an unchanged picture also re-imports without `unsupported-image-crop`.
