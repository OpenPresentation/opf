FA-31 (breaking, needs core 0.17.0): header and footer values are `{{ }}` variables in a zone's `text`. `{{slide.number}}` is a native slide-number field (the Slide Number placeholder for a one-line footer text, a live field inside the tagged shape otherwise) with the words around it as fixed runs; `{{deck.slideCount}}` and `{{slide.section}}` are fixed text, and every slide-scoped token in body text is fixed text. Each slide is composed and drawn from core's substituted slide (`resolveSlideContext(...).slide`), so text is measured with the real value and a paginated deck shows consecutive numbers. The `organization`, `speaker`, `section`, `slideNumber` and `slideNumberFormat` flags are gone with no alias, and `formatSlideNumber` and `DEFAULT_SLIDE_NUMBER_FORMAT` are removed from the furniture helpers. Import returns `{{slide.number}}` for a native slide-number field in a header or footer (a third-party PPTX with a slide-number footer included), and furniture provenance stores the authored zone text of a zone whose tokens are all built-ins (`{{organization.name}}`, `{{slide.number}}`, ...; `templates` in the slide manifest) and restores it while it draws the words still on the slide, so OPF to PPTX to OPF returns the same header and footer objects; edited words import as they stand. Organization and speaker metadata no longer come from furniture text (they return from the stored document record, which also draws a stored `{{organization.name}}`), social profiles need that record to rebuild `organization.socials`, a footer `{{slide.section}}` no longer reports `section-reference-changed`, and a moved slide keeps its live number instead of reporting `invalid-furniture-provenance`.
