RR-81 (OPF 0.19 layout templates; output-changing for decks whose slides use a template only): when a slide uses a 0.19 template (`areas`/`regions`), every template the deck can reach becomes one native `p:sldLayout` under each slide master, so Change Layout and New Slide list them all: the registered catalogs' templates in catalog order, then the templates the document embeds (`custom` first, then other groups by name), each by id, used or not. A layout is named by the record's `name` and typed as PowerPoint knows it (`cover` is `title`, `section` is `secHead`, `text`, `list`, `agenda` and `faq` are `obj`, `two-column` and `comparison` are `twoObj`, `image-beside` is `picTx`, every other template, `statement` included, `cust`). It has one placeholder per area of the empty layout core composes at the deck size (`composeLayoutAreas`, bled regions to the slide edge): `title` (`ctrTitle` and a `subTitle` below it on `cover` and `section`), `subTitle` for a `subtitle` area, and per body region (named by the region; its `idx` is a base per placeholder kind, `obj` 100, `body` 200, `pic` 300, `chart` 400, `tbl` 500, `media` 600, plus its position among that kind's regions, so Change Layout, which pairs placeholders by `idx`, only pairs regions of one kind) `pic` when it takes only pictures or is a `media` region of pictures and video, `chart`, `tbl` or `media` when it takes only charts, tables or video, `body` when only text and lists, otherwise a content placeholder; RR-11's date, footer and slide-number placeholders and `p:hf` stay, and an `OPF_LAYOUT_V1` tag records the layout's id, group, source, reference, a record hash, the region of every placeholder index and, in `full` provenance, an embedded template's record. Slides relate to their template's layout (a slide whose regions collapse uses the full layout), and the lone picture, chart or table of a `none` region is bound to its placeholder (`p:ph`, at core's geometry), so Reset, Change Picture and Change Layout move it; blocks of flowing regions, text and captioned or carded objects stay free shapes. RR-72 furniture variants copy the slide's own template layout (`Pillars (no furniture)`). A list core breaks into columns (`listColumns`) is drawn in its columns at core's break points (one shape per line, as every list; not a native `numCol` body, whose breaks would differ), where it used to draw the first column only. `OPF_SLIDE_V1` records a block's `region` pin and the region each root block was drawn in, so pins round-trip. `fromPptx` maps a tagged slide layout back: a slide with no stored layout (added in PowerPoint, or exported without provenance) takes it, a slide whose layout relationship names another OPF layout (Change Layout) takes that one (`layout-changed`), text typed into a region placeholder (which has no `xfrm` of its own) sits at the layout's box and gets a `region` pin where plain binding would move it, an embedded template no slide uses comes back from its tag, a placeholder with no text (the prompt of a slide added from a layout) is not imported as an empty block, and a damaged tag is `invalid-layout-provenance`. Decks whose slides use no template (0.18 records, automatic slides) export exactly as before.
