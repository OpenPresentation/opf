# PPTX 0.5.1 security candidate evidence

This patch removes the unused image-size parser from ordinary npm installations. It ships the exact PptxGenJS 4.0.1 ESM distribution and MIT license, pinned to the official archive integrity and file hashes in `vendor/pptxgenjs/UPSTREAM.json`. JSZip remains a direct runtime dependency. No conversion API or upstream runtime source changed, and the installed graph needs no consumer override.

Local Windows verification on Node 20 and 24 passes the complete existing model/corpus suite, syntax and metadata checks, and fresh packed-consumer installation/export/reimport tests. Both the repository and fresh consumer report zero known npm vulnerabilities. npm auditing does not inspect vendored source as an installed upstream package; the separate provenance and advisory maintenance responsibility is documented in [dependency notes](../DEPENDENCY-NOTES.md).

The [published comparison](evidence/security-0.5.1/published-comparison.json) verifies the actual registry 0.5.0 integrity and compares 126 decks containing 805 slides. All 126 PPTX files match byte-for-byte. This uses explicit replacement images and fallback fonts; it is not an original-asset or native-viewer fidelity assertion. Run `npm run test:compare-published -- <reference-consumer> <report.json>` to repeat it.

`npm run test:browser` passes in actual Microsoft Edge 152.0.4191.66: 13 WebP conversion cases with pixel/alpha/orientation checks, 20 native rich-table cases, 11 conditional-style assertions and 12 styled/merged table assertions. These exercise browser import, SVG preview and native export/reimport. CI repeats these suites in Chromium on Linux and Windows, alongside Node 20/24 package checks.

The native test uses the installed candidate tarball with registry core 0.7.0 and renderer 0.5.0, exact locally installed Calibri fonts and Microsoft PowerPoint 16.0. The [generation report](evidence/security-0.5.1/generation.json) deliberately marks PPTX as a local candidate, not a published registry release. The recorded archive predates final documentation edits; the exported runtime and source fixture are unchanged. [Native evidence](evidence/security-0.5.1/native.json) confirms three slides, two native editable tables and an edit surviving save/reopen. The [comparison report](evidence/security-0.5.1/comparison.json) verifies merged borders, validates all three original/saved/edited reimports without diagnostics, and measures renderer-versus-PowerPoint mean absolute channel differences of 3.2767, 1.8507 and 2.5945. These are the same measurements as the previous release, not pixel equality.

To repeat native checks, install a candidate tarball, core 0.7.0 and renderer 0.5.0 into a fresh consumer, then use the portable [core native test scripts](https://github.com/OpenPresentation/opf/tree/49642ae/scripts) in order: `test-native-powerpoint.mjs <consumer> generate`, `test-native-powerpoint.ps1 -EvidenceDirectory <consumer>/evidence`, and `test-native-powerpoint.mjs <consumer> compare`. PowerPoint and the named fonts must already be installed; the scripts preserve other presentations. Font binaries are not redistributed.

Publication remains gated on review and the latest CI results. After publication, verify a fresh registry installation and adopt the actual release in downstream applications. No existing release is republished.
