# Native body prototype

`toPptx(document, {bodyText: "native", onDiagnostic})` opts in to one coherent paragraph, flat-bullet or numbered-list body per text region (since 0.22.0; the first is the Body placeholder, see the last section). Omit `bodyText` or use `"measured"` for the existing measured-line output. This is a source prototype, without a native Keynote or PowerPoint acceptance claim.

Since 0.22.0 every eligible text, list or bullets region is its own native body. A named layout region must be unshared (one content item, no overflow); other image, metric, chart or table regions retain their existing export. One actual `p:sp` holds the complete body, with authored hard paragraph breaks, normal rich runs and native wrapping. No measured soft wraps become source paragraphs. Selected font families, run sizes, explicit normal/bold/italic values, colors, supported links, effective alignment and the region's vertical anchor remain explicit. Blank and appended paragraphs receive selected typing defaults. The body disables autofit rather than shrinking text.

Plain text and basic rich runs are eligible. Flat level-zero character bullets are eligible. Groups, cards, shared regions, right-to-left paragraphs, tabs, unsupported run effects, annotations, picture bullets and numbered lists that are not one sequence retain measured shapes and report a path-specific `native-body-fallback`. A list with descriptions or nested entries (qualification case K04), or with multiple composed columns (K06), also falls back explicitly. Content is never summarized or flattened to qualify.

The native object uses its allocated body frame, with title and furniture space retained. Native applications choose their own line breaks, baselines and overflow behavior, so the result can differ from the measured preview. Later edits can overflow that fixed frame; the prototype does not silently shrink or repaginate them. Native paragraph separators can normalize to LF on reimport. Since 0.22.0 a plain-string title that wraps is one Title-placeholder box (see the last section); titles with a hard break, overflow, rich runs or right-to-left text retain measured shapes.

Only selected native bodies receive a layout variant. The original OPF catalog record, reference and hash stay intact; the variant identifies its actual body placeholder index. An eligible automatic slide uses a separate title-and-body `tx` layout, while default automatic slides keep `titleOnly`. There is one meaningful body placeholder per eligible region, never one per measured line. Since 0.22.0 a slide with several eligible regions has one native body each (the first is the Body placeholder).

Reimport reads the current native paragraphs and runs. Body objects carry no per-line recovery tags or cached source words. Empty body prompts are skipped; removed objects stay removed. Explicit body placeholders cannot become inferred titles or subtitles when a title is cleared. Existing provenance checks keep edits authoritative and diagnose changed geometry/content instead of recreating deleted content. The native body reader's existing limitations still apply, including mixed bullet/nonbullet edits and native styles that OPF cannot represent.

Qualification must separately check Keynote's actual Title/Body controls, coherent appended text/list items, save/export/reopen and current-content reimport. Archive structure and passing local tests establish none of those native UI or raster claims. Direct `.key` output and advanced effects are outside scope.

## Wrapped titles, several bodies and numbered lists (RR-88)

Under `bodyText: "native"` a plain-string title that wraps over several lines (no hard break, no overflow, no rich runs, no right-to-left line) is one text box holding the whole title, with native wrap (`wrap="square"`), `<a:noAutofit/>`, the measured line pitch as exact spacing and the block its measured lines fill as its frame. It is bound to the Title placeholder like a one-line title, so Keynote's Title control and `title showing` work on every slide (they were `false` on a slide whose title wrapped, because only a one-line title bound). It carries one heading line tag (`count: 1`) and imports as the current words. Titles with a hard break or an overflow keep the measured lines.

A slide with more than one text, list or bullets region now gets one native body per eligible region instead of falling back for all of them. The first is the Body placeholder; every further one is an ordinary text box named `OPF native body <path>` at its region (a layout has one Body placeholder). A region that cannot be native keeps its measured shapes and its own `native-body-fallback`. Groups and cards still fall back.

A numbered list is native when its entries are one sequence: every entry has a number of the same style and suffix, counting up by one from the first (`numbering: 'arabic'`, `{style, start, suffix}`). Every paragraph then carries the same `a:buAutoNum` scheme and `startAt`, so PowerPoint and Keynote count them. An entry with its own `start` is not one sequence and keeps the measured list (`unsupported-list`). Import reads native auto-numbers as before.
