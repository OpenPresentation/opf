# Native body prototype

`toPptx(document, {bodyText: "native", onDiagnostic})` opts in to a single coherent paragraph or flat-bullet body per slide. Omit `bodyText` or use `"measured"` for the existing measured-line output. This is a source prototype, without a native Keynote or PowerPoint acceptance claim.

An automatic slide must have exactly one body leaf. A named layout must have exactly one unshared paragraph/list region; other image, metric, chart or table regions can retain their existing export. One actual `p:sp` holds the complete body, with authored hard paragraph breaks, normal rich runs and native wrapping. No measured soft wraps become source paragraphs. Selected font families, run sizes, explicit normal/bold/italic values, colors, supported links, effective alignment and the region's vertical anchor remain explicit. Blank and appended paragraphs receive selected typing defaults. The body disables autofit rather than shrinking text.

Plain text and basic rich runs are eligible. Flat level-zero character bullets are eligible. Groups, cards, multiple/shared bodies, right-to-left paragraphs, tabs, unsupported run effects, annotations, picture bullets and numbered lists retain measured shapes and report a path-specific `native-body-fallback`. A list with descriptions or nested entries (qualification case K04), or with multiple composed columns (K06), also falls back explicitly. Content is never summarized or flattened to qualify.

The native object uses its allocated body frame, with title and furniture space retained. Native applications choose their own line breaks, baselines and overflow behavior, so the result can differ from the measured preview. Later edits can overflow that fixed frame; the prototype does not silently shrink or repaginate them. Native paragraph separators can normalize to LF on reimport. Title export is unchanged: accepted one-line plain titles bind to genuine title placeholders, while long or rich titles retain measured shapes.

Only selected native bodies receive a layout variant. The original OPF catalog record, reference and hash stay intact; the variant identifies its actual body placeholder index. An eligible automatic slide uses a separate title-and-body `tx` layout, while default automatic slides keep `titleOnly`. There is one meaningful body placeholder per eligible region, never one per measured line. Multiple native bodies on one slide remain outside this prototype.

Reimport reads the current native paragraphs and runs. Body objects carry no per-line recovery tags or cached source words. Empty body prompts are skipped; removed objects stay removed. Explicit body placeholders cannot become inferred titles or subtitles when a title is cleared. Existing provenance checks keep edits authoritative and diagnose changed geometry/content instead of recreating deleted content. The native body reader's existing limitations still apply, including mixed bullet/nonbullet edits and native styles that OPF cannot represent.

Qualification must separately check Keynote's actual Title/Body controls, coherent appended text/list items, save/export/reopen and current-content reimport. Archive structure and passing local tests establish none of those native UI or raster claims. Direct `.key` output and advanced effects are outside scope.
