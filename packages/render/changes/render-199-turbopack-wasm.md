render#199: a Next.js app that imports `@openpresentation/opf-render` and `/fonts-node` builds with Turbopack and no `next.config`. Since RR-64 and RR-65, `next build` failed because Turbopack compiled `harfbuzzjs/dist/harfbuzz.wasm` (located with `require.resolve`) as a WebAssembly module; and in a server bundle, the font packages (`require.resolve` of a computed name, which a bundler turns into a stub that always throws) and the vendored `fonts/` directory (`new URL` with a computed path) were not found. The Node entries (`/fonts-node`, `/preview-fonts-node`) now locate these files at run time through Node's own resolution, in a form bundlers leave alone, so a Next.js server (Turbopack or webpack, route handler or server component) renders the same bytes as plain Node: subset faces, HarfBuzz-shaped outlines and the office pack. Plain Node output is unchanged. `loadFonts` now reports `harfbuzz-unavailable` through `onDiagnostic` when a harfbuzzjs `.wasm` cannot be loaded (a deployment that did not ship the package) and still loads the fonts, with whole faces and fontkit shaping; a missing file used to reject `loadFonts`. `npm run test:next-bundle` builds and serves such an app against the packed package.
