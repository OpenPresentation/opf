render#191: dependency refresh. The script and emoji font pins move to `@expo-google-fonts/noto-sans-jp`, `-kr`, `-sc` and `-tc` 0.4.4, `noto-color-emoji` 0.4.7 and `noto-emoji` 0.4.8 (optional peers; `src/font-manifest.js` re-pinned, licenses unchanged and verified OFL-1.1). The Noto Sans JP and KR faces are rebuilt files of the same 2.004 release with the same outlines and advances and renumbered glyph ids, so over the core examples and the script corpora SVG with embedded fonts and the raster goldens are unchanged; text-as-paths glyph ids (`opf-g-<face hash>-<glyph id>`) and the vector PDF's six-letter subset tags change for Japanese and Korean text. Noto Color Emoji moves from 2.051 to 2.057 (nine new emoji, redrawn glyphs), so a slide that embeds or exports it changes bytes. `<opf-deck>` thumbnails: the slide drawing is no longer inside the thumbnail button but under it, so the button's name ("Go to Slide 2 of 5: Agenda") is not contradicted by the slide's own text (WCAG 2.5.3, axe-core 4.14 `label-content-name-mismatch`); the strip looks and behaves the same (a host that paints a background on `::part(thumbnail)` now paints it over the drawing). `harfbuzzjs` 1.6.3 (HarfBuzz 14.6.0): shaping is unchanged (text-as-paths byte-identical over the examples and script corpora); hb-subset writes some `cmap` subtables differently, so 70 of the 807 example SVGs with embedded subsets change by a few bytes (same glyph mapping, same pixels). Development dependencies: `axe-core` 4.14.0, `@napi-rs/canvas` 1.0.10, `pdfjs-dist` 6.4.299.
