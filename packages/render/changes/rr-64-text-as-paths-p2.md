RR-64 phases 2 and 3 (output-changing for `textAsPaths: true` only): outlined text is shaped by HarfBuzz, the browser's shaper (`harfbuzz.wasm` of the pinned harfbuzzjs; the Node handle always, a browser handle given `loadFonts({ shapeWasm })`), so outlines in Bengali, Thai, Lao, Khmer, Myanmar, Syriac and Japanese with combining marks draw what the browser draws (fontkit picks other glyphs on 10 of the 140 corpus samples). Runs fall back to text one by one, reported as `text-as-paths-fallback` with a `reason` (`colour-font`, `restricted` for an fsType that restricts embedding, `shaping` for an unpinned run on which HarfBuzz and the layout's measurement disagree); this replaces `text-as-paths-kept-text`, which kept a whole element as text. Accessibility: the glyphs are hidden from assistive technology and each outlined line is also invisible real text pinned to the drawn width, so screen readers read text (no more `role="img"` labels), and selection, copy and find-in-page work; an outlined slide stays about 40 KB (opf-render#164).
