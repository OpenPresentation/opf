RR-55 (breaking, with core 0.14.0; old names are deleted, not aliased; output-neutral: every golden raster hash is unchanged): one fonts handle, whole-deck and one-slide render functions, and core's slide context. `renderSvg(deck, options)` now returns `string[]`, one SVG per slide (it was `renderSvgDeck`); `renderSlideSvg(deck, index, options)` returns the SVG of one slide (it was `renderSvg(deck, { slideIndex })`, and `renderSvgDeck` and the `slideIndex` option are removed). `loadFonts(options)` from `/fonts-node` and `/fonts-browser` (the environment is the subpath) replaces `prepareNodeFonts`, `loadOfficeFontRegistry`, `loadBundledFontRegistry`, `loadBrowserFontRegistry` and `createFontRegistry`; it keeps the pack, substitution-policy and script options, adds `pack: "none"` (only the `faces` you supply, a browser handle's `faces` are the entries `loadBrowserFontRegistry` took) and returns `{ textMeasurement, embeddedFonts, fontFiles, useBundledFonts, loadSystemFonts, registry, manifest, substitutions, ensure(presentation), pending(presentation) }` (a browser handle adds `dispose`). `ensure` loads the script (and, in a browser, vendored) faces a presentation needs and replaces the browser font gate; `registry` keeps the lower-level `ensureLazyFonts`, `ensureScripts`, `pendingLazyFonts`, `pendingScripts` and `loadScripts`. `createFontRegistry` and `pickFace` live in the internal `font-registry.js`, which is not an entry point.
    - Every deck-level function takes `{ fonts }` instead of the spread bag: `renderSvg`, `renderSlideSvg`, `resolvePresentation`, `svgToPng`, `svgToPdf`, `/export-browser` (`svgToPdf` embeds the handle's faces), `present` in `/player`, `<opf-deck>` (its `fonts` property takes the font root URL or a handle; `fontRegistry` is removed) and `renderDeckHtml` (a `fonts` object draws the markup, a string is the font root URL). The top-level `textMeasurement`, `embeddedFonts`, `fontFiles`, `useBundledFonts` and `loadSystemFonts` options are removed and, like any unknown option, not read: pass `{ fonts }` (`fonts: { loadSystemFonts: true }` still opts raster output into system fonts).
    - A slide's canvas, layout, theme, colour scheme, font scheme and family names come from core `resolveSlideContext` (slide design, then deck design, then theme, then the default) instead of a copy of that chain, and whether the background is dark (`darkBackground`) is core's decision too; host `catalogs` and `catalogSources` still reach it in the renderer's order. A slide with no `layout`, or one that names an id no catalog has, composes with no layout record (the inferred `text-1x`, `chart-1x` and similar layouts are gone: they composed identically on every corpus slide); `resolvePresentation(...).slides[i].layout` is then undefined. An unknown layout, theme, colour scheme or font scheme id no longer throws `catalog-resolution-failed`: core falls back and the render reports `unresolved-layout`, `unresolved-theme`, `unresolved-color-scheme` or `unresolved-font-scheme` through `onDiagnostic`.
    - `OPFRenderError('invalid-opf')` carries `findings` (the error findings of core `validate(deck, { only: ['format'] })`, also `details.findings`; `details.report` is the whole report) instead of `issues`; layout-overflow and variable errors carry `diagnostics` in `details`.
    - Core names: the layout engine, script fonts, direction, patterns, code colouring, trend marks, chart options and chart data are imported by name from `@openpresentation/opf/composition` (a missing export now fails at load instead of switching RTL text, script fonts, pattern fills, code colours, chart options or numbered lists off; `test/core-features.mjs` pins them). `/fonts` re-exports core's own `FONT_POLICY` (the table: `.families`, `.provisionalDecisions`, rows with `sources` and `note`), `fontPolicyFor`, `isSymbolEncodedFamily`, `symbolCodeOf`, `mapSymbolText` and `scriptFontRole`; the renderer's snapshots `src/font-policy.js` and `src/symbol-encodings.js`, their generators, the CI snapshot check, `FONT_POLICY_SOURCE`, `FONT_POLICY_DECISIONS`, `SYMBOL_ENCODINGS`, `SYMBOL_ENCODINGS_SOURCE` and `symbolEncodingFor` are removed (the symbol advances now come from core's table).
    - Removed legacy: the guards for a core without `resolveScriptFonts`, `paragraphDirection`, `patternRuns`, `metricTrendMark`, `tokenizeCode`, `resolveChartOptions`, `resolveChartData`, `chartPaletteForFill`, `glyphFallbackFamilies` and `resolveVariables` (and the diagnostics `language-preview-unavailable` and `paragraph-direction-unavailable`), and the hand-drawn pattern approximations. The browser `createFontGate` in `deck-runtime.js` now takes a fonts handle.
