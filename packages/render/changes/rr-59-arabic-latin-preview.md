RR-59 (#175, output-changing for right-to-left text with runs in more than one script): three preview defects in Arabic text with Latin phrases, which PowerPoint does not have when it opens the PPTX written with the same fonts handle. (1) The space at an Arabic/Latin run boundary is kept: a positioned right-to-left run used to keep its trailing space inside its isolate, where bidi rule L1 drew it at the run's right edge, so `الإصدار PowerPoint 365` drew as `الإصدارPowerPoint 365`; the run now draws without that space, after its measured advance. (2) and (3) A mixed-script line of a list entry (core places no origin for it) positions each script run at its measured advance, as a placed line does, instead of drawing one unpinned chunk of nested runs: resvg shaped such a chunk with the Latin face and then replaced every glyph with a fallback face that covered all of it, so the Latin phrase drew wider than measured in that face and ran into the right-to-left bullet. Core's composition and the PPTX export are unchanged.
