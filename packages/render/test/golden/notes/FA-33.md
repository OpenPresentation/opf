# FA-33: layouts as one list of regions

No slide changes. Core FA-33 (opf#756) replaces the layout record's `areas` grid, `columns`, `rows` and `regions` map with `direction` plus an ordered `regions` list, and Gallery 5 carries the 28 records in that form. Core compiles the list into the grid it composed with before, so every composed box, and therefore every pixel, is the same.

What moves is the digest of the input, not a rendering:

- **Example baseline.** `source.sha256` of core's `scripts/fixtures/opf-examples-png.rr96-color-variants.sha256.json` (core's change, selected through `ecosystem.lock.json`) is the digest of the converted example corpus. Rendering the corpus with this branch's core and Gallery 5 against that fixture's entries: 818 slides, 0 changed (`test/golden.mjs`, `diff.json`: `changedSlides: []`, `sourceMatches` false only for the digest before core's fixture update).
- **Template baseline.** `test/golden/layout-templates-rr96-color-variants.json` changes in one field, `source.sha256` (the digest of the 28 Gallery records the fixture serializes: 573a7d23... to 0f2637e8...). Its 495 `entries` (SVG and PNG hash, bytes) are untouched: `node test/layout-template-goldens.mjs --update` with Gallery 5 reports 0 changed slides against it.

Review: the digest was changed by hand because no pixel hash moved and the regeneration workflows rewrite hashes, not an input digest; the 0-changed result above is the evidence.
