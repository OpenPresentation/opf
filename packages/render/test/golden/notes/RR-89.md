# RR-89, RR-90, RR-92: chart series palette, chart text size and value axis (pending baseline)

Status: against published core 0.22.0 (`chartSeriesPalette` with `chart.colors`, the dark-panel palette tiers,
`chartTextSize` and the composed `chart.valueAxis`). The example baseline is the new directory
`test/golden/opf-examples-png.rr89-chart-palette-text/`, started as a byte-exact copy of core's `golden` fixture at the locked
core (`opf-examples-png.rr20-array-areas.sha256.json`, 807 slides, same source digest) and selected by `ci.yml`'s
`golden-override`; the `regenerate-goldens` workflow rewrites only the decks that differ. The template baseline is
`test/golden/layout-templates-rr89-chart-palette-text.json`, written by `regenerate-candidate-goldens` and selected by
`scripts/template-baseline.mjs` when core draws table text above 16 px and chart text above 16 px (never copied from a local run).

## Reviewed result

- **Example baseline.** `test/golden/opf-examples-png.rr89-chart-palette-text/` started as a copy of the `rr90-first-use-layout`
  directory (which keeps its bytes) and was regenerated by `regenerate-goldens` run 39173844510: 110 of 128 decks, only chart
  slides; selected by `ci.yml`'s `golden-override` and by `scripts/example-baseline.mjs` when core draws chart text above 16 px.
- **Template baseline.** Against `layout-templates-rr90-first-use-layout.json` 19 of 495 slides change, all charts: `chart 1-3 short`,
  `chart 1 long`, `chart 3 long`, `chart-beside 1-6 short`, `chart-beside 1-6 long`, `dashboard 1 short` and `dashboard 1 long`
  (a local macOS candidate; the committed baseline comes from `regenerate-candidate-goldens`, never from a local run).

What moves, measured by rendering the 807 slides of the examples (core 0.20.5 for `main`, the linked core builds with #708, #716, #710, #718 and the RR-90 size for this branch, before core 0.21/0.22 were published) and
comparing the traced SVG (not PNG hashes, which only the pinned image produces):

- 151 of the 156 slides that draw a chart change; 0 of the 651 other slides change. The five chart slides that do not
  move already drew at the new size or the floor and use series colours that did not change: two decks whose
  `minFontSize` (17 and 18) sits at or above the chart size (`gallery/industries/airline-disruption-recovery-review.opf.json#6`,
  `gallery/presentation-types/manager-training-deck.opf.json#6`) and sheets of small charts at the 16 px floor
  (`technical/block-composition.opf.json#0`, `technical/chart-type-sampler.opf.json#0` and `#1`).
- Chart text: 20 px (15 pt) instead of 14 px floored to 16 px (12 pt), shrunk only for a small chart box (at most 1/18 of
  the box height and 1/30 of its width, whole pixels, never below `minFontSize`). Category labels that no longer fit rotated
  now skip (`test/chart-category-labels.mjs` records the new decisions).
- Series colours: core's `chartSeriesPalette` of the deck colour scheme. The default scheme's first six colours equal the old
  list; the 7th to 12th are tints of them instead of the old distinct hues.
- Value axis: core's composed axis. With the text size held at the old value, only 6 of the 156 chart slides differ
  from the renderer-side scale, each by one 1/2/5 step in a short or narrow plot (core estimates the plot from the box,
  the renderer from the laid-out plot): `gallery/business-functions/engineering-capacity-planning.opf.json#2`,
  `gallery/business-functions/investor-relations-update.opf.json#6`,
