# FA-31: header and footer variables move no pixel

Core's FA-31 rewrites the example decks' header and footer zones from `organization: true`, `speaker: true`, `section: true` and `slideNumber: true` to one `text` with `{{organization.name}}`, `{{speaker.name}}`, `{{slide.section}}` and `{{slide.number}}`. The renderer draws a zone's `text` as one furniture part (`data-opf-furniture-field="text"`) instead of one part per flag.

**No slide hash changes.** Rendering the migrated core examples (core `d20249d4`) with this renderer and comparing against core's `opf-examples-png.fa-wave-c.sha256.json` (the lock's golden) gives 807 entries on each side and `changedSlides: 0`, and the same against `opf-examples-png.cover-centering`. Hashes were computed on Windows with Node 26.4.0 at scale 0.25 (the earlier baselines reproduce byte-for-byte across platforms); CI in the pinned Linux image is the check of record.

Only the corpus digest moves (the example decks changed, the pictures did not). CI selects core's golden through `ecosystem-refs`, which core's FA-31 pull request regenerates, so this renderer baseline keeps the core 0.16.0 corpus digest until the release-prep pull request moves it, as RR-20 did for 0.16 (`RR-20-core-0-16.md`).
