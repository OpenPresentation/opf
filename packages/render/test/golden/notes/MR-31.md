# MR-31: goldens in the monorepo (digest `70b9e5d4` against `22ebe285`)

No slide changes: 818 of 818 slide hashes are exactly those of `opf-examples-png.rr97-example-assets`. What moved is the digest of the input, and why it differed was understood, not tolerated.

## The mismatch

`test/golden.mjs` and `test/golden-gate.mjs` failed in the first monorepo run with "Golden corpus changed": the default baseline (`rr97-example-assets`) records the examples digest `22ebe285...` (129 decks), the workspace's `examples/` digests to `70b9e5d4...` (129 decks). It is the corpus digest, not a pixel: every rendered slide matches.

- **Cause.** Core FA-33 ([opf#756](https://github.com/OpenPresentation/opf/pull/756)) rewrote the layout records embedded in the example decks from the `areas`/`columns`/`rows`/`regions` grid to `direction` plus an ordered `regions` list: 101 files (100 gallery decks and `technical/full-feature-tour`). The digest of `examples/` is `22ebe285` at every commit before `d223fc00` (FA-33; checked at `bb914634`, RR-97, and `d223fc00^`) and `70b9e5d4` from `d223fc00` on. Core's own fixture `scripts/fixtures/opf-examples-png.rr96-color-variants.sha256.json` (the one `ecosystem.lock.json` selected) was updated by hand for FA-33 and already records `70b9e5d4`; the renderer's baseline lived in another repository and still recorded the pre-FA-33 digest. The old coordinated CI compared the examples with core's fixture (selected by the lock), never with this baseline, so no old run met the stale digest.
- **Not a wiring bug.** `@openpresentation/opf` and `@openpresentation/gallery` resolve to the workspace packages (`packages/javascript`, `packages/gallery`), the render fonts are the package's own and `systemFonts` is false, the gallery is the 0.26.0 workspace package (`packages/gallery`), and the corpus order and paths are the same (`examples/**` sorted, `examples/` stripped). The corpus was rendered with the workspace core and gallery.
- **Evidence.** `node test/golden.mjs --update` in the workspace: 818 slides, 129 decks, `diff.json` `changedSlides: []` against `rr97-example-assets`, and against core's `rr96-color-variants` fixture (the two baselines have identical entries: `818` keys, `0` differing hashes in both directions). The same hashes came out on macOS (a local run); the pinned image's `goldens` job is the Linux confirmation. `test/layout-template-goldens.mjs` (495 SVG and PNG hashes of the 28 layout records) passes with the FA-33 digest already in place.

## What changed

- **New baseline `opf-examples-png.fa-33-region-lists/`**, the default for the variants contract (`scripts/example-baseline.mjs`: `VARIANTS_EXAMPLE_BASELINE`). It was started as a copy of `rr97-example-assets` and `pnpm run golden:update` plus `golden:promote` rewrote it against the workspace corpus: 0 changed slides, 0 changed decks, 1 file written (`_baseline.json`, `source.sha256` `22ebe285...` to `70b9e5d4...`), 129 deck files untouched, byte-identical to `rr97-example-assets`. `rr97-example-assets` keeps its bytes (`VARIANTS_EXAMPLE_BASELINE_PRE_FA33`).
- **Selection.** `scripts/default-baseline.mjs` selects the default in one place for `test/golden.mjs` and `scripts/golden-promote.mjs` (the promoter used to default to `rr81-v2-reviewed`).
- **Core's 17 fixtures** (`scripts/fixtures/opf-examples-png.*.sha256.json`) are deleted: the examples corpus is the input of this directory, and the two fixtures that `scripts/registry-golden.mjs` retained for registry runs were read by no caller. Core's `rr96-color-variants` fixture and this baseline have identical entries, so no information moves with the deletion.

## Review

Visual review of the rendered corpus (two sampled slides at 0.6 scale, one from a deck FA-33 touched and one from `technical/full-feature-tour`): no difference from the approved look is possible with identical hashes; the sample is a sanity check that the corpus draws, not evidence of change. Matching hashes do not establish PowerPoint parity.
