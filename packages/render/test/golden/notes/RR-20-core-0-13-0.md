# RR-20: the default baseline records the core 0.13.0 examples

`opf-examples-png.cover-centering` (the default baseline: the publish workflow and a bare `npm test`) moves from the examples of core 0.12.2 (digest `485b5c07...`) to those of core main, which core 0.13.0 ships (digest `394c4ce7c81821d34a9edacb705aa7703631016563b0b4357475de72d594e155`, 126 decks). 14 of 805 slides change, in two deck files; the other 124 deck files are untouched.

Why: core's RR-20 example decks ([opf#367](https://github.com/OpenPresentation/opf/pull/367)) rewrote the two playground decks `technical/full-feature-tour` (embedded PNG assets, inline chart data, a complete inline colour scheme, the watermark moved to the closing slide) and `gallery/presentation-types/developer-conference-talk` (no deck-wide watermark, a neutral `accent5`, a full-width line chart). The renderer draws them as they are now authored; no renderer change moves a pixel. Coordinated CI has compared these 14 hashes since opf#367 through core's reviewed fixture `opf/scripts/fixtures/opf-examples-png.example-decks.sha256.json` (the lock's golden); the publish workflow installs the registry core and always uses this repository's own default baseline, so without this change `opf-render-v0.13.0` would fail "Golden corpus changed" exactly as `opf-render-v0.12.1` did ([run 37396674784](https://github.com/OpenPresentation/opf-render/actions/runs/37396674784)).

How it was checked:

- Written by the `regenerate-goldens` workflow in the pinned Playwright image ([run 37434810125](https://github.com/OpenPresentation/opf-render/actions/runs/37434810125), commit `08f4fb0`: "2 decks"), rendering the lock's core (`eca44d4`, examples digest `394c4ce7...`).
- The reassembled manifest (`test/golden-store.mjs` `readBaseline`) equals core's fixture byte for byte as JSON: source, version, scale, format, font policy and all 805 entries.
- Locally (macOS, Node 26.7) with renderer main `23553be` and core main `0f929170` (RR-54) linked: `node test/golden.mjs` passes against core's fixture ("805 slides, 126 decks") and, before this change, failed against this baseline only on the source digest and the 14 slides of the two decks. `npm run golden:update` plus `golden:promote` there wrote the same three files as the workflow, line for line.

Merge order: this changes nothing that coordinated CI selects (ci.yml keeps `golden-override: ''`, so the lock's golden stays core's fixture; selecting this baseline earlier broke the registry run on 2026-10-06, see the note `RR-20-core-0-12-2.md` and opf-render#130). Merge it after core 0.13.0 is on npm and before the renderer's 0.13.0 release prep, and first check that the registry core's examples have this digest (`npm pack @openpresentation/opf@0.13.0`, then the digest of `dist/examples.js`'s corpus as `test/golden.mjs` computes it). The comparison is unchanged: exact PNG hashes at scale 0.25, no tolerance; the 0.1 px and 0.15 px gates are untouched.
