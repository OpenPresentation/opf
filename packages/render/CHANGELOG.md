- Fix: slide background colours accept colour references. A solid background `color`, gradient stop colours and pattern foreground/background colours painted white (or the default text colour) for `var:id`, scheme slot names (`accent2`, `dark1`) and role names (`primary`, `secondary`, `accent`); they now resolve through the same core ColorRef rule as table fills and run colours, with the same fallback as an unparseable literal (white, the background role for a gradient stop, the text role for a pattern foreground). Pattern preview change: a pattern whose `foregroundColor`/`backgroundColor` named a slot, role or variable used to draw the default text colour and white; it now draws the resolved colours. Every background colour (solid, gradient stop, pattern foreground and background) resolves roles through the colour scheme only: `background`, `surface` and `text` are derived from the background itself (the contrast text), so they resolve to their scheme slots (`light1`, `light2`, `dark1`), never to the derived text colour. - Charts: dense category axes rotate and skip labels instead of wrapping mid-word. With many categories (49 in a column, histogram-by-category or pareto chart) the x-axis labels used to wrap inside their band into fragments (`Ca` over `t 1` for `Category 1`) and raised one `text-overflow` diagnostic per label. Category-axis labels now mirror PowerPoint's automatic labelling (`src/charts.js`): a label is never broken inside a word (one line, or two lines split at its spaces when the band is too narrow, or an ellipsized single line); labels that do not fit horizontally rotate to -45 degrees, then -90 degrees, shrinking the plot area (at most 40% of the chart height) to make room; and when even that collides the axis draws every n-th label, the smallest n that leaves no two drawn labels overlapping, always keeping the first (ties go to the less rotated arrangement). Applies to column, line and area charts (stacked and 100% too) and the chartex histogram, pareto, waterfall and box-and-whisker previews. Horizontal bar charts and funnels skip rows shorter than a text line, grow the label gutter with the longest label up to 30% of the chart width, and only beyond that wrap at spaces (rows permitting) or ellipsize. Radar spoke labels follow the one-line/two-line/ellipsis rule and drop a spoke label that would collide with one already drawn. No label raises `text-overflow` any more; the only label shortened is one wider than its gutter or the whole chart, reported once per chart as the new diagnostic `chart-label-truncated` (`path` the chart, `labels` the paths of the shortened labels). Rotated labels sit in a `<g transform="rotate(...)">` around their usual text group. opf-pptx is unchanged: it writes an automatic axis text body and no `tickLblSkip`, so PowerPoint chooses its own rotation and skip. Preview-moving: 1 of 805 golden rasters changes in `opf-examples-png.cover-centering.sha256.json` (`technical/chart-type-sampler.opf.json#1`, whose waterfall label `Expansion` broke as `Expansio` over `n`); see `test/golden/README.md`. New test `test/chart-category-labels.mjs` (3/12/49/120 categories with short, long and numeric labels across column, line, histogram, pareto and bar, plus the other axis constructs: no overflow diagnostics, whole words, no overlapping boxes, first label drawn, rotation and skip as specified, byte determinism). New internal `svg.reportDiagnostic` hook for the chart renderer; no public API change.

- FF-49 / FF-50: the preview's East Asian and complex-script slots are pinned to the selections opf-pptx writes into the theme's major/minor `a:ea` and `a:cs`. No engine change was needed: for every catalog font scheme, and a matrix of seven design schemes times nineteen languages, `resolvePresentation().slides[i].scriptFonts.profile` equals the documented rule (an explicit slot, the scheme's own family when its `languageFamily` is the slot and it serves the language, the language's script font when its script uses the slot, otherwise the latin family), no slot is empty, and a language never changes the latin slot. opf-pptx writes a theme slot only where a script font is selected and leaves the others empty as Office does, so the preview's slot equals the theme's family where the theme names one and the latin family where it is empty (checked for all 89 font schemes times all 93 languages). Text in a script draws the slot's selected family first, then the designated open replacement. New `test/theme-slots.mjs`; core `docs/programs/font-fidelity-everywhere/script-font-model.md` ("Language contract", "Theme slots").

- FF-44: Noto Sans Mongolian can be measured and drawn again. Every shaping of the pinned face (@expo-google-fonts/noto-sans-mongolian 0.4.1, Noto Sans Mongolian Version 3.002; all upstream 3.x builds are alike) threw `font-shaping-failed` ("Not a fixed size") for any text, Latin, digits and Mongolian, so the Noto Sans Mongolian font scheme could not be drawn in any host. Cause: the face has one GSUB lookup of type 8 (reverse chaining contextual single substitution) that both `calt` and `rclt` reference in every script; fontkit 2.0.4 (the latest release) cannot decode it (its type 8 struct lacks the `backtrackGlyphCount` field) and has no processor for the type. A lookup fontkit cannot decode now applies nothing (a lookup with no subtables, installed on the font after shaping failed, once per font), so the other calt/rclt lookups still run. Advances equal a browser's for the Latin sample and four of five Mongolian samples within 0.05 px at 100 px, and are 0.9% narrower for a sample with a variation selector (the skipped lookup). Version 2.003 shapes in fontkit but is not usable: its npm package ships no license file, and a vendored script package would break hosts that copy the npm packages. Tests: `test/mongolian-shaping.mjs`, `test/script-fonts-browser.mjs` (Mongolian case, Node advances within 0.1 px of the browser).
- FF-43: Raleway and Playfair Display are bundled, as the copyright holders' unmodified static files. Both reserve their own name, so no instance or subset may carry it, and the variable fonts that Google Fonts serves cannot be used (resvg ignores the weight axis). The upstream projects still publish statics: googlefonts/Raleway 7e0be84 (`fonts/TTF`, Version 4.026) and clauseggers/Playfair 6e115d7 (tag 1.202, `fonts/TTF`, Version 1.202), Regular, Italic, Bold and Bold Italic each (the four styles the policy needs; weights 400 and 700 with correct OS/2 weight and italic bits, no fvar), byte-identical with `upstreamFile { url, sha256 }` and the notice read from each repository's OFL.txt (OFL-1.1, Reserved Font Names "Raleway" and "Playfair Display"). Both repositories are added to the unmodified-upstream allowlist in `scripts/font-license.mjs` (a reviewed change). New manifest packs `raleway` and `playfair-display` (pack `open`, embed "used", lazy in browsers): 20 open packs, 78 open faces, and `registry.lazyFonts` lists 94 faces (was 86). The Raleway and Playfair Display font schemes (and the Bodoni MT and Didot replacement) now preview with their own faces instead of raising `font-unavailable` in Node or falling back to Roboto in the editor. Core's `scripts/lazy-font-counts.mjs` needs the entry for the next renderer version (94). Tests: `test/open-fonts.mjs` (manifest, byte-identical pins, strict resolution, distinct paints), `test/lazy-fonts.mjs`, `test/font-licenses.mjs`.

- FF-22b: native previews for the seven chartex chart types, drawn as the constructs opf-pptx now exports as Office 2016 chartex parts. `treemap` lays out one squarified tile per category of the first series (positive values), one palette colour per tile, category labels inside. `histogram` bins a lone value column like PowerPoint (Scott's rule count, right-closed bins from the minimum, labels `[a, b]` then `(a, b]`) or, with a category column, plots one column per category (Office "by category"); `pareto` sorts the columns descending and adds the cumulative-percentage line on a right-hand 0-100% axis. `box-and-whisker` groups rows by category into one box per series with exclusive quartiles (Excel QUARTILE.EXC), whiskers within 1.5 IQR, mean markers and outlier points, legend when there are several series. `waterfall` draws floating bars from the running total, increases and decreases in the first two palette colours, with connector lines. `funnel` centres bars narrowing from the top with value labels and category labels on the left. `world` (map) draws an honest non-geographic preview: one tile per region shaded from a light tint to the series colour by value, with the region name and value; no geography data is shipped, because PowerPoint draws the real map from Bing geodata it fetches itself. Every mark and label keeps a `data-opf-path` (bins and boxes trace to their value column) and traced chart groups carry `data-opf-chart` with the id; the chartex kinds also accept a lone value column (row numbers as categories, or binned for histogram and pareto). New exports `chartexValues`, `scottBinCount`, `histogramBins`, `squarify`, `boxStatistics`, `mixHex`. 26 of 805 golden rasters change in `opf-examples-png.cover-centering.sha256.json`, all chartex chart slides; see `test/golden/README.md`. No package version change.
- FF-19: `scripts: 'auto'` in Node keeps the Latin Noto Sans as a designated replacement when the presentation selects `Latn`. A Sylfaen scheme (and the Armenian and Georgian language values that use it) has Noto Sans as its replacement, but the office registry loads Noto Sans as a fallback-only face, which answers to its own name and to glyph fallback and is never another family's replacement, and `auto` skipped the package because it was already loaded. Node raised `font-unavailable` for Sylfaen while the browser registry (`ensureScripts` loads the package itself) drew it. `loadOfficeFontRegistry` now leaves the packages that `autoScriptSelection(presentation).scripts` selects out of the fallback-only load, as an explicit `scripts` list already does; a presentation that does not select `Latn` is unchanged (Noto Sans stays fallback-only). No PPTX, golden or example change. Test: `test/lazy-face-fallback.mjs` (Sylfaen with Latin, Armenian and Georgian text under visual substitution; fails before the change). They activate when this package moves to a core release that includes FF-35b, or when core ecosystem CI pins a commit that contains this test (see opf `docs/design-resolution.md`, "Sibling agreement checks"). All 805 example SVGs and 805 golden rasters are unchanged. No package version change.
- FF-39: titles follow only `design.titleAlignment`. When it is unset, a title is left-aligned, the same as core composition. Previously, a title without an accepted outline placement fell through to `design.contentAlignment`. A deck that set `contentAlignment: "center"` but no `titleAlignment` therefore previewed centered titles with the default measurement and left titles with outline measurement, and exported them left-aligned. Subtitle, tag and body text still follow `contentAlignment`. `test/design-preview.mjs` checks the anchors with both estimated and outline measurement. No bundled example sets `contentAlignment` without `titleAlignment`, so the 805-slide golden corpus is unchanged. Some pptx.gallery layout previews (chart/list/number `Nx`) do change.

- FF-35: fall back to the shared engine default font scheme, `aptos` (`engineDefaults.fontScheme.pptx.latin`, core `DEFAULT_FONT_SCHEME`), instead of `roboto` when the slide, deck and resolved theme name no font scheme. Previews of a custom theme without a font scheme now use the fonts that core pagination, opf-editor and opf-pptx use. Aptos is not bundled: estimated SVG names `Aptos`/`Aptos Display` and the default raster draws Roboto, as for any `aptos` deck; measured previews need the office pack with `substitutionPolicy: "visual"` (Carlito, approximate), licensed Aptos faces, or a `fallbackFamily`, and otherwise fail with `font-unavailable`. `engineDefaults.fontScheme.google` stays for a future Google Slides target. - FF-34: pass the socialPlatforms records to core composition (document source, injected `options.catalogs`, engine source, then bundled), so `socials: true` header/footer zones preview the primary organization's profile URLs. Requires a core build with `resolveSocialProfile`. Older cores ignore the option. Decks without `socials: true` render byte-identically; golden baselines are unchanged.

- FF-19: script fonts, `lang` and right-to-left text in previews. The renderer itemizes text by Unicode script. Each run is measured and drawn with its script slot's face, resolved by core `resolveScriptFonts` when the installed core provides it. Proprietary script fonts are previewed with designated open Noto replacements, recorded as `visual` substitutions. The SVG root carries `lang`/`xml:lang`, and measurement uses the matching OpenType language system. Direction is per paragraph, from core's `paragraphDirection(text, deckDirection)` (core #134), the rule the exporter uses: right to left when the deck is right to left and the first strong character is right to left, or there is none. Without that function, paragraphs are left to right, as in export, and `paragraph-direction-unavailable` is reported. Every wrapped line of a right-to-left paragraph is a Unicode isolate, and measured fragments are placed from the right edge. CJK punctuation and fullwidth forms, and language-dependent quotes, dashes and ellipsis, use the East Asian slot, while ASCII neutrals use the latin slot next to East Asian text. The text's role picks heading or body slots. Without core `resolveScriptFonts`, a document with a `language` reports `language-preview-unavailable`.

- When fontkit cannot apply a mark-positioning lookup (a null anchor, for example the Gurmukhi tippi in Noto Sans Gurmukhi), the text is measured again without mark positioning, which does not change advances. If that also fails, measurement throws `font-shaping-failed`.
