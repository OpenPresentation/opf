## 0.11.3

- Release 0.11.3 (patch: classic chart previews; no API change, no option removed, core floor stays `@openpresentation/opf` ^0.11.2). The preview draws every kept classic chart type natively, deprecated chart ids draw as their replacement, and value axes scale like Office, so the SVG, PNG and PDF output of slides with charts changes; other slides are unchanged. The vendored face list is unchanged (`registry.lazyFonts` still lists 86 faces, as in 0.11.2). Details in the FF-22b entry below.

- FF-22b: preview every kept classic chart type as the native construct opf-pptx exports. Chart ids resolve like the exporter: the 26 kept core ids, the 50 deprecated ids to their replacement (they render identically), `donut` to `doughnut`; other ids keep the legacy single-series preview. Column/bar render clustered, stacked (positive and negative values stack separately) and 100% stacked (0-100% axis, `%` tick labels); bar charts put the first category and series at the bottom, like PowerPoint. Line and stacked line (cumulative) render with or without circle markers; area, stacked area and 100% area are filled. Pie and doughnut plot the first series only, one colour per category, clockwise from 12 o'clock, doughnut hole 50%. Scatter uses a numeric X axis from `columns[1]` and Y series from `columns[2..]`, markers only. Radar, radar with markers and filled radar are drawn on a web grid. Value axes use Office-like 1/2/5 automatic scaling (zero stays on the axis unless every value is positive and the range is under a sixth of the maximum, mirrored for negative data, identically for line, column, bar and area; bars and area fills then start at the drawn axis edge; stacked totals always include zero); legends sit on the right (PptxGenJS `legendPos r`) when there is more than one series, and per category for pie and doughnut. Series colours use the opf-pptx `CHART_COLORS` order with the same surface-contrast adjustment. Every mark and label keeps a `data-opf-path`; traced chart groups carry `data-opf-chart` with the resolved id. Chartex types (treemap, histogram, pareto, box-and-whisker, waterfall, funnel, map) still use the legacy preview. Preview-moving: classic charts render natively, and deprecated ids (sparkline, bullet, dot-plot, dumbbell, high-low, 2x/3x variants and the rest) draw as their replacement instead of the legacy single-series preview. Finite-range charts are safe: value scales at subnormal and near-maximum magnitudes terminate with finite geometry (#46), and stacked, percentage, pie and doughnut totals outside the finite range throw a `RangeError` naming `slides.0.chart` instead of hanging or emitting invalid SVG. New tests: `test/chart-types.mjs`, `test/chart-scale.mjs`, `test/chart-axis.mjs` (rewritten from the legacy five-tick assertions to the Office-like scale; it keeps its name because the core packed-ecosystem harness runs it by name) and `test/chart-catalog.mjs`, which checks the kept ids, deprecated map and barDir/grouping/marker/radarStyle against core `catalogs.chartTypes`. 115 of 805 golden rasters change in `opf-examples-png.cover-centering.sha256.json`, all of them chart slides; see `test/golden/README.md`. No package version change.

## 0.11.2

- Release 0.11.2 (patch: additive automatic script selection and diagnostic detail; no export change, no option removed, core floor stays `@openpresentation/opf` ^0.11.2). `scripts: 'auto'`, `pendingScripts` and `ensureScripts` also load the script faces a font scheme itself names, and `missing-glyph` reports `details.loadedFaceHasGlyph` and how to load the script font. The vendored face list is unchanged (`registry.lazyFonts` still lists 86 faces, as in 0.11.1). Details in the FF-19 entry below.

- FF-19: `scripts: 'auto'` also loads the script faces a font scheme itself names, and `missing-glyph` says what to load. A deck whose scheme is a script font (Yu Gothic, Meiryo, Malgun Gothic, Microsoft YaHei, Arabic Typesetting, Mangal or a pinned Noto family) previews even its Latin text with that font's open replacement, but auto loaded a face only for drawn characters, so such a deck raised `font-unavailable` (Latin text, a slide that overrides the scheme, or Han-only text with English as the language, where only Noto Sans SC loaded). `autoScriptSelection().scripts`, `pendingScripts` and `ensureScripts` now include the scripts the deck's (and each overriding slide's) heading and body schemes need, and Han-only text in a deck whose scheme names a CJK face uses that face instead of loading a second one; `detected` still lists only what the text draws. The `missing-glyph` message and `details.loadedFaceHasGlyph: false` say when no loaded face has the character (the script face is not loaded: `scripts: 'auto'` with the presentation in Node, `registry.ensureScripts(presentation)` in a browser); the default Aptos scheme (Intos, embed "used"), Carlito and Open Sans fail the same way without a script face and fall back to Noto Sans JP, SC or Arabic once it is loaded, in either load order. No change to the PPTX, to golden output or to decks whose scheme is a Latin font. Tests: `test/lazy-face-fallback.mjs` (Aptos, Calibri and Open Sans with Japanese, Han, Arabic, Greek and Cyrillic; script-named schemes, slide overrides, the selection API) and `test:lazy-face-fallback-browser` (lazy Intos and Open Sans plus lazy script faces in both orders, painted within 0.1 px of the measured advances).

## 0.10.0

- Release 0.10.0 (minor: several intentional preview-output changes, no public export removed). Require `@openpresentation/opf` ^0.11.1, which supplies the shared contracts this renderer consumes: the font policy table, `resolveScriptFonts()`, `paragraphDirection()`, `resolveFontSchemeReference()`, per-item `alignment`, formatted slide-number/date furniture with the host `date` option, `resolveSocialProfile()` and `geometry.slideImage`. Intentional output changes since 0.9.0, each described below: Aptos previews in Roboto instead of Carlito; Cambria is reported as a visual (not metric) Caladea replacement; titles follow only `design.titleAlignment` (left when unset); centered and right-aligned metric lines anchor at their accepted edge; an unknown font-scheme id falls back to `aptos` with a diagnostic instead of throwing `catalog-resolution-failed`. The golden baseline now defaults to `opf-examples-png.ff25-wdupdiag.sha256.json`, matching core 0.11.1's `wdUpDiag` example corpus; the 805 slide hashes are unchanged. The default `index.d.ts` declarations now include the `date` and `textRasterPadding` render options, `ResolvedSlide.scriptFonts`/`textMeasurement` and the language and direction diagnostic codes, which only the browser entry's `svg.d.ts` declared before.
- FF-38: pin the missing-image placeholder as the contract opf-pptx exports. `test/image-placeholders.mjs` asserts the dashed 1 px panel, the centered semibold 20 px `Image unavailable` label over the description (alt, else title, else `Image`) and the group's `Image unavailable: <description>` accessible name. The preview is unchanged. Before, opf-pptx drew a plain `Image` label at 11 pt, so the gallery parity harness failed the text check for all 15 image-treatment values that have no assets.

- FF-31: the renderer now chooses preview replacements from a snapshot of the core OPF font policy table. The snapshot is `src/font-policy.js`, generated from opf `spec/reference/font-policy.json` by `scripts/update-font-policy.mjs`, with a `--check` option for drift. It exports `FONT_POLICY`, `FONT_POLICY_DECISIONS`, `FONT_POLICY_SOURCE` and `fontPolicyFor`, and `FONT_COMPATIBILITY` is derived from it. Legacy rules stay only for families that the table does not list, and the FF-19 script replacements are unchanged.
  - **Provisional owner decisions (owner may revise):**
    - Aptos → Roboto, measured at a 2.15% mean width difference (signed +0.1%). Before, Aptos previewed with Carlito, which is 7.1% narrower. Aptos Display keeps Carlito.
    - Segoe UI → Red Hat Display.
    - Cambria → Caladea reclassified as visual: advances differ from Cambria 6.99 by a mean of 2.7%. Before FF-31, metric mode, including the default `loadOfficeFontRegistry()`, resolved Cambria to Caladea as metric at weights 400 and 700, upright and italic, and threw `font-unavailable` at any other weight. The decision's `metricModeFallback` keeps exactly that coverage in metric mode, now reported as visual: weights 400 and 700, upright and italic, with exact Caladea faces. Every other weight still throws `font-unavailable`, as Calibri 500 does. Visual mode previews every Cambria weight.
  - **Georgia → Gelasio is metric with ligatures off.** Basic-Latin advances are identical, but with default features Gelasio ligates fi, fl, ffi and ffl and runs differ by up to 1.02%. The policy row lists `disabledFeatures: ["liga", "clig"]`, so the registry shapes Gelasio with those features off (`disabledFeaturesFor(family)` exposes the list) and the SVG output puts `font-variant-ligatures:none;font-feature-settings:'liga' 0,'clig' 0` in the `style` of `text`/`tspan` elements drawn with it. Measured that way the policy finds no difference against Georgia 5.59 (mean and maximum below 0.01%, four styles), so metric mode now resolves Georgia to Gelasio at weights 400 and 700, upright and italic. The rule applies to the face, so Gelasio requested by name is also shaped and drawn without ligatures. resvg (PNG and PDF) ignores both CSS properties, so only when rasterizing (never in the emitted SVG) the renderer puts a zero-width non-joiner after each f that a ligature would join to f, i or l, in text drawn with such a face; glyphs then follow the measured advances (ink width 158.25 against 158.86 measured for "office file fluffy" at 24px, 154.75 without it). Nested runs in another family go back to default shaping in the SVG, and a flow line's outer text element no longer carries the style, so other faces do not inherit it.
  - **Consolas and Aptos Mono keep Cousine**, which has all four styles, so bold italic code stays italic. Roboto Mono is an alternate.
  - **Alternates are always visual.** Only a row's declared replacement can carry its metric claim. Metric mode never uses an alternate, for example Liberation Sans for Arial; visual mode uses it and reports it as visual.
  - **Bundled fallback, no new downloads:** no new font packages are added. When a declared replacement's pack is not installed, the renderer uses the row's alternates, which end with the best measured face already in the base or office pack. For example, Segoe UI previews with Arimo. `registry.substitutions` records the face used and its tier.
  - **Caller faces:** `prepareNodeFonts`, `loadBundledFontRegistry` and `loadOfficeFontRegistry` accept caller-supplied `faces` (`data` or `path`), such as a licensed Aptos. These resolve as exact faces.
  - **Resolution details:**
    - `FontResolution.substitute` says whether the face is the chosen family itself. `textMeasurement.resolveFont` exposes it, so exporters keep the chosen family.
    - Resolutions also carry `decision`, `measured` (for the declared replacement), `licenseClass` and `availability`.
    - A family whose name encodes a weight selects that weight in the replacement.
    - A visual replacement that has no italic draws upright and reports `styleFallback`.
  - **Strict mode** never falls back silently. `font-unavailable` names the license class, the declared replacement and tier, the candidate packs and the `faces` hook.
  - **Tests:** new `test/font-policy.mjs`. Updated for the policy change: `office-fonts`, `font-outlines`, `font-preparation` and `default-font-scheme`. The accepted-text browser fixtures now choose Carlito explicitly.

- FF-19: script fonts, `lang` and right-to-left text in previews. The renderer itemizes text by Unicode script. The SVG root carries `lang`/`xml:lang`, and measurement uses the matching OpenType language system. Direction is per paragraph, from core's `paragraphDirection(text, deckDirection)` (core #134), the rule the exporter uses: right to left when the deck is right to left and the first strong character is right to left, or there is none.
