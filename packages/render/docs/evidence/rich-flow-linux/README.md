# Cross-platform accepted rich advances

The initial natural-spacing candidate passed Mac browser tests but exposed a pre-existing measured-advance difference in Linux Chromium. Exact before commit `b953dc50ebc8d33b52285efbaa7fc9d35459eec6` and CI run `34525725224` are retained for both Node 20 and 24. Estimated natural-flow gaps remained below 0.001px. Measured gallery gaps reached 3.025px and 4.533px with default browser positioning. A labeled geometric-precision control reduced them to 0.00937px and 0.10760px; the latter still failed the unchanged 0.1px gate.

The corrected renderer requests geometric precision for measured runs. Where shared outline placement has accepted an advance, SVG `textLength` with `lengthAdjust="spacingAndGlyphs"` also makes the painted horizontal advance conform to that placement. This can scale glyphs horizontally; it retains the selected nominal font size, vertical scale and baseline. Width-only providers receive no glyph scaling. A spacing-only experiment accumulated per-character rounding and failed; it was not retained as runtime behavior.

This is a rendering constraint, not proof that raw browser metrics equal Fontkit. Before measurements remain available independently. The 30-case browser test also measures unadjusted cloned spans and bounds the fixture correction to 0.1% of advance plus 1/64px, independently of its unchanged 0.1px painted-spacing/alignment/baseline assertions. It checks source spans, links, decoration, requested styles, blank lines and script shifts. It does not establish multilingual shaping or arbitrary-provider accuracy.

Mac measurements after correction show gallery run gaps below 0.0011px. Both complete measured slides were inspected. Linux verification runs against the exact revised PR head; passing raw font compatibility must not be inferred from constrained SVG advances. The 805-slide default estimated regression checkpoint is separate and remains unchanged by this measured-only increment.
