## 0.37.0 (2026-11-27)

- A deck can carry a document id: an optional root `id`, an opaque non-empty string (the docs recommend a UUID, and a host keeps the id it already has) that says "this is the same deck" across saves, exports, imports and publishes. Core never makes one (it has no clock and no randomness): `opf create` gives every new deck, starter or example, its own UUID, and core's `fill` drops the template's id from each filled deck while `opf fill` gives each its own new one when the template had one. The id is a claim, not a credential: a file can carry any id, so a host must check who owns an id before it selects a stored deck. PowerPoint: `toPptx` writes the id into the `OPF_DOCUMENT_V1` tag (also in `references-only` mode) and `fromPptx` restores it; an export with `provenance: false` drops it and reports `document-provenance-omitted` at `id`. The MCP viewer keys an editing session on the deck's id when it has one (so two decks both named "Untitled" no longer share a session) and on its name otherwise. `diff` reports a changed id at `/id`, and `merge` keeps one side's id and reports a conflict at `/id` when the sides carry different ones. Conformance: two valid and two invalid cases for Core Reader and Core Writer. A deck without an `id` is unchanged.
- FR-02 (CR 6): list items, bullets, timeline events and table rows can carry an `id`, so a comment, a patch, a diff or a merge can name one entry and find it after the entries move. A list item and a bullet take `id` in the object form, a timeline event takes it directly, and a table row is an array of cells or the object `{ "id", "cells" }`, both in one table. Every id shares one document-wide namespace with slide, block and overlay ids (a duplicate is a validation error), is optional, and an unmarked deck is valid and addressed by index. `tableRows` and `rowCells` (`@openpresentation/opf`) return rows in one form, so engines and converters never branch on the two spellings. `assignIds(doc, { items: true })` gives every entry an id (a string item becomes `{ id, text }`, an array row `{ id, cells }`; the default stays slides and blocks only, `generate` mints random ids for a co-editing host); `touches` lists the entry ids a patch reaches. The content conversions between list, table and timeline keep each entry's id. The renderer draws a deck the same with and without ids. The editor keeps row and item ids through edit, move, sort and delete, gives a copy new ids and replaces a taken id on paste. PowerPoint export stores the ids in the slide record (`full` provenance) and import restores an id while its entry is still recognizable, with one `entry-ids-not-restored` finding naming how many were not; a deck without entry ids exports the same bytes as before. Markdown keeps the ids through its embedded form. Dataset rows and chart data rows have no ids.
- FR-03 (opf#1297): a link to a slide of the same deck. A run, shape block, overlay shape or table cell `link` may be `slide:<id>`, spelled like `asset:<id>` and `var:<id>`; the id is a slide's `id` (`assignIds` gives every slide one). A link to a slide id no slide has is the error `opf/slide-link-unknown`. The SVG draws a slide link as a link that opens no tab (`data-opf-slide-link`, and `data-opf-slide` on the slide it names, only on slides a link names); the slideshow player, the editor's presenter (a hidden target included) and the MCP viewer's Present go to that slide, and a click on any link no longer moves the player's show; the PDF export writes a go-to-page link (a slide that is not in the PDF is left unlinked and reported as `pdf-link-skipped`); the PowerPoint export writes a native slide jump (`ppaction://hlinksldjump` with a relationship to the slide part) on text, shapes and table cells, and import returns `slide:<id>` (the stored slide id, or `slide-<number>` for a slide a jump names in a deck PowerPoint wrote). The editor's formatting toolbar and shape panel have a slide picker beside the link field. A deck without slide links draws and exports as before.
- FR-03: links work where a slide is read, not edited. In the editor's `viewer` layout and any read-only editor the slide is no longer inert: a click or Enter on a `slide:<id>` link shows that slide (a hidden one too) and puts the focus on the slide, and a web, mail or phone link goes to the new `onOpenLink(href, event)` option, else opens a new tab with `noopener` and `noreferrer`; other addresses are ignored (`isOpenableLink` in `@openpresentation/opf-render/svg`). The canvas has `readOnly`, `setReadOnly`, `onLink` and `focusSlide`; an editable slide keeps a plain click for editing and follows a link on Ctrl or Cmd with the click. The editor emits a `link` event. The MCP viewer opens links through its host (`ui/open-link`) and shows the address in the footer where the host refuses. A slide draws as before.
- OPF 0.37 (FR-05; no drawing changes): a dataset column and an inline chart data column may declare what its cells hold (`type`: `text`, `number`, `date`, `boolean`), what it is for (`role`: `dimension`, `measure`) and a `unit` label engines never print, as a new `DatasetColumn` (a `DataColumn` with the three keys; a table's own column headers stay `DataColumn`). A deck without the keys draws and exports exactly as before; the only drawing-adjacent change is the time-order decision for the category column: `date` is time ordered when its labels run forward (the title fallback is skipped), `text` and `boolean` never are. New warning `opf/data-cell-type` (a cell of another kind than its column's `type`, one finding per cell up to five in a column and then one for the column; `number` means a finite number, so `"12"` warns) with a safe fix (applied by `opf fix --audits`) that stores a strict decimal string as a number and a number in a text column as text and never changes the declared type. ISO 8601 date-times are time labels. `resolveChartData` returns `types`; core exports `datasetColumnDeclaration`, `cellMatchesType`, `suggestCellTypeFix`, `inferColumnDeclaration` and `declareColumns`; `opf ingest --dataset` declares the dataset columns it writes from their cells (a column that cannot be told stays a plain string; a dataset column that already exists keeps its declaration) and stores typed cells as that type; the editor's data panel gets type, role and unit fields (`setGridColumnDeclaration`). PowerPoint: the keys stay inline in `OPF_DATASETS_V1` and a chart's `OPF_DATA_V1`; a 0.36.0 importer does not know them, drops those records and imports the values the charts and tables show (as for the data source keys of FR-04). See `docs/chart-table-data.md`.
- A metric can be computed from data (0.37, FR-06): `metric.data` links it to rows of a dataset of the same deck (`dataset`, `field`, `aggregate` of `sum`, `mean`, `min`, `max`, `count`, `first` or `last`, and a `filter` of `{ field, op, value }` conditions, all of which a row must meet), and core computes the value from them. The change is optional, `data.delta`: against the previous row (`compare: "previous"`), a baseline (`compare: { filter }`), a fixed number (`compare: { value }`) or a column that already holds it (`field`), as a difference or a percent (`as`), with its own `format`. The arrow follows the sign of the computed change when `trend` is not typed, and `better: "up" | "down"` (valid on any metric) says which direction is good news, so a rising churn draws an up arrow in red; a typed `trend` or `sentiment` still wins. `metric.format` is a number format for a `value` that is a number (`"0.0%"`, `"$#,##0.0M"`), also on a metric with no link; the metric's format wins over the linked column's, which wins over the number rules of today. While the link resolves the computed numbers are drawn and `value` and `delta` are the last computed numbers, kept for readers that do not compute; when it does not resolve the written numbers are drawn as before. New rules: an unknown dataset or column in a link is the errors `opf/dataset-unknown` and `opf/dataset-field-unknown`; the warnings are `opf/metric-data-stale` (the written number differs from the computed one; safe fix, applied by `opf fix --audits`; `opf fill` applies it to every filled deck), `opf/metric-data-aggregate` (a text or boolean column cannot be summed), `opf/metric-data-empty`, `opf/metric-data-delta` and `opf/metric-unit-repeated`. Core exports `resolveMetric` (the metric to draw, the value as drawn with its number and format, the record, the findings) for a host that draws a metric another way, and `updateMetricLiterals`. PowerPoint: the native shapes are those of a typed metric; the tag holds the metric as drawn (a 0.36 importer reads a plain metric with the same numbers) and the 0.37 part in a `link` key, restored on import while the value and change text are unchanged (an edit in PowerPoint drops the link: `metric-data-dropped`). The editor's metric inspector has a Data section (dataset, column, aggregate, rows, change, direction, number format, and an Update button for the written numbers), and a rename of a dataset column updates the links. No existing deck changes. See `docs/chart-table-data.md`.
- A table can shade the number cells of named columns by value: `table.colorScale` (`columns`, `colors`, `center`, `min`, `max`), in scheme colors only (the new `SchemeColorName`), sequential (two colors) or diverging (three colors, symmetric around `center` unless `min` or `max` is pinned), mixed in OKLab, with the text color that reads on each fill. Core computes the fills (`resolveTableColorScale`, `layoutTable`'s `colorScale` option and each cell's `scaled`); the preview, PNG and PDF draw them; a table split across slides keeps one range. The PowerPoint export writes native cell fills and text colors, records the scale beside the stored table (a released 0.36.0 importer still restores the table, without the scale), and import restores it while every shaded cell still has its fill, else it returns plain fills with `table-color-scale-not-restored`. The editor edits the scale as one undoable patch (`@openpresentation/opf-editor/table-color-scale`) with a Color scale section in the table inspector. New rules: the error `table-color-scale-unknown-column` and the warnings `table-color-scale-no-data` and `table-color-scale-range`.
- FR-08: the `embed` content kind, a live web page that a web presenter may show and every other output draws as a picture linked to it. `embed` is an https string or `{ src, title, aspectRatio, preview }` on a slide or a block (with a `caption`); engines never load the page. Wherever it is not shown live (the preview, PNG, PDF, PowerPoint, the MCP viewer) it is the `preview` picture, contained on the surface color, or a card (a link badge, the title, the site name), linked to `src`; the PDF links the frame. A layout region that accepts `video` accepts an embed. The editor's presenter (the workspace option `embeds`) and the web player (`present(deck, { embeds })`) show a page the host lists in a sandboxed frame over its static form (nothing is live by default, and a page of the presenting page's own origin never is); `@openpresentation/opf-render/live-embeds` is the shared helper. New: warning `opf/embed-credentials` for a user name with a password or a secret query parameter in `src` (the test a data source's `src` already takes, `credentialInSrc`, which now also reads compound names such as `accesstoken`), video-to-embed conversions, the editor's Embed insert entry and inspector (`@openpresentation/opf-editor/embed-options`), `embedCardLayout` for the card's geometry, and a PowerPoint round trip: the picture or the card as native parts linked to the page, with `OPF_EMBED_V1` restoring the embed while its link and picture (or the card's title text) are unchanged (`embed-provenance-changed` otherwise). A 0.36.0 importer reads the file as a linked picture or shapes.
- FR-09: a variable's declaration can say how much room it has. A text variable takes `maxLength` (characters as a reader sees them, counted in grapheme clusters, so an accented letter or an emoji counts once) and `maxLines` (checked where the variable is drawn, because the line count depends on the width of the box); a list variable takes `maxItems`. A limit on another kind of variable, or below 1, is a schema error. A value over a limit is the new warning `opf/variable-overflow` (the deck still draws): `validate` reports `maxLength` and `maxItems` on the declared value and on a value given with `values`, and `maxLines` at each place the variable is drawn (a title, a subtitle, a tag, a text block or a list entry, alone or inside longer text), naming the slide. `fill` and `resolveVariables` return the same overflow as a `variable-overflow` diagnostic for `maxLength` and `maxItems`; `opf fill` reports all three on stderr with the record and the slide, and in `fill.overflow` of its report, before anything is written. `listVariables` and the editor's `listTemplateFields` carry the limits, the Fill template panel shows the count ("12 of 48 characters"), and `visibleLength` counts a text the way `maxLength` does. A deck without limits validates, draws and exports exactly as before. See `docs/templates-and-variables.md` and `examples/technical/variable-limits.opf.json`.
- FR-10 (part 1): a variable can carry translations. A text, list, url or image variable takes `translations`, a map from a language tag to `{ "value": ... }` in the form of the variable's own value; a date variable's entries are `{ "format": ... }`, because the date is the same in every language and how it is written is not. The language of the place where the variable is drawn selects the entry: the slide's declared `language`, else the deck's, then the tag with its last subtag removed (`de-AT`, then `de`), without regard to case, else `value`. It applies to an inline `{{id}}` and a whole `var:id` field alike, in titles, text, notes, captions and links; a language read from the text selects nothing, so a deck with no declared language draws `value` as before. A template may hold translations without a `value` (the variable is filled where the language selects one). `maxLength`, `maxLines` and `maxItems` apply to every translation and report the translation's path. Two keys that differ only in case are the warning `opf/variable-translation-duplicate`, and a translation no declared language selects the warning `opf/variable-translation-unused`. `opf fill` and `fill()` remove a variable's translations when a record gives a value without translations (reported as `translationsRemoved`; a date's formats stay), and a record may give `{ "value": ..., "translations": ... }` itself. The editor's Fill template panel lists translations as rows with Add translation (the deck's and slides' languages first), through `setVariableTranslation` and `removeVariableTranslation`. Variables resolve before the PowerPoint export, so each slide's text is in its language; nothing new is stored in the file. A deck with no translations validates, draws and exports exactly as before. See `docs/templates-and-variables.md` and `examples/technical/variable-translations.opf.json`.
- The MCP viewer (`ui://opf/deck`) is 285,269 bytes smaller in its JSON-RPC frame (9,501,842 to 9,216,573, 1,269,187 bytes of headroom under the SDK's 10 MiB stdio limit, and the test's headroom floor is 1,000,000 again), with build-time changes whose results are proven identical (opf#1516). Core's generator writes the font policy, the DrawingML preset geometry and the engine vocabularies in a compact form (`scripts/compact-literal.mjs`: each repeated string named once, each repeated row shape built by a function), and stops unless what it builds has the same JSON text as the spec file; `FONT_POLICY`, `LANGUAGES`, `CHART_TYPES`, `SOCIAL_PLATFORMS` and the preset shapes keep their values, types and freezing, and load in the same time. The precompiled validators build enum, additional-property and bound errors (`minimum`, `maximum`, `exclusiveMinimum`, `minItems` and the like) with three more helpers that derive params and message from the schema, each chosen only where Ajv's own code is the same; every error still equals Ajv's property by property. The viewer's build writes the gallery's records and the renderer's font manifest as the same compact expression instead of JSON text; other consumers of both packages are unchanged, and the viewer starts in the same time (Chromium, 40 runs, median difference -4.1 ms). See `docs/programs/release-readiness/mcp-viewer-size.md`.
- Breaking (0.37, FR-04; no drawing changes): a dataset and inline chart data say where they came from in their own keys, and a new root `datasources` map describes each place data lives once. The nested `source` object (`{ src, sheet, range, fields, retrieved, description }`) is removed, with no alias: a 0.36 deck that has one fails validation (`opf/schema` at the `source` key) until `opf fix deck.opf.json -i` rewrites it (the safe fix `use-datasource`). Before: `"source": { "src": "./data/revenue.csv", "sheet": "FY26", "range": "A1:C13", "retrieved": "2026-10-05" }`. After: `"datasource": { "src": "./data/revenue.csv" }, "query": "FY26!A1:C13", "retrieved": "2026-10-05"`. `sheet` and `range` fold into `query` (a sheet name with a space is quoted, `'Q3 plan'!A1:B9`), `description` moves into the inline data source, and `fields` is dropped (the fix says so). New keys on a dataset and on inline `chart.data`: `datasource` (a string is only ever the id of an entry of `datasources`; a file or URL is the inline object `{ "src": "./revenue.csv" }`), `query`, `retrieved` (a date or a date-time), `version`, `sha256` (the hash of the source file's bytes as retrieved, 64 lowercase hex digits) and `generator` (`{ type: "human" | "model", name }`). A data source takes `title`, `description`, `connector`, `src`, `license`, `refreshEvery` (an ISO 8601 duration; no engine acts on it) and `extensions`, and never holds credentials. New rules: `opf/datasource-unknown` (error), `opf/datasource-credentials` (a `src` with a user and password, or a key or token in its query string; warning) and `opf/dataset-stale` (warning, only when a date is passed: `validate(deck, { asOf })`, `opf validate --as-of <date>`; core never reads a clock). Engines never read, fetch or refresh a data source; the keys travel through editing, Markdown, YAML and the PowerPoint document tags (`OPF_DATASOURCES_V1` beside `OPF_DATASETS_V1`) unchanged. In code: `DataSourceRef` is replaced by `DataSource`, `DataGenerator` and `DataProvenance`; `resolveChartData(...).source` is `.provenance`; `stats` reports `withDatasource` and `datasets.items[].datasource` where it reported `withSource` and `source`; the editor's `prepareDatasetImport` takes `provenance` where it took `source`; `opf ingest --dataset` writes `datasource`, `sha256` and (with `--date`) `retrieved`. See `docs/data-sources.md`. Removed from the schema with it: `opf.schema.json:$defs.DataSourceRef`.
- FR-10 (part 2, a declared drawing change): the month and weekday names of a date are the language's where the date is drawn. `MMMM`, `MMM`, `EEEE` and `EEE` in a date variable's `format` and in a header or footer `dateFormat` print the names of the slide's declared language, else the deck's (English when none is declared or the table has no data for the language, so a deck with no declared language, and an English one, draws exactly as before); a month in a pattern with a day token is in its form after a day ("5 марта"), without one in its stand-alone form ("март 2026"), a language that counts its months prints the whole label ("3月"), and the digits are the numerals table's. A date variable with no `format` uses the language's long date pattern (`d. MMMM yyyy` in German, `d MMMM yyyy` in French and British English, `yyyy年M月d日` in Japanese); US English and a deck with no language keep `MMMM d, yyyy`. A deck's header and footer variables take the language of each slide they are drawn on: a slide in another language than the deck's gets a resolved copy of the deck's furniture in its own. The names come from a generated table (`packages/javascript/src/date-name-data.ts`, 88 languages, ICU 78.3 and CLDR 48.0, 12.7 KB gzipped, read by `scripts/build-date-names.mjs`; `ay`, `ber-Latn` and `ctg` have no data and draw English); the entries that draw dates carry it, and their size budgets in `scripts/catalog-free-budget.json` were raised by its measured cost. `formatFurnitureDate(iso, pattern, language?)` gains the language, and core exports `dateNamesOf` and `longDatePattern`. In PowerPoint a date field is looked up in the language of the slide it is written on (PowerPoint formats a field by its run's language), so a deck footer drawn on a French slide of a German deck is a French field or fixed text, and the `furniture-date-fixed` message names that language. A current date with month or weekday names stays a native English field only in a deck whose names are English, and is fixed text in another language, so the file shows the words OPF drew. The drawing changes only for a deck that declares a language other than English (or `en-GB` and the like for a date variable with no format) and draws a date with names or without a format; no gallery record draws differently. See `docs/templates-and-variables.md`, "Dates in other languages".
- FR-11: the `opf/schema` finding for a key the object does not define and that is not close to a known key (not a typo) now says in its `help` which OPF release the validator is and that a later release may define the key, and carries the version as `validation.params.validatorVersion`. A validator cannot name the release a key needs, so it names its own. `opf validate`, the editor and the MCP `validate` tool show it because they share core's findings; a key with a "did you mean" suggestion keeps its help. The version comes from a generated constant, so core stays edge-safe.
- Breaking (0.37; no slide draws differently, and `opf fix` makes every change below): eight keys of 0.36 are renamed so that one idea has one name, with no alias. A deck that still writes an old name fails validation (`opf/schema` at the key, a message that names the new key, the safe fix `rename-key`; `rename-value` for a value). Schema removals, named as the gate names them: `font-scheme.schema.json:properties.languageFamily` (the font scheme record also becomes a closed object), `layout.schema.json:$defs.Composition.properties.minFontSize`, `opf.schema.json:$defs.FontScheme.properties.languageFamily`, `opf.schema.json:$defs.TableCellStyle.properties.verticalAlign`, `opf.schema.json:$defs.Speaker.properties.organizationId`, `opf.schema.json:$defs.Composition.properties.minFontSize`, `opf.schema.json:$defs.Composition.properties.maxFontSize`, `opf.schema.json:$defs.Reference.properties.url`, `opf.schema.json:$defs.ImageBackground.properties.tone`, `opf.schema.json:$defs.GradientBackground.properties.tone` and `opf.schema.json:$defs.Chart.properties.line`. Enum values no longer accepted: `ea` and `cs` in `opf.schema.json:$defs.FontScheme.properties.scriptGroup.enum` and `font-scheme.schema.json:properties.scriptGroup.enum` (they were values of `languageFamily`).
    - A font scheme's `languageFamily` is `scriptGroup`, and its values are `latin`, `eastAsian` or `complexScript`; `ea` and `cs` are no longer accepted. The 93 font scheme records of the gallery are rewritten (they draw the same).
    - A styled table cell's `verticalAlign` is `anchor`.
    - A speaker's `organizationId` is `organization`.
    - A composition's `minFontSize` and `maxFontSize` are `minFontSizePx` and `maxFontSizePx` (the same numbers, in reference pixels).
    - A reference's `url` is `link`, and it must be an http, https, mail or phone link; `opf validate` offers `Add https://` (not safe) for an address without its scheme.
    - A picture or gradient background's `tone` is `appearance`; the deck's own `tone` is unchanged.
    - A combo chart's `line` is `lineSeries`.
    - A chart reference line's `stroke.dash` also accepts the eight other preset dashes a shape outline takes (`longDash`, `dashDot`, `longDashDot`, `longDashDotDot`, `sysDot`, `sysDash`, `sysDashDot`, `sysDashDotDot`); the preview draws them and the PowerPoint export and import carry them. A table cell border keeps `solid`, `dash` and `dot`.
    - Exported names that follow the keys: `normalizeLanguageFamily` and `LanguageFamilyName` are `normalizeScriptGroup` and `ScriptGroupName`; the option `tone` of `resolveColorRoles` is `appearance`; `stats` lists a speaker's `organization`; the composition options `minFontSize` are `minFontSizePx`; the `url` of `Reference`, of a laid-out note and of the editor's reference functions is `link`; the `line` option of the editor's `setChartOptions` is `lineSeries`; the `verticalAlign` field of the editor's table cell style is `anchor`. New: `renameRecordKeys`, core's one table of renamed keys.
    - PowerPoint: the records store the new names. A file written before 0.37 still imports: the importer reads each record through the rename table. A 0.36.0 importer does not read the new names inside the records of a 0.37 file.
    - Updating: `opf fix deck.opf.json -i`; docs/migrations/0.37.md.
- NT-03: the export skill's Keynote table, now "Keynote differences", covers Keynote 16.0: a line names the Keynote and OPF versions its rows were seen in, and the 0.36.0 round adds eight rows (the fonts a Mac lacks and `--typefaces safe`, a live slide number with hidden slides, a footer over a full-bleed picture, data labels that lose the category, long column names, labels on some points of a stacked area, long legend entries, and picture alt text). The table is generated from the known differences in `scripts/native-acceptance/known/keynote.json`.

## 0.36.0 (2026-11-25)

- The docs index (`opf://docs/index`) now points to the platform at openpresentation.com, where hosted rendering, PPTX export, AI generation and storage are being built, instead of naming pptx.dev. pptx.dev is a simple browser tool for making PowerPoint files and is no longer named as the hosted service.
- The MCP viewer draws no Expand button in its bar when the host is Claude. Claude has its own expand control above the viewer, so there were two in the same corner; now there is one. Other hosts keep the bar's Expand, and the More menu of a phone-size bar keeps its item everywhere.
- The viewer's footer now says "Claude can see this version" (the host's name, or "The assistant") in quiet text at the right once the deck has been shared with the assistant, without opening Ask; it reads "Sharing changes…" while an edit is on its way, gives way to a status note such as "Opened …" while one shows, is not a live region (it is not announced after each edit), and wraps to its own row in a narrow frame. Before this the sentence was only in the closed Ask composer.
- Design, Find and replace, and Export open one panel: the same 360px frame (a header with the title and Close, a scrolling body, a foot line), in the same place (under the button, or under the host's bar with the new `anchor` option of `createDesignMenu`, `createFindPanel` and `createExportMenu` and the workspace's `panelAnchor`), one at a time (opening one closes the other in place; Escape closes it and gives the focus back to its button), never taller than the room under its anchor, and a bottom sheet with a grabber at 600px and under. All three read only the `--opf-ui-*` tokens (Find no longer injects its own stylesheet with fixed colors).
    - **Design** shows one section at a time behind four tabs (Theme, Colors, Fonts, Layout; a `tablist` driven by the arrow keys): themes as small slides in their own colors with the schemes they bring, color schemes in two columns of joined swatches, font schemes for the deck's language (its script's slot; an English deck lists the 29 Latin schemes, not all 94) under "In use" and their type, each drawn in its own face once loaded, with a filter, and the slide's layouts as schematic thumbnails drawn from each layout's regions. The current choice is tinted with a check; each choice is still one undoable edit, and the foot says what happened with Undo.
    - **Find and replace** has the match count inside the find field, the options as toggle chips (`aria-pressed`; "This slide only" is now "This slide"), Replace and All, and the results grouped under a label per slide. A press outside still does not close it.
    - **Export** rows are 36px with the file type and hint in mono at the right (the PowerPoint row is now "PowerPoint", `.pptx · editable`); choosing a format keeps the panel open and shows progress, Cancel, the file made or the failure, and the notes in a card at the top, announced as before.
    - The MCP viewer groups Design, Find and Export as one bordered set of icon buttons whose open one is pressed, opens their panel under its bar, makes Export a sheet at 600px and under (it was 900px), and its Find button opens find and replace and toggles.
- The MCP viewer's PowerPoint export now lists the fonts a viewer's PowerPoint may not have (Roboto, Aptos and the like) among its export notes, as `opf convert` reports them in `pptx/typeface-not-office-safe` (opf#1403). The export still succeeds; the note is information. `@openpresentation/opf-pptx` exports `typefacesNotOfficeSafeMessage(families)`, the sentence of that finding, and the command line and the viewer both use it.
- The OPF viewer on a server that offers no `read_font_file` (a hosted server that passes no `readFontFile`) no longer sits on a blank stage with "Drawing the slides…": it says that the slides cannot be drawn because the fonts the deck needs could not be loaded from the server, and that the host must offer its font files. `docs/mcp.md` no longer claims the view draws with Roboto in that case; only Roboto Regular is inline, and any other face comes from the server.

It runs in the client's sandbox with no network, no eval and no WASM, so all deck work happens on the user's machine. When the user edits, the whole deck goes back to the model as context; a Send to Claude button also starts a turn. `show_deck` also checks the deck and answers in text for clients without MCP Apps. Fonts other than the built-in Roboto come from `opf-mcp` through the app-only tool `read_font_file`, which serves the installed renderer's files in 512 KiB pieces; the renderer checks each file's SHA-256 before using it. A hosted server can pass `processDecks: false` so it does no deck work: `show_deck` then only opens the view, which checks the deck and sends the findings to the model, and `validate_deck`, `convert` and the `fix_validation_findings` prompt are left out. `createOpfServer({ deckApp: false })` leaves the view out. The viewer has the editor's Undo and Redo, review pill and Review panel, Design menu, and Find and replace. The server also builds as a Claude Desktop extension (`pnpm --filter @openpresentation/mcp run build:mcpb`, `opf-<version>.mcpb`). The extension carries the renderer and its fonts and needs no Node install or configuration; `--no-script-fonts` builds a lite bundle without the script faces. For a hosted server, `siteFontFiles({ fetch })` serves the viewer's fonts from a site that already serves the OPF preview fonts (the OpenPresentation site's `/opf-fonts/` layout), in a Worker through its static-assets binding, and `deckApp.html` can be a function, so a hosted server loads the viewer's page only when a client opens it.
- SH-04: overlay shapes and connectors. A slide's `shapes` array is drawn over the composed slide, above the content and the furniture, in array order, and never moves content. An overlay shape has the shape block vocabulary (preset or `path`, `adjust`, fill, stroke, style, the effects, `rotate`, `flip`, text with `anchor`, `padding` and `textDirection`, `alt`, `decorative`, `hidden`, `link`) and one placement: `x`, `y`, `width` and `height` (fractions of the slide; `x` from the right edge in a right-to-left deck) or `at: { block, edge, offset, width, height }` against a composed block (`top`, `bottom`, `start`, `end` or `center`), so it follows the block; `layer: "back"` draws it behind the content (above the background and watermark). A connector (`{ connector: { from, to, route, fromSite, toSite }, stroke }`) joins two blocks or overlay shapes at connection sites (a preset's own, a rectangle's four for any other block), chosen automatically as the facing pair with the shortest route; `route` is `straight`, `elbow` or `curved`. A connector's `adjust` (`adj1`) keeps a route as drawn in PowerPoint. Core composes them as `SlideComposition.overlayShapes`: overlay shapes as shape block items (`kind: "shape"`, SH-02's `ComposedShape`, text fitted by OPF's measured fonts) and connectors as `ComposedConnector`s routed as PowerPoint's `straightConnector1`, `bentConnector2`/`bentConnector3` and `curvedConnector2`/`curvedConnector3` with their `a:xfrm` frame and `a:avLst`, and the same route in slide coordinates. The preview draws overlay shapes with the shape block drawing and connectors with the shape stroke (dash, compound, sketch, arrowheads); the PPTX export writes overlay shapes as native `p:sp` and connectors as native `p:cxnSp` glued (`a:stCxn`, `a:endCxn`) to the shape blocks, overlay shapes, pictures and cards at their ends, so a connector follows a shape moved in PowerPoint. When `paginate` splits a slide, a shape placed by fractions is on every page, an `at` shape on its block's page and a connector on the page that holds both ends; a connector whose ends land on different pages is reported as `connector-split` in `PaginatedPage.diagnostics`. New findings: `opf/shape-anchor-missing` and `opf/connector-end-missing`; an overlay shape with both placements or none, a connector with a shape-only key, and a site index the shape does not have are `opf/schema` errors. Docs: `docs/shapes.md` ("Overlay shapes and connectors"); examples `examples/technical/shape-overlays.opf.json` and `shape-overlays-rtl.opf.json`.
- SH-06: shapes in the editor and the MCP. The editor inserts, restyles and adjusts shape blocks, each edit one undoable change: a shape picker (`@openpresentation/opf-editor/shape-picker`: `createShapePicker`, `createShapeMenu`; the playground's **Insert shape**, **Add content > Shape** and **Change shape…**) with PowerPoint's nine gallery groups, a tile drawn from each preset's geometry and a search by DrawingML name and common words; the yellow adjust handles on a selected preset shape (drag, arrow keys, Escape; fractions and degrees pinned to each handle's range); and a **Selected shape** section of the design controls (`shape` in `DESIGN_CONTROL_SECTIONS`) for the preset and its adjust values, fill (none, color, gradient, pattern), opacity, line (color or gradient, width, dash, cap, join, miter limit, compound, alignment, arrowheads, sketch), style, the six effects, rotation and flip, text, anchor, padding, direction, alt text, decorative, hidden and link, with Lighter and Darker tints on every color. `@openpresentation/opf-editor/shape-options` is the same from code: `insertShape`, `setShapePreset`, `setShapeAdjust`, `setShapeProperties` (each with a `prepare...` form), `searchShapes`, `shapeGroups`, `readShape`. A shape's outline is selected, not edited as text, when clicked; `createCanvasEditor` takes `shapeTools: false` to leave the handles out. Core gains `@openpresentation/opf/shape-catalog` (`SHAPE_CATEGORIES`, `SHAPE_CATALOG`, `searchShapeCatalog`, `shapeThumbnail`, `shapeThumbnailSvg`): the 187 presets in PowerPoint's gallery groups with their keywords. The MCP has a `search_shapes` tool (query, category, limit): each preset with its DrawingML name, group, default frame, adjust values (default, range, unit, whether a handle moves it) and a small SVG. See docs/shapes.md.
- SH-09: pyramids and matrices, written to PowerPoint as live SmartArt. A layout region's new `arrangement` (`"pyramid"` or `"matrix"`) draws its lone list of one level as a diagram, in the first design that holds every entry at one text size, the list's role size or larger, never smaller: PowerPoint's own geometry (Basic Pyramid of 1 to 8 levels, the first at the top; Basic Matrix of exactly four quadrants over a diamond), else OPF's own design of the arrangement (a stepped pyramid with each entry beside its level, or four quadrants filling the region). A matrix of other than four entries draws a grid of cards, and a list no design holds (or with nested entries, descriptions, icons or numbering) stays a list; both report the new info finding `opf/arrangement-adapted`. The gallery adds the `pyramid` and `matrix` layouts (32 layouts). Core exports the geometry and paint (`pyramidNodes`, `matrixNodes`, `pyramidSteps`, `matrixQuadrants`, `cardNodes`, `arrangementPaint`) and the domain PowerPoint was compared on (`SMART_ART_DOMAIN`, `smartArtUnavailable`); the preview draws the nodes under the entries. The PPTX export writes PowerPoint's design as live SmartArt where the instance lies in that domain: a `p:graphicFrame` with OPF's data model (explicit run sizes with `custT`, so PowerPoint keeps them), OPF's own colors and quick style parts, a drawing from core's geometry and no layout part (`r:lo` empty: OPF never writes a SmartArt layout definition); everything else, and everything with `smartArt: "shapes"` (CLI `--smart-art shapes`), is native `trapezoid`, `roundRect` and `diamond` shapes under the measured lines, with the info finding `pptx/smartart-unavailable` and its reason where live SmartArt was not written. Import reads an unchanged OPF SmartArt (`OPF_SMARTART_V1`) back as its list on its layout, and an edited one or a PowerPoint-authored Basic Pyramid or Basic Matrix from its data model (the nodes in `cxn` order with their run properties). See `docs/smartart.md`.
- The package READMEs of core, the CLI and the gallery gain a short section on shapes, icons, live SmartArt layouts and native Mermaid diagrams, and the gallery README documents the `@openpresentation/gallery/icon-sets` export (American spelling throughout). - SH-02 (breaking: picture `border` is now `stroke`, image `shape` names and `cornerRadius` changed): shape blocks. A block with `shape` (any of DrawingML's 187 presets: `chevron`, `rightArrow`, `wedgeRectCallout`, `flowChartDecision` and the rest) and no `image`, or with a custom `path` (SVG path data), draws the shape with optional `text` inside, and composes like any block: the largest frame of the preset's proportions (or `aspectRatio`) in its cell, its text fitted in the preset's text rectangle by OPF's measured fonts and never below `minFontSize` (`opf/text-overflow` at `<block>/text` otherwise). It takes `adjust` (the preset's handles in fractions and degrees), `fill` (`none`, a color, `{gradient}` with `type` linear, radial, rectangle or shape, `{pattern}`), `opacity`, `stroke` (color or gradient, width, preset or custom `dash`, `cap`, `join`, `miterLimit`, `compound`, `align`, arrowheads `start` and `end`, `sketch`), `style` (none, subtle, moderate by default, intense: PowerPoint's theme shape styles, written as `p:style`), `rotate`, `flip`, `anchor`, `padding`, `textDirection`, `alt`, `decorative`, `hidden` and `link`; the effect keys (`shadow`, `innerShadow`, `glow`, `softEdge`, `reflection`, `blur`) are in the format for SH-03 to draw. Every ColorRef also takes `{ "color": ..., "lighten": 0.4 }` or `{ "color": ..., "darken": 0.25 }` (PowerPoint's "Lighter 40%"), exported as `a:lumMod`/`a:lumOff` on the base color. An image block's line is `stroke` (renamed from `border`, no alias) with the same vocabulary, its `shape` takes every preset (`rectangle`, `rounded` and `circle` became `rect`, `roundRect` and `ellipse`) and `adjust` replaces `cornerRadius` (schema removals: `opf.schema.json:$defs.ImageBorder` and the old image `shape` enum, `opf.schema.json:$defs.ContentPayload.properties.shape`). ## 0.32.0 (2026-11-04)
