- RR-37 (CI tooling, no package change): the `Installed candidates (windows-latest)` job failed on core branches that pin an opf-render with a `bin` file (opf-render RR-28 added `opf-preview-fonts`) with "Installed runtime differs from the staged package". opf-render has no `eol=lf` rule for `dist`, so a Windows checkout (`core.autocrlf=true`) writes `dist/preview-fonts-cli.js` with CRLF, `pack-ecosystem.mjs` stages and packs those bytes, and npm rewrites a CRLF shebang line to LF when it links the bin at install time: the installed file was one byte shorter. - RR-29 audit fixes (two defects `opf audit` found in the bundled examples; additive API). (1) **Reading order of promoted regions.** `composeSlide` composed promoted regions (`left`, `center`, `right`, `top:left`, ...) in alphabetical key order, so `center` was composed, drawn and exported before `left`, and screen readers and PowerPoint's selection order followed. Regions are now composed in visual reading order (rows top to bottom, then along the row; new `visualReadingOrder`, which `audit/reading-order` shares). No geometry moves: only the order of `items` changes, which changes the SVG draw order and the PPTX shape order of promoted-region slides. Of the 126 example decks, 55 slides in 50 decks reported `audit/reading-order` and none do now. (2) **Chart palette collapse on dark surfaces.** `chartColorForFill` adjusts each series colour for contrast on its own, so on a dark or mid-tone card the dark blues of the default palette were lifted to nearly the same colour and two series became indistinguishable (15 charts in the examples reported `audit/chart-color-only`). New `chartPaletteForFill(fill, palette)` adjusts the whole palette: colours that already pass are kept, and a colour the surface moves is placed again on the lightness axis (same hue) so neighbouring series keep a lightness step of 11 L* (readable in greyscale) and every series a colour difference of 12, each capped at the palette's own separation. It is deterministic and depends only on the surface and the palette, so every chart on a surface gets the same series colours; `opf-render` and `opf-pptx` call it for the preview and the export. 32 of the 158 example charts change colour, and `audit/chart-color-only` falls from 15 charts to 5 (the 5 left are four-slice pies on the default light surface, where the first and fourth slice cannot both clear 3:1 contrast and keep an 11-point lightness gap).

- RR-32: templates and variables ("a template is just an incomplete OPF file").
