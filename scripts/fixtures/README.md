# Coordinated renderer baseline

`opf-examples-png.sha256.json` identifies the current core examples for coordinated renderer CI. The renderer standalone suite retains its baseline for published core 0.4.0. Both enforce exact corpus and raster hashes; this file is selected explicitly only for coordinated source checks.

Reviewed against renderer 87663fb on 2026-09-08: 126 decks / 805 slides. Compared with the published-example baseline, only `technical/asset-source-forms.opf.json#1` changes. Its truncated eight-byte PNG signature is replaced with a complete project-authored PNG; the newly visible image was inspected at individual-slide scale. The other 804 PNG hashes are unchanged. This does not establish complete visual or PowerPoint parity.

`opf-examples-png.cover-centering.sha256.json` is the coordinated packages golden for unpublished cover centering (`composeSlide` centers the heading group of cover slides). `ecosystem-ci.yml` selected it through `OPF_GOLDEN_BASELINE` until renderer 0.11.6 became the pinned renderer (chart previews, label rotation and fonts changed 140 of the 805 hashes since); it now selects the pinned renderer's own `test/golden/opf-examples-png.cover-centering.sha256.json`, and this file is kept as the record of the cover-centering review. Reviewed on Node 24.21.0 with the renderer at scale 0.25 and `systemFonts: false`, on the FF-25 `wdUpDiag` corpus (digest `d089278ffc10c44d3504f9e53b3369f37178fdb55e8941ccec2b2bb7704a69d4`, 126 decks / 805 slides). Rendering unmodified main matches the renderer `opf-examples-png.ff25-wdupdiag.sha256.json` exactly; this candidate changes 103 slides, all of them slide 1 of a deck, and leaves 702 unchanged. Only `y` changes for the tag, title and subtitle boxes; `x`, widths and heights are identical, and the diagnostic set is identical. Fifteen before/after pairs spanning widescreen, 16:10, 4:3, letter, A4, bold/classic/minimal/dark themes, left/center/right title alignment, header and footer furniture, wrapped titles and decks that carry a deck-level `slideImage` were inspected. No example cover opts into a reserved slide image band, so the band, background and replaced-image cases are covered by core unit tests instead of this fixture. Do not copy this candidate into a renderer manifest until the renderer PR that pins this core lands.

`opf-examples-png.design-fields.sha256.json` is the coordinated packages golden for the unpublished design-field composition (`design.logo` on covers, `design.contentDirection`, `design.chartPrimary`, `design.listBullet`, `fontScheme.accent`; see the CHANGELOG under Unreleased). `ecosystem-ci.yml` selects it through `OPF_GOLDEN_BASELINE`. Generated with the pinned renderer 0.11.8 (`0ce9bb95`) on Node 24.21.0 at scale 0.25 with `systemFonts: false`, on this checkout's corpus (digest `d089278ffc10c44d3504f9e53b3369f37178fdb55e8941ccec2b2bb7704a69d4`, 126 decks / 805 slides). The same environment reproduces the renderer's own `test/golden/opf-examples-png.cover-centering.sha256.json` byte-for-byte with the published core 0.11.3, so the difference is this core alone: 121 of 805 hashes change and every one is explained by a `composeSlide` box change, with the diagnostic set unchanged. 81 are covers whose heading group moves below the new logo box (the renderer does not draw the logo yet) and 40 are chart slides split 3:2 by `chartPrimary`. `contentDirection` changes no example slide: a layout record's `composition.mode` ranks above it, and the pinned renderer's `test/gallery-layout-alignment.mjs` (57 gallery layouts that must differ from the default only in alignment) passes against this core. Before/after pairs of a cover and a `chartPrimary: top` evidence slide were inspected at golden scale. Picture bullets, the logo picture and the accent font change nothing in this renderer; the renderer PR that consumes this core regenerates its own golden.
