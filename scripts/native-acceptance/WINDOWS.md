# Reusable Windows native observation runner

This versioned runner consumes a fresh suite generated by `prepare.mjs` from the
chosen installed consumer and current source checkouts. It contains no packet
number, workstation path or frozen release SHA. Regenerate on the Windows host
against the exact checkouts used for execution; LF/CRLF differences are real code
identity differences and must not be hidden by rewriting recorded hashes.

Use short local paths (for example `C:/opf-work`). Install the required tools using
the repository instructions. Prefer clean reviewed commits. A captured dirty
checkout is accepted only when its current dirty flag and every recorded code
file digest match the suite; this does not qualify unrelated dirty source.
Generate suites and attempts outside the source repositories. No fonts are
installed or registered by this runner.

```powershell
node scripts/native-acceptance/prepare.mjs --consumer C:/opf-work/consumer --output C:/opf-work/suite --pptx-repo C:/opf-work/opf-pptx

# Office-free runner/path/hash self-test. This does not invoke the entrypoint.
node --test scripts/native-acceptance/run-windows.test.mjs

# On Windows: verify suite/code, snapshot selected inputs, run the existing pure
# process and furniture harnesses, and stop before Office.
powershell.exe -NoProfile -NonInteractive -File scripts/native-acceptance/run-windows.ps1 -SuiteDirectory C:/opf-work/suite -PptxRepository C:/opf-work/opf-pptx -Case feature-metrics -OutputDirectory C:/opf-work/check-metrics -ValidateOnly

# SUPERVISOR ONLY. Use an actual eligible suite case ID and a fresh directory.
powershell.exe -NoProfile -NonInteractive -File scripts/native-acceptance/run-windows.ps1 -SuiteDirectory C:/opf-work/suite -PptxRepository C:/opf-work/opf-pptx -Case feature-metrics -OutputDirectory C:/opf-work/native-metrics
```

The Node self-test launcher removes inherited `PSModulePath` only from its
Windows PowerShell child environment, so PowerShell 7 module paths cannot break
the pure checks. Run the direct `powershell.exe` validation and supervisor
commands shown here from a Windows PowerShell 5.1 environment with its standard
module paths. The Node self-test launcher does not change those commands' environment.

The four required parameters are `SuiteDirectory`, `PptxRepository`, `Case` and
`OutputDirectory`. `TimeoutSeconds` defaults to 45 seconds and cannot exceed 60. Choose
`Case` from `suite.json`; manual/ineligible cases are refused rather than skipped.
The commands select the generated `feature-metrics` ID; its eligibility is checked at execution.

Before creating output or opening Office, the runner verifies schema1, all file
lengths/SHA-256s, exact case selection, declared PPTX/action assets, path containment
and absence of reparse-point aliases. It binds both repository revisions, boolean
dirty flags and recorded code hashes, including this runner and the four required
worker/harness files. The existing worker's pure parser validates the action plan.

Pure `native-process-check.ps1` and `native-furniture-harness-check.ps1` must pass
before native execution. The selected input/action snapshots and original suite
are rechecked, then the existing `test/native-furniture-control.ps1` performs its
bounded one-case observation. Existing limits remain: at most 3 slides, 30 shapes
per slide and 20 prevalidated actions. The runner never quits/kills Office, changes
security, retries or closes unrelated presentations. Preserve a failed/timed-out
attempt and inspect Office; do not run again automatically.

Retain the entire fresh output: `runner.json`, two pure logs/reports, input snapshots,
`native-worker.log` and the native worker's requests/stages/reports/PNGs/saved deck.
`runner.json` records exact suite/artifact provenance and executing code identity.
A successful worker is an observation requiring supervisor review, not program
acceptance, registry acceptance or proof that every layout works natively.

Linux/macOS static validation and Node tests do not establish Windows execution.
The PowerShell self-test exercises preflight only with tiny non-PPTX byte fixtures;
those bytes never reach Office. No native execution is performed during authoring.

## Dedicated table-color case

`table-colors` has six slides and is not eligible for the three-slide furniture
runner. The tracked dedicated runner verifies the same suite/code, runs the generic
`-ValidateOnly -Case feature-table` checks into a fresh sibling `.validation`
directory, and copies/rechecks both sealed table inputs into a fresh attempt.
It invokes existing `test/native-table-colors.ps1` once, retaining its six-slide
scope. The original suite is never the worker's output directory.

```powershell
# SUPERVISOR ONLY; no automatic retry. Defaults to 45 seconds, maximum 60.
powershell.exe -NoProfile -NonInteractive -File scripts/native-acceptance/run-table-windows.ps1 -SuiteDirectory C:/opf-work/suite -PptxRepository C:/opf-work/opf-pptx -OutputDirectory C:/opf-work/native-table-colors -TimeoutSeconds 45

# Office-free comparison after the actual native worker completes.
pnpm native:compare:tables --consumer C:/opf-work/consumer --suite C:/opf-work/suite --output C:/opf-work/native-table-colors --pptx-repo C:/opf-work/opf-pptx
```

The versioned comparator recomputes current package/code identity and binds the
generation/native receipts. It checks native editable table text and character
colors through save/reopen and further export/import cycles. It does not establish
raster or geometry equivalence for reexports. Preserve failed attempts and their
validation siblings. Other manual/ineligible cases need separate supervisor
review and are never silently passed by either runner.
